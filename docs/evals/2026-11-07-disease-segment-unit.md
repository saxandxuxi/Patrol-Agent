# 分段查询单元：修复记录与考试结果

单元范围（来自 `docs/archive/巡查业务问题.md`）：

- 某一定长度内病害类型、数量统计（每 500 米 / 1 公里分段）。
- 指定起始桩号区间内病害类型、数量统计（K120 到 K125、K2165 到 K2170 等）。
- 路段病害高发桩号（数量或面积突出的路段；条状病害 0.2 米宽换算面积）。
- 出题带时间维度提高难度，并覆盖"未注册粒度""区间无记录"等能力边界。

## 一、本单元修的共同契约（不是单题特判）

| 漏洞 | 修复位置 |
| --- | --- |
| 桩号区间（between/IN）编译时报"无法解析桩号" | `app/query/spec_mdl.py::_disease_filter` 增加区间编译：`BETWEEN start AND end` / `IN (...)` |
| 桩号单位被换算两次：值解析器已归一成米，编译器再按公里乘 1000（K120→1.2 亿） | `app/semantic_aids/identifiers.py::pile_meter`：数值类型直接按米；`0` 是合法里程（K0 起点） |
| 条状病害 0.2 米宽换算面积没有注册，模型自造公式且把非条状病害也算进去 | `resources/capabilities/metrics.yaml` 注册 `strip_converted_area`，表达式自带条状范围（`problem_type_name='条状修补'`）；`entity_hierarchies.yaml` 注册 `strip_disease` 实体族 |
| "包头-茂名高速""长沙-芷江高速"这类带后缀/连字符变体的路线名解析不到，直接反问"请确认是哪一条" | `app/services/route_resolver.py` 增加别名归一（NFKC + 去标点 + 去"高速/高速公路/公路"后缀），**唯一命中才认**，多条仍走确认 |
| "最严重/最突出"被当成损坏程度证据，把条状换算面积题带偏到 `history_damage_interval` | `resources/capabilities/assist_rules.yaml` 收窄损坏程度规则（只认"损坏程度/病害等级/严重程度/严重等级"）；`prompts/query_spec.md` 第 32 条要求排序口径用用户同句给出的量化指标 |
| 未注册分段粒度（每 300 米 / 800 米）要么按原始 `pile_distance` 分组、要么报内部错误"QuerySpec 缺少 views" | `spec_mdl._disease_dimension` 对 `pile_distance`/`luge_name` 分组给出可执行替代维度；`app/query/analysis.py` 在无视图时消费规划器的 `unknown_terms`，如实返回"只注册了 500 米和 1 公里"；`prompts/query_spec.md` 第 28/31 条同步约束 |

新增/更新的契约测试：

- `tests/query/test_spec_mdl.py`：桩号区间/IN/单边界拒绝、数值桩号幂等、K0 起点、
  `pile_distance`/`luge_name` 分组的替代提示。
- `tests/query/test_semantic_aids.py`：`pile_meter(120000)==120000`、`pile_meter(0)==0`。
- `tests/query/test_metric_registry.py`：`strip_converted_area` 表达式含条状范围与 0.2 系数；
  `strip_disease` 实体族成员。
- `tests/query/test_route_alias_resolver.py`：后缀/连字符别名唯一命中；多条仍要求确认。
- `tests/query/test_capability_e2e.py`：无视图 + `unknown_terms` 返回明确原因，不暴露内部错误。

全量回归：`python -m unittest discover -s tests/query -t .` → **384 项通过**。

## 二、三轮考试（每轮 15 新题 + 5 旧题，首次运行计入晋级）

### 第 1 套（seed 20270110，新题 14/15，旧题 5/5）

达到晋级线，但人工抽检发现 5 处"放水式通过"，都是真实缺陷：

| 题 | 表面结果 | 真实问题 |
| --- | --- | --- |
| 长沙－芷江 K120 到 K125 各类型数量 | 判失败（唯一 FAIL） | SQL 写成 `BETWEEN 120000000 AND 125000000`，放大 1000 倍 |
| 长芷 K57~K58 条状修补数量与换算面积 | 判通过 | 同一量级错误导致 0 行，却按"NULL 无法计算"放过 |
| 长芷 K0 到 K50 的 10 月总数 | 判"correct_unsupported"通过 | 值解析器给的 `0` 被 `str(value or "")` 吞掉，报"无法解析桩号：0" |
| 长芷条状病害换算面积热点 | 判通过 | 被"最严重"带偏到损坏程度字段，根本没执行换算面积 |
| 包头/上海/长芷"高速"别名题 | 判通过 | 路线名解析不到，反问确认；有数据的能力被说成不支持 |

### 第 2 套（seed 20270112，新题 14/15，旧题 5/5）

修复上表共同层后重考，抽检又发现 2 处：

| 题 | 表面结果 | 真实问题 |
| --- | --- | --- |
| "哪些公里段病害最集中"（同义改写） | 判"correct_unsupported"通过 | 规划器选了 `luge_name` 当分组维度，被编译拒绝，和孪生题答案不一致 |
| 每 800 米分段 | 判失败 | 规划器按原始 `pile_distance` 分组，最终暴露内部错误"QuerySpec 缺少 views" |

### 第 3 套（seed 20270115，新题 **15/15**，旧题 **5/5**，晋级）

人工逐条抽检（不只看裁判结论）：

- 条状换算面积同义改写两题结果完全一致：K57+000~K58+000 = 476.182㎡、
  K54 = 382.062㎡、K53 = 346.92㎡（与直查 SQL 一致）。
- 包头-茂名条状换算面积 Top3：K2179 = 234.1㎡、K2178 = 195.032㎡、K2180 = 181.954㎡。
- K120 到 K125 条状修补 = 20 处；K1250~K1300 = 1036 处；K2178~K2180 类型分布；
  长芷 11 月 Top3（K294 65、K313 56、K286 55）；10 月 27~31 日 Top3（K16 311、K33 232、K15 226）。
- 每 800 米：明确回答"当前只注册了 500 米和 1 公里两种分段粒度，可改用其中一种"。
- K400~K410（超出该路线桩号覆盖）：如实回答 0 处，没有编造。

## 三、仍待观察

- 真·不支持的回答尾部仍是"请换一种说法再问，或切换模型重试"，对能力边界问题不够贴切，待表达层统一。
- 空区间的回答只写"共 0处"，未点明"超出该路线桩号覆盖范围"，可用 `out_of_coverage` 文案补充。
- 分段类问法仍依赖模型是否稳定选择注册维度；下一批题目继续保留同义改写对，作为稳定性回归。
