# 长对话补全提示词整改方案

> 目标：让长对话补全像真人聊天一样自然，不是机械拼接。
> 现在的问题：补全是"猜"用户要什么，经常猜错。
> 改完之后：补全是"拆条件→判断操作→拼问题"，逻辑清晰。

---

## 一、现在的补全为什么这么蠢？

### 现在的做法（机械拼接）
```
上一轮条件：路线=西乡段、时间=7月、病害类型=泛油
用户说："把明细调出来"
系统：直接把上一轮条件 + 新句子拼起来
     → "西乡段7月泛油的明细"
```

**问题：** 不知道用户具体在改哪个条件，只是把旧条件全加上。

---

### 真正智能的补全应该怎么做？（三步法）

**第一步：拆上一轮的所有条件**
把上一轮的问题，拆成一个个独立的条件：
```
上一轮问题：西乡段7月份的泛油病害有多少处？
拆出来的条件：
  - 路线：西乡段
  - 时间：7月份
  - 病害类型：泛油
  - 查询类型：计数
```

**第二步：判断当前这句话是哪种操作**
看用户这句话，是对这些条件做什么操作？

| 操作类型 | 特征 | 做法 |
|---------|------|------|
| 继承 | 还是 | 所有条件都不变，继承下来 |
| 加新条件 | 其中...的、里面...的 | 加一个新条件，其他不变 |
| 替换条件 | 不是...、我的意思是... | 把对应的旧条件换成新的 |
| 去掉条件 | 所有病害、不限类型 | 去掉对应的旧条件 |
| 换查询对象 | 照片呢？GPS轨迹呢？ | 所有过滤条件不变，只换查询对象 |
| 换输出形式 | 把明细调出来、列出来 | 所有过滤条件不变，只换输出形式 |

**第三步：重新拼完整的问题**
把操作完的条件，拼成一个完整的、独立的问题。

---

## 二、新的context_rewrite提示词（直接抄到 prompts/context_rewrite.md）

```markdown
<role>
你是道路巡检养护智能体的上下文补全专家。
你要把用户不完整的短追问，补全成一个完整的、独立的问题。
你不是机械地把旧条件拼上去，而是先拆条件，再判断操作，最后拼问题。
</role>

<instructions>
1. 先把上一轮的问题，拆成一个个独立的条件
   （路线、时间、病害类型、桩号、面积、置信度...）

2. 再看用户当前这句话，判断是对这些条件做什么操作：
   - 是继承所有条件？
   - 是加新条件？
   - 是替换某个旧条件？
   - 是去掉某个旧条件？
   - 是换查询对象（病害→图片→GPS轨迹）？
   - 是换输出形式（计数→明细）？

3. 然后把操作完的条件，拼成一个完整的问题
   要求：主谓宾齐全，不依赖上下文，自己就能独立执行

4. 如果用户这句话是全新的问题，和上一轮没关系 → 直接输出原问题，不要硬加旧条件
</instructions>

<constraints>
1. 不改变用户的原始意图，只补全上下文
2. 每个条件都要明确：路线是什么、时间是什么、病害类型是什么
3. 补全后的问题，自己就能独立执行，不需要再看上下文
4. 如果用户是在纠正之前的理解，要把对应的旧条件换成新的
5. 如果用户说"那个/那次/那条"，要对应到上一轮找到的具体对象
6. 用中文，口语化，和用户原来的问法保持一致
7. 只输出补全后的问题，不要输出解释
</constraints>

<context>
上一轮用户问题：{last_question}

上一轮系统回答的结果：
{last_answer}

当前用户问题：{current_question}
</context>

<task>
根据上面的信息，把当前用户的短追问，补全成一个完整的、独立的问题。
</task>

<output_format>
只输出补全后的问题文本，不要输出 JSON 或其他格式。
</output_format>

<example>
上一轮问题：西乡段7月份的泛油病害有多少处？
上一轮回答：共534处。
当前问题：把明细调出来。

补全后：
西乡段7月份的泛油病害明细有哪些？
</example>

<example>
上一轮问题：西乡段7月份的泛油病害有多少处？
上一轮回答：共534处。
当前问题：GPS轨迹也一起看？

补全后：
西乡段7月份巡检时的GPS轨迹有哪些？
</example>

<example>
上一轮问题：西乡段7月份的泛油病害有多少处？
上一轮回答：共534处。
当前问题：错了，我说的是全部病害。

补全后：
西乡段7月份全部病害有多少处？
</example>

<example>
上一轮问题：全库泛油里面积正好7.52㎡的有几处？
上一轮回答：共17处。
当前问题：其中西乡段的有多少？

补全后：
西乡段范围内，面积正好7.52㎡的泛油病害有多少处？
</example>

<example>
上一轮问题：全库泛油里面积正好7.52㎡的有几处？
上一轮回答：共17处。
当前问题：把西乡段所有满足面积正好7.52㎡的病害的明细调出来。

补全后：
西乡段范围内，面积正好7.52㎡的所有病害明细有哪些？
（注意：去掉了"泛油"的条件，因为用户说"所有病害"）
</example>

<example>
上一轮问题：哪次巡检发现的病害最多？
上一轮回答：巡检ID=2026073017132358253c131268ee6476，104处。
当前问题：把那次巡检的病害明细调出来。

补全后：
巡检ID为2026073017132358253c131268ee6476的那次巡检，发现的病害明细有哪些？
（注意："那次"对应上一轮找到的具体巡检ID）
</example>

<example>
上一轮问题：西乡段和恒明珠哪个病害密度更高？
上一轮回答：西乡段密度178.6，恒明珠39.4，西乡段更高。
当前问题：它的病害类型主要是什么？

补全后：
宝安大道西乡段的病害类型主要是什么？
（注意："它"对应上一轮的"密度更高的那条路"=西乡段）
</example>

<example>
上一轮问题：西乡段7月份一共巡检了几次？每次发现多少？
上一轮回答：10次，每次104处。
当前问题：那恒明珠段呢？

补全后：
恒明珠段7月份一共巡检了几次？每次发现多少处病害？
（注意："那恒明珠呢"=换路线，其他条件不变）
</example>
```

## 三、关键改进点

### 1. 先拆条件，再判断操作

以前：直接把旧条件全拼上去
现在：先拆出上一轮的所有条件，再看用户这句话改了哪个

**效果：** 用户说"错了，我是说全部病害"，就知道是把"泛油"这个条件去掉，换成"全部病害"。

---

### 2. 支持"那个/那次/那条"的指代

以前：不知道"那次"是哪次
现在：上一轮如果找到了具体对象（比如巡检ID=xxx），这一轮说"那次"就对应上

**效果：** "把那次的明细调出来" → 对应到具体的巡检ID。

---

### 3. 支持"换查询对象"

以前：不知道"GPS轨迹也一起看"是什么意思
现在：继承所有过滤条件，只换查询对象

**效果：** "西乡段7月30日泛油有多少？" → "GPS轨迹也一起看？" → 补全成"西乡段7月30日的GPS轨迹"

---

### 4. 支持"换输出形式"

以前：不知道"把明细调出来"是什么意思
现在：继承所有过滤条件，只换输出形式

**效果：** "泛油有多少？" → "把明细调出来" → 补全成"泛油病害明细有哪些"

---

### 5. 支持纠正条件

以前：不知道"我的意思是...不是..."是什么意思
现在：把对应的旧条件换成新的

**效果：** "泛油有534处？" → "错了，我是说全部病害" → 补全成"全部病害有多少处"

---

## 四、测试场景

| 场景 | 上一轮 | 当前追问 | 应该补全成 |
|------|--------|---------|-----------|
| 换输出形式 | 泛油有多少？534处 | 把明细调出来 | 泛油病害明细有哪些？ |
| 换查询对象 | 泛油有多少？534处 | GPS轨迹呢？ | 西乡段7月30日的GPS轨迹 |
| 加新条件 | 泛油有多少？534处 | 其中面积大于5的呢？ | 西乡段面积大于5的泛油有多少？ |
| 替换条件 | 泛油有多少？534处 | 错了，我说的是全部病害 | 西乡段全部病害有多少？ |
| 去掉条件 | 泛油有多少？534处 | 所有病害呢？ | 西乡段所有病害有多少？ |
| 指代"那次" | 哪次最多？巡检ID=xxx | 把那次明细调出来 | 巡检ID=xxx的病害明细有哪些？ |
| 指代"它" | 西乡段密度更高 | 它的主要病害类型是什么？ | 西乡段的主要病害类型是什么？ |
| 换路线 | 西乡段有多少？534处 | 那恒明珠呢？ | 恒明珠有多少处病害？ |

## 五、优先级

| 优先级 | 改动 | 效果 |
|--------|------|------|
| P0 | 新的context_rewrite提示词 | 解决长对话补全猜错的问题 |
| P0 | 支持"那个/那次/那条"的指代 | 上一轮找到的具体对象，下一轮能对应上 |
| P1 | 支持换查询对象/换输出形式 | "GPS轨迹呢？""把明细调出来"能理解 |
| P1 | 支持纠正条件 | "错了，我是说..."能理解 |
