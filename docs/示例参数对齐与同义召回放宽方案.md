# 模板回填"值取本轮参数" + 同义召回放宽（给 codex）

## 一、模板/示例回填：槽名对齐，值取本轮（用户点名要改）

### 现象
问"西乡段 **8 月**巡检几次"，系统推荐了"西乡段 7 月巡检几次"这条相似示例并直接按它生成 SQL，时间还是 7 月。本地实测该示例存的 spec 是：
`route=宝安大道西乡段, time_range=[2026-07-01,2026-08-01], must_keep=[route,time_range]`。
问题在于：回填时**槽名对齐了，但值直接照抄示例 spec 里的旧值（7 月）**，本轮用户说的"8 月"没有替换进去。

### 规则
1. **槽名对齐，默认值取本轮，但卡片上可见可改（不是静默自动覆盖）**：
   - 默认值：route、time_range、pile_range、damage_type、device 这些槽，本轮 plan 里给了值就用本轮的（问 8 月就默认填 8 月端点）；本轮没提的才沿用示例 spec 的默认值。
   - 关键：这些槽在相似示例确认卡上**必须可编辑**（现在 time_range 被硬写成 editable=False，capabilities.py:164-180，用户问 8 月它填 7 月还改不动——这才是 8 月错的直接原因）。改成 editable=True，把本轮解析出的时间/路线/桩号/类型直接展示在卡片上。
   - 为什么不能纯静默"值取本轮"：本项目 plan 的时间槽本来就不稳（8月变7月、月份 off-by-one）。默认用本轮是为了跟上用户意图；把槽摆出来可改，是为了 plan 抽错时用户一眼看到、改一个数再确认，不静默错。这比"照抄示例锁死"和"纯自动覆盖"都稳。
   - 例：示例是"西乡段 7 月巡检几次"，本轮问"8 月" → 卡片上默认 route=西乡段、time_range=8 月，用户确认；本轮只问"恒明珠呢" → route=恒明珠、time_range 沿用 7 月。
2. **参数从 plan/spec 正推，不从 SQL 反推**：模板的"参数是什么"直接取 `plan_to_spec` 已经解析好的槽（route/pile_range/damage_type/time_range/上下行/设备/阈值/TopN），SQL 只负责把这些槽的值填回占位符。不要让 sqlglot 从 SQL 字面量猜哪些可换（这是现在抽参效果差的根因）。
3. **值靠查表不靠猜**：路线名→route_id 查 basic_facilities_routes，病害类型名→problem_code 查 ai_problem_base / code_map，桩号文字→pile_distance 米数。查不到就把该槽标成"待用户在卡片上确认"，不要瞎填。
4. 拿不准/查不到的落 candidate，人工确认；不追求全自动。
5. 注：相似示例卡片用户说了他**无所谓**——卡片本来就是让用户判断"是不是同一个问题"。本规则主要管"自动模板/参数化重放"的填值正确性，不影响卡片展示。

## 二、同义改写召回不到（主因：召回池被 trusted 卡死）

### 现象
原题"数据库里一共有多少种资产类型？每种类型有多少个资产？"已经存进示例库；换个说法问"数据库里每种资产类型有多少个资产？"，居然没召回、直接走了 Wren。用户判断：只要召回把这条找出来，再交给打分 LLM 判断，是能认成同一类的。

### 根因（已读代码）
1. **召回阶段就用 trusted 把题筛掉了（主因）**：`_reuse_candidates`（nl2sql.py:5807-5809）只遍历 `trusted=1` 的记录；向量召回结果还要求 `sample_key ∈ trusted_questions` 才保留（5831）。没点过"答对了"的已存题，**根本进不了打分 LLM 的候选清单**——不是 LLM 判断错，是它压根没看到这条。
2. **摆卡门槛又叠了几道硬闸**：direct_match._score（direct_match.py:106-111）要求 score≥0.92、missing_slots 为空、**differences 必须为空**、Top1−Top2≥0.08。同义改写只要措辞有一处不同（"有多少种"省略、"分别"换"每种"），LLM 就倾向判 differences 非空 → 整条丢弃。

### 改法（分层：召回放宽，执行仍严）
1. **彻底删除 trusted 这个功能（用户明确要求）**：不要再保留"已确认/未确认"这个二分标记，整个系统不再有 trusted 概念。
   - 召回：删掉 `_reuse_candidates` 里所有 trusted 过滤——nl2sql.py:5807-5809 的 `if not row.get("trusted"): continue`，以及 5831 行向量召回要求 `sample_key ∈ trusted_questions` 的检查。**凡是存进示例库 / RAGFlow 问答集 / 固定看板的题，一律参与召回**。
   - 挖掘：`templatizer.mine_all` 不再 `WHERE trusted=1`（1355-1359），所有带 SQL 的已存示例都参与挖模板。
   - 存储：`example_pairs` 表的 trusted 列不再读写（可保留列但代码全部去掉引用；新表/重建时直接不要这列）；"答对了/固化到看板"这个动作只用来更新示例内容、置顶/上看板，不再写一个 trusted 标记。
   - 展示：dashboard / 同步状态里的"已确认 N"去掉，只显示"本地 N · 带 SQL N · RAGFlow N"。
   - 安全模型改成：示例池里的题都视为可用（本来就是人工存进 RAGFlow 的），能不能用由**打分 LLM 语义判断 + 用户在卡片上点确认 + SQL 可执行**来把关，不再靠 trusted 这个事前标记。
2. **由打分 LLM 做语义同问判断**：现有 `example_direct_match` 提示词让 LLM 判"是不是同一类问题、参数能不能换"。放宽：
   - threshold / margin 适当下调（或改成 LLM 给 same_query 布尔 + 理由，而不是卡 0.92 这种死阈值）；
   - 允许 differences 里"措辞差异但口径等价"（如省略"有多少种"只问分布）——只要 LLM 认为换参数后口径一致，就摆卡。
3. **安全闸放在"确认执行"，不放"召回"**：摆卡后仍要用户在卡片上点确认，且 SQL 必须可执行（物理 SQL 或 Wren 可编译）才执行。召回宽一点没关系，最后一步由用户把关。
4. 这样既解决"同义改写找不到"，又不会错配——错配由用户在卡片上点不点来兜底。

### 验收
1. 已存"数据库里有多少种资产类型、每种多少个"后，问"每种资产类型有多少个资产？" → 召回命中这条、打分 LLM 判 same、摆出确认卡（而不是直接走 Wren）；
2. 相似示例换月份/路线时，回填值取本轮（8 月问法不再出 7 月结果）；
3. 明显不同的题（换了对象或指标）仍不被摆成示例直达；
4. 摆卡后仍必须用户确认才执行。

## 三、改动文件
- `backend/app/services/nl2sql.py`：`_reuse_candidates` 去掉 trusted 过滤（5807-5809、5831）；模板/示例回填按"槽名对齐、值取本轮"（fill_example_slots 一带，约 6042-6108）。
- `backend/app/services/direct_match.py`：`_score` 放宽 threshold/margin、differences 口径等价（106-135）。
- `backend/app/services/templatizer.py`：`mine_all` 不再筛 trusted（1355-1359），所有带 SQL 的已存示例都参与挖掘。
- `backend/app/store.py`：example_pairs 去掉 trusted 列的读写（add_example_pair、mark_example_trusted、各查询里的 trusted 过滤一并清理）。
- `backend/app/routers/chat.py`：approve 不再写 trusted=1，只更新示例内容。
- `backend/app/routers/dashboard.py` / `nl2sql.example_sync_status`：去掉"已确认 N"。
- `prompts/example_direct_match.md`：补充"措辞不同但口径/维度一致也算同一类问题；省略的总览问句不影响分布类复用"的判定示例。
