# 宏观元数据查询（表级/库级）系统性整改方案

> 针对的问题类型：用户问的是**数据库本身的结构信息**，不是业务数据。如"每个数据库有哪些表""哪些表不为空""每张表多少行""MySQL 和 PostgreSQL 各有几张表"。
> 现状：系统当成业务数据查询，去业务表里找 table_name 字段，报"查不到这个字段"。本方案从识别层和执行层系统性解决。

---

## 一、问题定义（这一类问题的通用模式）

**模式**：用户问的对象是"数据库/表/列"本身，不是表里的业务记录。关键词通常包含"数据库/表/字段/列/有多少张/哪些/不为空/空表/行数/记录数"。

| 子类 | 例子 | 查什么 |
|---|---|---|
| 表列表 | 每个数据库有哪些表 | information_schema.tables |
| 空表/非空表 | 哪些表不为空 / 全库空表有哪些 | information_schema.tables + COUNT |
| 表行数 | 每张表有多少行 / 哪张表数据最多 | information_schema.tables.table_rows 或 COUNT(*) |
| 表数量 | 库里有多少张表 | COUNT(*) from information_schema.tables |
| 跨库对比 | MySQL 和 PostgreSQL 各有几张表 / 哪个库表多 | 两个库分别查再对比 |
| 字段列表 | 某张表有哪些字段 | information_schema.columns |
| 字段画像（已有） | 哪些字段空值率高 / 没数据 | 现有 profiling_reply |

**关键特征**：用户不是在问"某条路有多少病害"（业务数据），而是在问"这个数据库长什么样"（元数据）。

---

## 二、根因

### 1. 识别范围太窄
`generic.is_profiling_question` 要求**同时**满足：
- subject："字段"/"列"/"表"（三选一）
- word："没数据"/"空值率"/"完整度"/"数据画像"等

但表级元数据查询（"有哪些表""哪些表不为空""每张表多少行"）：
- 有"表"（subject 命中）
- 但**没有**"没数据/空值率"等 word（"不为空""有多少行"不在列表里）
- → is_profiling_question 返回 False → 走业务 plan → 报错

### 2. 执行层只有字段画像，没有表级/库级查询
`profiling_reply` 只处理：
- 某张表的字段画像（空值率排名）
- 全库空表列表（顺带输出，但不是主功能）

**不处理**：
- 表列表（有哪些表）
- 非空表列表（哪些表有数据）
- 表行数排名（哪张表数据最多）
- 表数量统计
- 跨库对比

### 3. 跨库元数据查询没有特殊处理
"每个数据库的不为空的表格名称"涉及 MySQL 和 PostgreSQL 两个库，现有 cross_db 拆分主要针对业务数据查询，元数据查询走 information_schema 不需要 Wren/MDL，应该直接查。

---

## 三、系统性解决方案

### 层 1：扩展识别——新增"表级/库级元数据"识别

**文件**：`generic.py` `is_profiling_question` + `lexicon/trigger_words.yaml`

**改法**：
1. 新增 `is_metadata_question(message)` 函数，独立于现有的 `is_profiling_question`：
   - 识别表级/库级元数据查询，不要求同时有 subject 和 word；
   - 触发词："有哪些表""哪些表""表名""表格名称""不为空""空表""有数据""多少行""行数""记录数""多少张表""表数量""数据库里""每个数据库"。
2. `is_profiling_question` 保留（字段画像），`is_metadata_question` 新增（表级/库级），两者是"或"关系。
3. 在 `agent.py` 3517-3530 行的元数据短路里，把 `is_profiling_question` 改成 `is_profiling_question or is_metadata_question`。

### 层 2：扩展执行——新增表级/库级元数据查询函数

**文件**：`generic.py` 新增 `metadata_reply(message, kind)` 函数

**改法**：根据问题类型分 6 个子处理，全部直接查 information_schema（MySQL）/ pg_catalog（PostgreSQL），不走 Wren/MDL/业务 plan：

#### 子处理 A：表列表（"有哪些表""表格名称"）
```sql
SELECT table_name, table_comment 
FROM information_schema.tables 
WHERE table_schema = DATABASE()  -- MySQL
ORDER BY table_name
```
回答：列出所有表名（带中文注释），按表名排序。

#### 子处理 B：非空表/空表（"哪些表不为空""空表有哪些"）
```sql
SELECT table_name, table_rows 
FROM information_schema.tables 
WHERE table_schema = DATABASE()
  AND table_rows > 0  -- 不为空；=0 则为空
ORDER BY table_rows DESC
```
回答：非空表 X 张、空表 Y 张，分别列出。

#### 子处理 C：表行数排名（"每张表多少行""哪张表数据最多"）
```sql
SELECT table_name, table_rows 
FROM information_schema.tables 
WHERE table_schema = DATABASE()
ORDER BY table_rows DESC
```
回答：按行数从高到低列出，标注最多的表。
**注意**：information_schema.table_rows 是估算值（InnoDB），如果用户问"准确行数"，对 Top N 表跑 `SELECT COUNT(*)` 精确统计。

#### 子处理 D：表数量（"有多少张表"）
```sql
SELECT COUNT(*) as table_count 
FROM information_schema.tables 
WHERE table_schema = DATABASE()
```
回答：库里共 X 张表。

#### 子处理 E：字段列表（"某张表有哪些字段"）
```sql
SELECT column_name, column_type, column_comment 
FROM information_schema.columns 
WHERE table_schema = DATABASE() AND table_name = ?
ORDER BY ordinal_position
```
回答：列出该表所有字段（带类型和注释）。

#### 子处理 F：跨库对比（"每个数据库""MySQL 和 PostgreSQL 各"）
- 对每个库分别跑子处理 A/B/D，然后合并对比回答；
- 不调 cross_db 拆分器（元数据查询不需要 Wren），直接在 metadata_reply 里循环两个库。

### 层 3：跨库元数据查询直接处理

**文件**：`agent.py` 元数据短路段（3517-3530 行）

**改法**：
- 元数据问题（is_profiling_question or is_metadata_question）不做跨库拆分，直接调 metadata_reply；
- metadata_reply 内部如果检测到"每个数据库/两个库/各有"等跨库信号，自动查两个库再合并；
- 不走 cross_db.db_scope / orchestrator.decompose（那些是给业务数据查询用的）。

## 四、判断逻辑流程图（伪代码）

```
用户问题
  │
  ▼
is_profiling_question or is_metadata_question?
  │
  ├─ 否 → 走原有业务链路（不变）
  │
  └─ 是 ▼
  问题类型判断：
  ├─ 字段画像（空值率/哪些字段没数据）→ profiling_reply（现有）
  ├─ 表列表（有哪些表/表格名称）     → metadata_reply 子处理 A
  ├─ 空表/非空表（不为空/空表）       → metadata_reply 子处理 B
  ├─ 表行数（多少行/哪张表最多）       → metadata_reply 子处理 C
  ├─ 表数量（多少张表）                → metadata_reply 子处理 D
  ├─ 字段列表（某表有哪些字段）        → metadata_reply 子处理 E
  └─ 跨库（每个数据库/两个库各）       → metadata_reply 循环两库再合并
  │
  ▼
直接查 information_schema / pg_catalog → 自然语言总结
```

## 五、验收（多个例子，覆盖全部子类）

1. "每个数据库的不为空的表格名称" → 列出 MySQL 和 PostgreSQL 各自的非空表，不报错；
2. "库里有哪些表" → 列出所有表名（带中文注释）；
3. "哪些表是空表" → 列出空表，标注共 X 张；
4. "每张表有多少行" → 按行数排名列出；
5. "库里有多少张表" → 回答共 X 张；
6. "ai_problem 表有哪些字段" → 列出该表所有字段（带类型和注释）；
7. "MySQL 和 PostgreSQL 各有几张表" → 分别回答并对比；
8. 回归："哪些字段空值率最高" → 走现有 profiling_reply，不退化。

---

## 六、不做的（明确边界）
- 不做表结构变更（ALTER TABLE 等），只做查询；
- 不做索引/约束/外键的元数据查询（后续可扩展，本期不做）；
- 不做业务数据和元数据的混合查询（如"西乡段的病害表有哪些字段"——这是元数据，直接查表结构即可，不需要过滤西乡段）；
- 不改 Wren/MDL 链路（元数据查询完全绕过 Wren，直接查 information_schema）。

---

## 七、实施顺序
1. **第一步**：新增 `is_metadata_question` 识别函数 + 触发词（层 1）；
2. **第二步**：新增 `metadata_reply` 函数，实现 6 个子处理（层 2）——核心；
3. **第三步**：agent.py 元数据短路段接入 is_metadata_question + 跨库直接处理（层 3）；
4. 每步做完跑验收例子，确认不回归。
