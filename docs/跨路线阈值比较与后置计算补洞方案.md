# 跨路线阈值比较题答不出/答案飘（给 codex）

## 一、现象
问："恒明珠的泛油面积大于西乡段泛油平均面积的有多少条？"
答（45.8 秒）：只有西乡段平均 1.0670，"未包含恒明珠任何数据""数据不足，无法回答"。
同一题连问三遍，三个答案。

## 二、正确拆法 vs 现在
正确拆法应是 3 步：
1. data：西乡段泛油平均面积 = 1.0670；
2. data：恒明珠每条泛油病害的面积明细（必须查库）；
3. post_calc：恒明珠里 area > 1.0670 的条数。

现在的两个洞：

1. **post_calc 只算术不补查**：`_post_calc_payload`（agent.py:1875-1914）被设计成"不查数据库，只基于前序结果算"。前序结果里没有"恒明珠每条面积明细"时，它直接回"数据不足算不出来"（1913），**不会回头补一个 data 子任务去查恒明珠明细**。第 2 步根本没拆出来。
2. **拆分器对"用 A 的聚合值当 B 的逐行阈值"不稳定**：LLM 语义拆分没把"恒明珠泛油明细"当成独立 data 任务，加上长对话把"恒明珠"和上一轮的"西乡段"路线搅在一起，每次拆分结果飘 → 三遍三个答案。

## 三、整改
1. **拆分提示词补这类模式**：明确"用某对象 X 的聚合值（均值/最大）作为另一个对象 Y 的逐行过滤阈值，数 Y 满足条件的条数" = 两步 data（X 的聚合值 + Y 的逐条明细）+ 一步 post_calc。必须把 Y 的逐条明细拆成独立 data 子任务，不能指望 post_calc 自己算。
2. **post_calc 缺中间结果时不要直接投降**：发现需要的中间明细（这里是"恒明珠每条面积"）不在前序结果里时，回退补一个 data 子任务去查，而不是报"数据不足"。至少在规划阶段把这种明细任务列全。
3. **跨路线第二对象不被上一轮路线覆盖**：本题"恒明珠"是新对象，不能被上下文粗条件锁成上一轮的西乡段（又是长对话粗条件继承的老问题，注意区分"换对象"和"沿用上一条路线"）。
4. **稳定性**：这类题先确定性拆（结构是封闭的：聚合阈值 + 逐行计数），减少每次靠 LLM 重新理解造成的答案飘。

## 四、验收
1. "恒明珠的泛油面积大于西乡段泛油平均面积的有多少条？" → 三步都跑，返回一个明确数字，不再说"数据不足"；
2. 同一题连问三遍答案一致；
3. 把"西乡段/恒明珠"换成任意两条路、把"泛油/平均面积"换成任意类型和指标，拆法不变、能跑通。

## 五、改动文件
- 拆分提示词（问题拆分/规划那套 prompts）：补"跨对象聚合阈值 → 逐条计数"的拆法示例；
- `backend/app/services/agent.py`：`_post_calc_payload` 缺中间结果时回退补 data 子任务，而非直接报数据不足；
- 长对话粗条件继承：新路线对象（恒明珠）不被上一轮路线（西乡段）错误覆盖。
