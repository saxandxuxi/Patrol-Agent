# 巡检任务完成情况 测试题（10 道）

所有答案均为 2026-10-21 通过项目只读数据库实查得出，口径为未删除记录 `del_flag=0`。

本套题围绕五个业务方向：某次巡检任务的完成里程、某一次巡检任务的病害数量与病害分布、某台巡检设备在指定时段的任务完成情况、某一路段巡检工作完成情况、月度巡查次数。

## 一、数据背景

### 表关系

- 巡检任务表 `ai_maintain_patrol`：一行是一次巡查，主键 `id`。
- 病害表 `ai_problem`：一行是一条病害，外键 `patrol_id` 指向巡检任务 `id`。
- 巡检设备表 `ai_collection_equipment`：一行是一台采集设备，主键 `id` 与设备编码 `device_code` 是两个字段。
- 路线关联表 `ai_maintain_routes_patrol`：记录某次巡检经过了哪些路线，字段为 `patrol_id`、`routes_id`。
- 路段关联表 `ai_maintain_sections_patrol`：记录某次巡检经过了哪些路段，字段为 `patrol_id`、`sections_id`。
- 路线台账 `basic_facilities_routes`、路段台账 `basic_facilities_sections`。

### 巡检任务关键字段

- `task_number`：任务编号，例如 `XJJL202607210004`。
- `patrol_name`：巡查名称，本库均为“快捷巡查”。
- `patrol_type`：巡查类型，0 定期巡查、5 日常巡查、10 专项巡查、15 复核考评、20 重点抽查。
- `patrol_status`：巡查状态，0 未开始、5 进行中、10 暂停、15 已完成、20 逾期。
- `patrol_method_type`：巡查方式，5 生成路线、6 已有路线内。
- `equipment_id`：巡检设备编码，本库设备信息存在这个字段，关联 `ai_collection_equipment.device_code`。
- `patrol_mileage`：本次巡检完成里程，单位是米，不是公里。
- `create_time`：任务创建时间，`over_time`：任务完成时间，`end_date`：业务日期。

### 设备关联关键字段

- 巡检任务表的 `device_code`、`vehicle_id` 两列在本库全部为空，不能用。
- 真正有值的是 `equipment_id`，存的是设备编码，例如 `102367594568`。
- 关联设备表时必须写 `ai_collection_equipment.device_code = ai_maintain_patrol.equipment_id`，不能用设备表主键 `id` 去连。
- 设备表 `device_name` 是设备名称。

### 病害分布关键字段

- `categories_type`：病害大类，0 路面病害、5 路基病害、10 沿路设施、15 交安事件。
- `damage_type`：病害细分类别代码，代码 10 表示泛油，空值表示未识别。
- `up_or_down`：上行下行，1 上行、2 下行。
- `ai_problem.device_code` 与任务表 `equipment_id` 是同一套设备编码，可按设备统计病害。

### 全库实查事实

- 巡检任务共 147 次，全部为已完成状态 `patrol_status=15`，全部为定期巡查 `patrol_type=0`。
- 巡查次数按月份分布：2025 年 6 月 2 次，2026 年 6 月 83 次，2026 年 7 月 62 次。
- 病害共 1702 条。
- 设备使用情况：

| 设备名称 | 设备编码 | 任务次数 |
|---|---|---|
| 567test | 102367594567 | 80 |
| 平整度测试设备 | 102367594568 | 59 |
| 测试设备 | 123456789 | 6 |
| D-6809 | 1420324266809 | 1 |
| 无对应设备台账 | 1425024331028 | 1 |

- 病害按设备：平整度测试设备检出 936 条、涉及 10 次巡检，567test 检出 766 条、涉及 27 次巡检。
- 实际巡检只覆盖三个路线对象：宝安大道西乡段 57 次、宝安中心--恒明珠 47 次、未知路线 87 行次。

### 必须避开的坑

#### 1. 里程单位是米

`patrol_mileage` 存的是米，例如 913 表示 913 米，换算公里要除以 1000，得到 0.913 公里。直接当成公里会放大一千倍。

#### 2. 字典表 JOIN 会放大病害行数

字典表 `ai_problem_base` 的 `problem_code` 不唯一，同一代码下有多行。直接 JOIN 再 `COUNT(*)`，会把任务 XJJL202607210004 的泛油从 60 处放大成 120 处。

统计病害分布时优先按代码直接分组，需要中文名称时连表必须用 `COUNT(DISTINCT ai_problem.id)`。

#### 3. 月度数任务必须用巡检表，不能用病害表

147 次巡检中有 110 次没有检出病害。如果用病害表的 `patrol_id` 去数巡查次数，这 110 次零病害巡检会全部丢失，月度巡查次数会被严重低估。月度数任务必须以 `ai_maintain_patrol` 为主表。

#### 4. 路线关联表含有大量历史任务，必须先限定主表

`ai_maintain_routes_patrol` 中共有 4342 个不同任务关联，而巡检任务主表当前只有 147 条有效任务，关联表内含有大量历史或已删除任务。

统计某路段的巡检次数时，必须先 JOIN 巡检任务主表并限定 `del_flag=0`，再用 `COUNT(DISTINCT p.id)` 计数，不能直接在关联表上数。

#### 5. 路段巡检里程不能按路线汇总

西乡段的 57 次巡检全部同时关联了“西乡段 + 未知路线”，恒明珠的 47 次中有 15 次同时关联了“恒明珠 + 未知路线”，共有 72 次巡检跨两条路线。

一次巡检的 `patrol_mileage` 是整条轨迹的总里程，无法按路线拆分。若按路线关联表直接 `SUM(patrol_mileage)`，跨路线任务的里程会在每条路线上各计一次，西乡段会得到 63456 米这个虚高结果。巡检次数用 `COUNT(DISTINCT)` 不受影响，是可靠的，完成里程只能在单次任务或单台设备层面统计。

#### 6. 存在明显异常的里程数据

部分测试数据轨迹漂移导致里程虚高，例如任务 XJJL202607210009 在 3 分钟内记录里程 105755 米，XJJL202606270001 记录 60450 米。涉及 567test 7 月 21 日的里程汇总被这些异常值拉高，不代表真实完成里程。出里程题时选用数据干净的平整度测试设备。

#### 7. 路线关联与病害定位是两个口径

巡检任务经过哪些路线由路线关联表 `ai_maintain_routes_patrol` 登记，病害具体落在哪条路线由病害表 `routes_id` 在采集时定位，两者是独立来源，存在个别任务登记不一致。

西乡段就有 1 次巡检在关联表只登记了未知路线，但其采集到的 57 处病害定位到了西乡段。因此“巡检多少次”和“多少次检出病害、病害多少处”应分别按两个口径统计并如实说明，不能简单相减推算零病害次数。

## 二、题目与标准答案

### 方向一：某次巡检任务的完成里程

#### 题1：单次任务的完成里程（基础）

**题目**

任务编号 XJJL202607210004 的这次巡检，完成了多少里程？

**标准答案**

完成里程 913 米，即 0.913 公里。该任务由平整度测试设备执行，2026-07-21 14:22:16 开始，14:26:02 完成，状态为已完成。

**统计口径**

- 用 `task_number` 定位巡检任务，取 `patrol_mileage`。
- 里程单位为米，公里数除以 1000。
- 只统计 `del_flag=0`。

**正确 SQL 口径**

```sql
SELECT task_number,
       patrol_mileage AS 完成里程_米,
       ROUND(patrol_mileage / 1000, 3) AS 完成里程_公里,
       patrol_status, create_time, over_time
FROM ai_maintain_patrol
WHERE del_flag = '0' AND task_number = 'XJJL202607210004';
```

#### 题2：某设备一天多次巡检的合计里程（聚合）

**题目**

平整度测试设备在 2026 年 7 月 30 日一共完成了几次巡检？累计完成里程是多少？

**标准答案**

3 次，累计完成里程 3103 米，即 3.103 公里。三次分别为 XJJL202607300001 的 1220 米、XJJL202607300003 的 913 米、XJJL202607300005 的 970 米。

**统计口径**

- 设备编码 102367594568，用 `equipment_id` 匹配，日期取 `create_time`。
- 同一次任务里程为一条记录，合计用 `SUM`，次数用 `COUNT`。

**正确 SQL 口径**

```sql
SELECT COUNT(*) AS 巡检次数,
       ROUND(SUM(patrol_mileage), 0) AS 完成里程合计_米,
       ROUND(SUM(patrol_mileage) / 1000, 3) AS 完成里程合计_公里
FROM ai_maintain_patrol
WHERE del_flag = '0'
  AND equipment_id = '102367594568'
  AND DATE(create_time) = '2026-07-30';
```

### 方向二：某次巡检任务的病害数量与分布

#### 题3：单次任务的病害总量

**题目**

任务编号 XJJL202607210004 的这次巡检，一共检出多少处病害？

**标准答案**

106 处。

**统计口径**

- 用 `task_number` 定位任务，再按 `patrol_id` 关联病害表。
- 病害只统计 `del_flag=0`。
- 该任务不 JOIN 字典表，直接 `COUNT(*)` 即为 106。

**正确 SQL 口径**

```sql
SELECT COUNT(*) AS 病害数量
FROM ai_problem pr
JOIN ai_maintain_patrol p ON p.id = pr.patrol_id
WHERE pr.del_flag = '0'
  AND p.task_number = 'XJJL202607210004';
```

#### 题4：单次任务的病害分布（大类与细分）

**题目**

任务编号 XJJL202607210004 检出的这 106 处病害，分别是怎么分布的？

**标准答案**

按病害大类：路面病害 62 处、沿路设施 31 处、交安事件 13 处，没有路基病害。

按病害细分类别：泛油 60 处、未识别类型 46 处。

**易错点**

- 大类按 `categories_type` 分组，细分按 `damage_type` 分组，两者是两套分类口径，不能混用。
- 细分类型不能 JOIN 字典表 `ai_problem_base` 后 `COUNT(*)`，否则泛油会被放大成 120 处。
- 空的 `damage_type` 属于未识别类型，不能丢弃。

**正确 SQL 口径（按大类）**

```sql
SELECT CASE pr.categories_type
         WHEN '0'  THEN '路面病害'
         WHEN '5'  THEN '路基病害'
         WHEN '10' THEN '沿路设施'
         WHEN '15' THEN '交安事件'
         ELSE '未分类' END AS 病害大类,
       COUNT(*) AS 处数
FROM ai_problem pr
JOIN ai_maintain_patrol p ON p.id = pr.patrol_id
WHERE pr.del_flag = '0'
  AND p.task_number = 'XJJL202607210004'
GROUP BY pr.categories_type
ORDER BY 处数 DESC;
```

**正确 SQL 口径（按细分，不连字典表）**

```sql
SELECT CASE WHEN damage_type = '10' THEN '泛油'
            WHEN damage_type IS NULL OR damage_type = '' THEN '未识别'
            ELSE damage_type END AS 病害类型,
       COUNT(*) AS 处数
FROM ai_problem pr
JOIN ai_maintain_patrol p ON p.id = pr.patrol_id
WHERE pr.del_flag = '0'
  AND p.task_number = 'XJJL202607210004'
GROUP BY damage_type;
```

### 方向三：某台设备在指定时段的任务完成情况

#### 题5：某设备某月的任务完成情况

**题目**

平整度测试设备在 2026 年 7 月一共完成了多少次巡检？累计完成里程多少米？

**标准答案**

完成 39 次巡检，累计完成里程 38046 米，即 38.046 公里，平均每次约 976 米。39 次全部为已完成状态。

**统计口径**

- 设备用名称定位，先在设备表按 `device_name='平整度测试设备'` 找到 `device_code=102367594568`，再用 `equipment_id` 关联。
- 月份按 `create_time` 用 `DATE_FORMAT(...,'%Y-%m')` 过滤。
- 里程求和为 38046 米，这台设备里程数据干净，可直接使用。

**正确 SQL 口径**

```sql
SELECT COUNT(*) AS 巡检次数,
       ROUND(SUM(p.patrol_mileage), 0) AS 累计完成里程_米,
       ROUND(AVG(p.patrol_mileage), 0) AS 平均每次_米
FROM ai_maintain_patrol p
JOIN ai_collection_equipment e ON e.device_code = p.equipment_id
WHERE p.del_flag = '0'
  AND e.device_name = '平整度测试设备'
  AND DATE_FORMAT(p.create_time, '%Y-%m') = '2026-07';
```

#### 题6：同一时段两台设备的任务量对比

**题目**

2026 年 7 月，平整度测试设备和 567test 分别完成了多少次巡检？哪台完成得多？

**标准答案**

平整度测试设备完成 39 次，567test 完成 23 次。平整度测试设备更多，多 16 次。

**统计口径**

- 7 月只有这两台设备执行巡检，合计 62 次，与全库 7 月总任务数一致。
- 按设备分组统计任务数，不涉及里程，避免 567test 7 月 21 日的异常里程干扰。

**正确 SQL 口径**

```sql
SELECT COALESCE(e.device_name, '未知设备') AS 设备,
       COUNT(*) AS 巡检次数
FROM ai_maintain_patrol p
LEFT JOIN ai_collection_equipment e ON e.device_code = p.equipment_id
WHERE p.del_flag = '0'
  AND DATE_FORMAT(p.create_time, '%Y-%m') = '2026-07'
GROUP BY e.device_name, p.equipment_id
ORDER BY 巡检次数 DESC;
```

### 方向四：某一路段的巡检工作完成情况

#### 题7：某路段累计巡检次数与检出情况

**题目**

宝安大道西乡段截至目前一共被巡检了多少次？累计检出多少处病害、由多少次巡检检出？

**标准答案**

西乡段共被巡检 57 次，病害表中累计记录西乡段病害 911 处，由 10 次巡检检出。

这两个数字来自不同口径，不能直接用 57 减 10 推算零病害次数。巡检次数按路线关联表统计，其中有 9 次巡检在关联表登记了西乡段并在西乡段检出病害，对应 854 处病害；另有 1 次巡检在路线关联表只登记了未知路线，但病害采集时定位到西乡段，贡献了 57 处病害。因此 911 处病害由 10 次巡检检出，而明确登记覆盖西乡段的巡检是 57 次，两者口径来源不同。

**统计口径**

- 巡检次数通过路线关联表 `ai_maintain_routes_patrol` 关联路线台账，用 `COUNT(DISTINCT p.id)` 计数，得 57。
- 病害数和检出任务数直接用病害表 `routes_id` 统计，得 911 处、10 次。
- 巡检任务的路线登记来自生成路线，病害的路线定位来自采集定位，两者是独立来源，存在 1 次任务登记不一致。该次任务关联表只挂未知路线，病害却落在西乡段。
- 因此不能把零病害次数简单算成 57 减 10 等于 47。

**正确 SQL 口径（巡检次数）**

```sql
SELECT COUNT(DISTINCT p.id) AS 巡检次数
FROM ai_maintain_patrol p
JOIN ai_maintain_routes_patrol rp ON rp.patrol_id = p.id AND rp.del_flag = '0'
JOIN basic_facilities_routes r ON r.id = rp.routes_id AND r.del_flag = '0'
WHERE p.del_flag = '0'
  AND r.short_name = '宝安大道西乡段';
```

**正确 SQL 口径（检出病害的次数与病害数）**

```sql
SELECT COUNT(DISTINCT patrol_id) AS 检出病害的巡检次数,
       COUNT(*) AS 病害数
FROM ai_problem
WHERE del_flag = '0'
  AND routes_id = '1b0b4a9f700477b1d96119caac87c168';
```

**正确 SQL 口径（核对两次口径差异，列出 10 次任务各自病害数与登记情况）**

```sql
SELECT pr.patrol_id, COUNT(*) AS 病害数,
       CASE WHEN rp.patrol_id IS NOT NULL THEN '关联表登记西乡段'
            ELSE '关联表未登记西乡段' END AS 登记情况
FROM ai_problem pr
LEFT JOIN (
  SELECT DISTINCT patrol_id FROM ai_maintain_routes_patrol
  WHERE del_flag = '0' AND routes_id = '1b0b4a9f700477b1d96119caac87c168'
) rp ON rp.patrol_id = pr.patrol_id
WHERE pr.del_flag = '0'
  AND pr.routes_id = '1b0b4a9f700477b1d96119caac87c168'
GROUP BY pr.patrol_id, rp.patrol_id
ORDER BY 病害数 DESC;
```

#### 题8：某路段分月的巡检次数

**题目**

宝安大道西乡段在 2026 年 6 月和 7 月分别被巡检了多少次？

**标准答案**

6 月 20 次，7 月 37 次，7 月比 6 月多 17 次。两个月合计 57 次。

**统计口径**

- 必须先 JOIN 巡检任务主表限定有效任务，再关联路线表。
- 按 `create_time` 的月份分组，用 `COUNT(DISTINCT p.id)`。
- 这里统计的是次数，跨路线任务重复计数不影响西乡段自身的次数结论。

**正确 SQL 口径**

```sql
SELECT DATE_FORMAT(p.create_time, '%Y-%m') AS 月份,
       COUNT(DISTINCT p.id) AS 巡检次数
FROM ai_maintain_patrol p
JOIN ai_maintain_routes_patrol rp ON rp.patrol_id = p.id AND rp.del_flag = '0'
JOIN basic_facilities_routes r ON r.id = rp.routes_id AND r.del_flag = '0'
WHERE p.del_flag = '0'
  AND r.short_name = '宝安大道西乡段'
  AND p.create_time >= '2026-01-01'
GROUP BY DATE_FORMAT(p.create_time, '%Y-%m')
ORDER BY 月份;
```

### 方向五：月度巡查次数

#### 题9：全库各月巡查次数

**题目**

数据库里各个月份的巡查次数分别是多少？总共多少次？

**标准答案**

2025 年 6 月 2 次，2026 年 6 月 83 次，2026 年 7 月 62 次，总共 147 次。

**易错点**

- 必须以巡检任务表 `ai_maintain_patrol` 为主表按 `create_time` 分组，不能用病害表。
- 2025 年 6 月的 2 次是早期测试任务，没有设备、里程几乎为零，仍属于有效巡检记录，不能漏。
- 用病害表的 `patrol_id` 去数会丢掉 110 次零病害巡检。

**正确 SQL 口径**

```sql
SELECT DATE_FORMAT(create_time, '%Y-%m') AS 月份,
       COUNT(*) AS 巡查次数
FROM ai_maintain_patrol
WHERE del_flag = '0'
GROUP BY DATE_FORMAT(create_time, '%Y-%m')
ORDER BY 月份;
```

#### 题10：某个月各设备的巡检次数分布

**题目**

2026 年 6 月，三台巡检设备分别完成了多少次巡检？

**标准答案**

567test 完成 57 次，平整度测试设备完成 20 次，测试设备完成 6 次，合计 83 次。

**统计口径**

- 6 月有三台设备执行任务，7 月只有两台。
- 设备关联用 `equipment_id = device_code`，按设备名称分组。
- 三个数字相加等于 6 月全月任务数 83，可用于校验。

**正确 SQL 口径**

```sql
SELECT COALESCE(e.device_name, '未知设备') AS 设备,
       COUNT(*) AS 巡检次数
FROM ai_maintain_patrol p
LEFT JOIN ai_collection_equipment e ON e.device_code = p.equipment_id
WHERE p.del_flag = '0'
  AND DATE_FORMAT(p.create_time, '%Y-%m') = '2026-06'
GROUP BY e.device_name, p.equipment_id
ORDER BY 巡检次数 DESC;
```
