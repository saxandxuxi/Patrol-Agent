# 两步走选表方案：解决592个字段塞不进提示词的问题

---

## 一、现在的问题

### 现状
```python
# sql_engine.py 里
models=models_text[:12000]    # MDL模型文本截断到12000字符
schema=schema_context[:16000]  # schema上下文截断到16000字符
```

### 问题
17张表592个字段，肯定超过16000字符。截断之后，后面的表和字段就丢了！

这就是为什么你问冷门字段的时候，LLM根本不知道有这些字段——因为提示词里根本没写。

---

## 二、解决方案：两步走（业界标准做法）

### 核心思想
不要一次性把所有字段都塞给LLM，让它自己选。
就像你写SQL的时候，你也不会把592个字段都看一遍才开始写——你先想"我要查哪张表"，再去看那张表的字段。

```
第一步：给LLM看"表清单"（只有表名+一句话说明）
    ↓
第二步：LLM选出最相关的2~3张表
    ↓
第三步：只把这2~3张表的完整字段列表给LLM，让它写SQL
```

---

## 三、新增提示词：table_selector.md

> 用途：两步走第一步——让LLM从17张表里选出最相关的2~3张表
> 调用：新增 `table_selector.py`，在写SQL之前先调用
> 模型：role_model("semantic")（语义理解模型）
> 占位符：<<table_list>> <<question>>

```markdown
[system]

硬规则（不可违反）：
1. 只从给定的表清单里选，不能自己编表名。
2. 最多选3张表，最少选1张。
3. 选的表必须能回答用户的问题，不能选不相关的。
4. 回答完用户的问题需要几张表就选几张，不要多选，也不要少选。

["disease", "route"]

注意：
- 不要输出任何解释，只输出JSON数组
- 表名必须和上面清单里的完全一致
```

## 四、表清单示例

> 这个表清单从MDL里自动生成，每张表一行，只有表名+一句话说明。
> 17张表加起来也就几百字，肯定放得下。

```
- disease（病害主表）：病害数量、类型、位置、时间、图片、面积、置信度、收藏、工单状态、病害来源
- route（路线台账表）：路线长度、等级、管养单位、起止桩号、限速、车道数
- section（路段台账表）：路段划分、管养单位、起止桩号
- damage_dict（病害类型字典表）：病害类型编码→中文名、病害大类、默认置信度
- patrol（巡查任务表）：巡查任务编号、巡查时间、巡查车辆、巡查人员
- asset（资产主表）：沿线设施、资产、位置、类型
- distance_capture（定距表）：定距图片、里程校准
- pile_point（桩号明细表）：桩号、路段归属
- bridge（桥梁台账表）：桥梁信息、长度、宽度
- tunnel（隧道台账表）：隧道信息、长度
- slope（边坡台账表）：边坡信息、类型
- project（工程项目表）：养护工程、投资金额、工期
- maintenance_project（养护项目表）：养护项目、类型、金额
- work_record（施工记录表）：施工记录、时间、人员
- work_order（工单表）：工单状态、处理人、处理时间
```

## 五、流程改动

### 现在的流程
```
用户问题 → 直接生成SQL（把所有字段截断塞进提示词）
```

### 改成两步走
```
用户问题 → 第一步：选表（从17张表里选2~3张）
         → 第二步：只把这2~3张表的字段给LLM，让它写SQL
```

### 具体改哪里
1. **新增 `table_selector.py`**：调用table_selector.md提示词，选表
2. **修改 `sql_engine.py`**：
   - 写SQL之前，先调用table_selector选表
   - 只把选中的那几张表的MDL信息塞进提示词，不要全塞
3. **修改 `mdl_sync.py`**：生成表清单（每张表一行，只有表名+一句话说明）

## 六、业务逻辑说明

### 为什么这样选表？
1. **用户问病害相关的问题** → 选 disease + route
2. **用户问巡检任务相关的问题** → 选 patrol + disease
3. **用户问资产相关的问题** → 选 asset + route
4. **用户问工程/养护相关的问题** → 选 project / maintenance_project
5. **用户问工单相关的问题** → 选 work_order + disease

### 为什么最多选3张表？
- 太多了LLM也会乱
- 2~3张表刚好能回答绝大多数问题
- 真需要更多的话，再走复合问题拆分
