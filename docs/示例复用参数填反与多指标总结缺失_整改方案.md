# 示例复用参数填反与多指标总结缺失 系统性整改方案

> 覆盖的问题类型：复合问题（含子查询/CTE 的多指标查询）通过示例复用（chosen_example_direct）执行时，参数（路线 id/时间/病害类型等）填反了位置，导致 SQL 里的数据和列别名（中文标签）对不上；同时结果总结只取了一个数值，忽略了其他指标。

---

## 一、复现

**用户问题**（复合问题，两部分）：
1. 宝安大道西乡段泛油病害平均面积
2. 宝安中心恒明珠段面积大于上述平均值的泛油病害数量

**弹卡显示**（标签是对的，按用户问题）：
- 宝安大道西乡段泛油病害平均面积：0.9352㎡
- 宝安中心恒明珠段面积大于上述平均值的泛油病害数量：132㎡（单位也错了，应该是"处"）

**AI 回复**（只答了一个指标）：
> 共 132 处。（各口径：宝安大道西乡段泛油病害平均面积 = 0.9352）（注意：这次结果里只有 1 个对象的记录，做不了比较——多半是比较的另一方没查到，或条件没带全，建议换个问法再确认。）

**SQL 实际逻辑**（参数填反了）：
```sql
WITH avg_area AS (
  SELECT AVG(d.area) AS avg_val
  FROM disease d JOIN route r ON d.routes_id = r.id
  WHERE r.id = 'd74bf5e5...'  -- ⚠️ 恒明珠段（应该是西乡段）
    AND d.problem_type_name = '泛油'
)
SELECT
  ROUND((SELECT avg_val FROM avg_area), 4) AS 宝安大道西乡段泛油病害平均面积,  -- ⚠️ 标签写西乡，实际算恒明珠
  COUNT(*) AS 宝安中心恒明珠段面积大于上述平均值的泛油病害数量
FROM disease d JOIN route r ON d.routes_id = r.id
WHERE r.id = '1b0b4a9f...'  -- ⚠️ 西乡段（应该是恒明珠段）
  AND d.problem_type_name = '泛油'
  AND d.area > (SELECT avg_val FROM avg_area)
```

**引擎**：`chosen_example_direct`（复用之前确认过的示例 SQL）

## 二、根因（四层）

### 根因 1：示例复用的参数槽位填反了

示例 SQL 里有两个路线参数槽位：
- 槽位 A：计算平均值的路线（用户问题里是"西乡段"）
- 槽位 B：计算数量的路线（用户问题里是"恒明珠段"）

但复用时，参数填入的顺序搞反了：
- 槽位 A 填了恒明珠段的 id
- 槽位 B 填了西乡段的 id

结果：SQL 算的是"恒明珠的平均面积 + 西乡大于该面积的数量"，但标签写的是"西乡的平均面积 + 恒明珠大于该面积的数量"。

**本质**：示例的参数槽位没有和用户问题里的**语义角色**绑定（"算平均值的路线"/"算数量的路线"），只是按位置顺序填，顺序一错就全错。

### 根因 2：SQL 里的中文列别名是硬编码的

示例 SQL 里的 `AS 宝安大道西乡段泛油病害平均面积` 是写死的中文字符串。复用时参数换了，但别名没跟着换，导致标签和数据对不上。

### 根因 3：结果总结只取了一个数值列

`_grouped_summary`（或相关函数）只识别了一个数值列（132），忽略了另一个（0.9352）。用户问了两个指标，回复只答了一个。

这和上一个方案（二维分组总结）是同一类问题，但这里是**单行多指标**（不是多行分组），需要单独处理。

### 根因 4："只有 1 个对象"的警告是误报

结果自检函数判断"只有 1 个对象的记录，做不了比较"，但实际上 SQL 查了两个对象（西乡和恒明珠），只是结果是单行多列。自检函数把"单行"误判成了"只有一个对象"。

## 三、系统性解决方案

### 3.1 示例复用的参数槽位必须绑定语义角色

**改法**：示例的参数槽位不能只按位置顺序，必须带**语义角色标签**：

```yaml
# 示例的参数定义（原来只有位置顺序）
slots:
  - name: avg_route_id    # 语义角色：算平均值的路线
    label: 计算平均值的路线
  - name: count_route_id  # 语义角色：算数量的路线
    label: 被比较的路线
  - name: damage_type
    label: 病害类型
```

复用时，根据用户问题的 plan 里的条件，按**语义角色**填参数，不是按位置：
- 用户问题里"西乡段泛油平均面积" → 西乡段 id 填入 `avg_route_id`
- 用户问题里"恒明珠段面积大于上述平均值" → 恒明珠段 id 填入 `count_route_id`

**不能靠位置顺序填**——位置顺序在复合问题里非常容易搞反。

### 3.2 SQL 里的中文列别名必须动态生成

**改法**：示例 SQL 里的列别名用占位符，复用时根据填入的参数动态生成：

```sql
-- 原来（硬编码）
SELECT ROUND(..., 4) AS 宝安大道西乡段泛油病害平均面积, COUNT(*) AS 宝安中心恒明珠段面积大于上述平均值的泛油病害数量

-- 改成（占位符）
SELECT ROUND(..., 4) AS {{avg_route_label}}泛油病害平均面积, COUNT(*) AS {{count_route_label}}面积大于上述平均值的泛油病害数量
```

复用时：
- `{{avg_route_label}}` = 填入 `avg_route_id` 对应的路线中文名（如"宝安大道西乡段"）
- `{{count_route_label}}` = 填入 `count_route_id` 对应的路线中文名（如"宝安中心--恒明珠"）

这样参数换了，标签也跟着换，不会出现标签和数据对不上的情况。

### 3.3 单行多指标的结果总结

**改法**：结果是单行但有多个数值列时，总结必须**列出所有指标**，不能只取一个：

```
宝安大道西乡段泛油病害平均面积：0.9352 ㎡
宝安中心--恒明珠段面积大于该平均值的泛油病害：132 处
```

**判断条件**：
1. 结果只有 1 行；
2. 数值列 ≥ 2 个；
3. 不是二维分组（二维分组是多行 × 多列，这个是单行 × 多列）。

**渲染规则**：
1. 每个数值列都要念出来，带列名（中文标签）和单位；
2. 单位根据列名判断：含"面积"→㎡，含"数量/处数/多少"→处，含"平均"→对应单位，含"密度"→处/公里；
3. 如果列名里有"上述/该/前面的"等指代，要在总结里明确指代的是什么（如"大于该平均值（0.9352㎡）"）。

### 3.4 结果自检的"对象数"判断修正

**改法**：判断"有几个对象"不能只看行数，要看：
1. SQL 里的 WHERE 条件涉及几个不同的路线/对象（从 plan 或 SQL 解析）；
2. 或者结果的列名里包含几个不同的对象名；
3. 单行多列（每列对应一个对象）不算"只有 1 个对象"。

如果 SQL 里查了两个对象（即使结果是单行），就不能报"只有 1 个对象，做不了比较"的警告。

### 3.5 弹卡上的单位显示

**改法**：弹卡上每个指标的单位不能硬编码，要根据指标类型动态显示：
- 平均面积 → ㎡
- 数量/处数 → 处
- 密度 → 处/公里
- 长度 → 公里/米
- 百分比 → %

可以从列名里的关键词判断，或者从示例的参数定义里带单位信息。

## 四、判断流程图

```
示例复用执行
  │
  ▼
参数填入
  │
  ├─ 按语义角色填（avg_route_id/count_route_id），不是按位置 ✓
  ├─ 列别名动态生成（根据填入的参数换中文标签）✓
  │
  ▼
执行 SQL，得到结果
  │
  ▼
结果总结
  │
  ├─ 单行多指标？
  │    ├─ 是 → 列出所有指标，各带单位和中文标签
  │    └─ 否 → 走原有逻辑（一维分组/二维分组/单值）
  │
  ▼
结果自检
  │
  ├─ 对象数判断：看 SQL 条件里的对象数，不是只看行数
  └─ 单行多列（每列一个对象）不算"只有1个对象"
```

## 五、验收例子

### 例子 1：本次复现的问题
**问**：宝安大道西乡段泛油病害平均面积？宝安中心恒明珠段面积大于上述平均值的泛油病害数量？
**期望**：
- SQL 参数正确：avg_route_id=西乡段，count_route_id=恒明珠段
- 列别名正确：标签和数据对应
- 总结："宝安大道西乡段泛油平均面积 0.9352 ㎡；宝安中心--恒明珠段面积大于该值的泛油病害 132 处"
- 不误报"只有1个对象"

### 例子 2：参数顺序反过来
**问**：恒明珠段泛油平均面积？西乡段面积大于上述平均值的泛油数量？
**期望**：
- SQL 参数正确：avg_route_id=恒明珠段，count_route_id=西乡段
- 标签和数据对应（不会因为位置顺序搞反）

### 例子 3：单行多指标（非复合问题）

**期望总结**："西乡段泛油病害：总数 534 处，平均面积 1.07 ㎡，最大面积 7.52 ㎡"（三个指标都列出来）

### 例子 4：回归（一维分组不变）

**期望总结**：（和现在一样，不变）

## 六、不做的（明确边界）
1. 不改变示例的存储格式（只改参数填入和别名生成的逻辑）；
2. 不做 LLM 校验参数是否填反（用确定性的语义角色绑定，不额外调 LLM）；
3. 不改变 SQL 生成逻辑（只改示例复用的参数填入和结果总结）；
4. 三维及以上的复合问题（3 个以上子查询）暂不支持，直接让用户看表格。

---

## 七、实施顺序
1. **第一步**：示例参数槽位加语义角色标签（avg_route_id/count_route_id），按角色填不按位置；
2. **第二步**：SQL 列别名用占位符，复用时动态生成中文标签；
3. **第三步**：单行多指标的结果总结（列出所有指标，带单位）；
4. **第四步**：结果自检的对象数判断修正（看 SQL 条件，不只看行数）；
5. **第五步**：弹卡单位动态显示；
6. 每步做完跑验收例子，确认不回归。
