# 推荐卡准度：换问法就召回不到看板示例（给 codex）

## 一、现象
看板里已验证的问法，换个说法/改个数字，确认卡里就出不来相似示例，退到通用算子/Wren。

## 二、根因（代码注释自证）
同义召回两道闸，都把正确答案挡在外面：

### 闸1：fast path 门槛 0.85，正确问法实际只有 0.80~0.84
direct_match.py:196 注释原文：
"实测：w=0.85 时正确问法 0.80~0.84、第二名 0.68~0.71，所以默认门槛取 0.85"
→ 正确问法 0.80~0.84 < 门槛 0.85，永远过不了 fast path。

### 闸2：fast path 没过，LLM 打分默认关 → 直接空
direct_match.py:76-84：
if not rag_direct_score_enabled(默认False): return []
→ fast 没过就 return []，示例候选为空。

合起来：换问法 → 向量分 0.80~0.84 → 过不了 0.85 → 打分关 → 空。

### 闸3：only_exact 一刀切
capabilities.py:1226：命中槽位全齐的 preset/auto 时 only_exact=True；direct_match.py:67 非 exact 直接 return []，同义示例全丢。

## 三、修法
1. fast 门槛 rag_direct_fast_threshold 从 0.85 降到 0.78~0.80：正确问法 0.80~0.84 能进，第二名 0.68~0.71 仍被分差（fast_margin 0.05）挡住；
2. 不开 LLM 打分模型（rag_direct_score_enabled 维持关，避免 20s）；
3. only_exact 那层：槽位全齐的模板命中时，同义示例仍补一张卡，别一刀切 return []（候选卡可同时摆模板+相似示例，用户自己选）。

## 四、验收
1. 拿一条看板已验证问法，换说法（加"请列出"前缀、换路线名、改月份），确认卡能召出该示例并排在前面；
2. 换对象（泛油→裂缝）不应被召成同一条；
3. 不增加那次 20s 的打分调用。
