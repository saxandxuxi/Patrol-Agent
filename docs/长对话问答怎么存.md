# 长对话/多轮问答怎么存

## 长对话和单轮的区别

单轮问答：问题是完整的，直接生成 SQL。

长对话问答：后面的问题是不完整的，带指代词，依赖前面的上下文：
```
第1轮：西乡段泛油有多少处？  → 完整问题，直接查
第2轮：那恒明珠呢？          → 不完整，"那"指代上一轮的"泛油"
第3轮：它俩哪个多？多多少？   → 不完整，"它俩"指代前两轮的两个路线
```

所以长对话的存储，核心是：**既要存"用户说的原话"（带指代词），也要存"补全后的完整问题"**。

---

## 存储结构：每轮单独存，带上下文补全信息

### 每条多轮问答对，存这些字段：

```json
{
  "session_id": "对话唯一ID",
  "turn_index": 2,
  "user_question": "那恒明珠呢？",
  
  "context_completed_question": "恒明珠的泛油数量是多少处？",
  "inherited_slots": {
    "damage_type": "泛油"
  },
  "new_slots": {
    "route": "宝安中心--恒明珠"
  },
  
  "sql": "SELECT COUNT(*) FROM ... WHERE r.id = 'xxx' AND dd.problem_type = '泛油'",
  "tables": ["disease", "route", "damage_dict"],
  "query_type": "single_count",
  
  "prev_turns": [
    {
      "turn_index": 1,
      "user_question": "西乡段泛油有多少处？",
      "completed_question": "西乡段泛油有多少处？"
    }
  ]
}
```

### 每个字段是什么意思：

| 字段 | 说明 | 为什么要存 |
|------|------|-----------|
| `user_question` | 用户说的原话（带指代词） | 检索的时候，用户说"那恒明珠呢？"，匹配到这条 |
| `context_completed_question` | 补全后的完整问题 | SQL 生成阶段，用这个去生成 SQL |
| `inherited_slots` | 从上一轮继承了哪些槽位 | 学会"追问的时候要继承上一轮的条件" |
| `new_slots` | 这一轮新增了哪些槽位 | 学会"哪些条件是新提的" |
| `prev_turns` | 前面几轮说了什么 | 学会"多轮对话的上下文长什么样" |

---

## 为什么这么存

### 场景：用户现在问了一句追问"那它的平均面积呢？"

**第一步：上下文补全**
- 检索：拿用户的原话"那它的平均面积呢？"去搜 `user_question` 字段
- 找到类似的追问示例：之前有一条"那恒明珠呢？" → 补全成"恒明珠的泛油数量是多少处？"
- 学到：追问的时候，要继承上一轮的病害类型，替换成新的路线

**第二步：生成 SQL**
- 用补全后的完整问题"西乡段泛油的平均面积是多少？"去搜
- 找到类似的单轮问题示例
- 生成 SQL

## 长对话的三种典型模式，各存各的

### 模式1：换主体追问（"那XX呢？"）
```
第1轮：西乡段泛油有多少处？ → 单轮存
第2轮：那恒明珠呢？ → 多轮存，带 inherited_slots={"damage_type": "泛油"}
```
**检索用途：** 学会"追问新主体的时候，要继承上一轮的其他条件"

---

### 模式2：追问指标（"那平均面积呢？"）
```
第1轮：西乡段泛油有多少处？ → 单轮存
第2轮：那平均面积呢？ → 多轮存，带 inherited_slots={"route": "西乡段", "damage_type": "泛油"}
```
**检索用途：** 学会"追问新指标的时候，要继承上一轮的主体和过滤条件"

---

### 模式3：比较类追问（"它俩哪个多？"）
```
第1轮：西乡段泛油有多少处？ → 单轮存
第2轮：恒明珠的泛油呢？ → 多轮存
第3轮：它俩哪个多？多多少？ → 多轮存，带 post_calc 类型
```
**检索用途：** 学会"比较类追问，要结合前两轮的结果做 post_calc"

---

## 检索的时候怎么用

### 上下文补全阶段
**检索什么：** `user_question`（用户原话，带指代词）+ `inherited_slots`（继承了哪些条件）

**怎么检索：**
1. 用户现在说"那它的平均面积呢？"
2. 拿这句话去搜 `user_question` 字段（模糊匹配）
3. 找到类似的追问示例
4. 看示例里 `inherited_slots` 继承了哪些槽位
5. 照着补全当前问题的上下文

---

### SQL 生成阶段
**检索什么：** `context_completed_question`（补全后的完整问题）+ `sql`

**怎么检索：**
1. 先用上下文补全，把"那它的平均面积呢？"补全成"西乡段泛油的平均面积是多少？"
2. 拿补全后的问题去搜单轮问答对
3. 找到类似的单轮问题示例
4. 照着生成 SQL

---

## 一句话总结

**长对话存储的核心：每轮单独存，存两个版本的问题——用户原话（带指代词）+ 补全后的完整问题。**

- 上下文补全阶段：拿用户原话去搜，看类似的追问是怎么补全的
- SQL 生成阶段：拿补全后的完整问题去搜，看类似的完整问题 SQL 怎么写
