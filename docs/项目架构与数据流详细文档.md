# 巡检智能体 · 架构与数据流详细文档（带例子版）

> 每个模块都配一个具体"输入→输出"例子，照着代码逻辑讲。
> 代码根：`backend/app/`。主链路 `services/agent.py`。

---

## 〇、一句话概览
自然语言 → SQL → 数据 → 自然语言回答。
核心：**能不调大模型就不调**（模板/示例都是 0 次大模型）；所有确定性路径只摆确认卡，**用户拍板才执行**。

---

## 一、完整数据流（一条问题的旅程）
```
用户提问
 → [1]长对话补全 → [2]选库 → [3]语义规划 → [4]字段触达 → [5]路线解析
 → [6]收集候选(确认卡) → [7]用户点选 → [8]执行SQL → [9]校验 → [10]总结 → [11]记忆
```

---

## 二、逐模块 + 例子

### 1. 入口与路由（routers/）
**干什么**：收 HTTP 请求、返回流式回答。
**例子**：用户在前端输入框打"西乡段泛油有多少"→ `routers/chat.py` 收到这个字符串，转给 `agent.py` 主链路。

---

### 2. 长对话补全（query_rewrite.py）
**干什么**：把上一轮的条件和这一轮的话合并成完整句。
**例子**：
- R1：西乡段 7 月泛油有多少？
- R2："**那恒明珠呢？**"
- 补全后 → "恒明珠段 7 月泛油有多少？"（路线换成恒明珠，时间/病害类型沿用上一轮）。
- R3："**把明细调出来**" → "恒明珠段 7 月泛油的病害明细有哪些？"（明细指代）。

---

### 3. 选库（cross_db.py）
**干什么**：判这题该查 MySQL 还是 PostgreSQL。
**例子**：
- "西乡段病害有多少" → 词命中"病害/路线"→ MySQL；
- "GPS 轨迹点有多少条" → 词命中"GPS/轨迹"→ PostgreSQL（gpsdb）。
- 防的就是"经纬度"错回 MySQL 病害表。

---

### 4. 语义规划（nl2sql.build_query_plan）
**干什么**：调一次 LLM，把问题解析成结构化 plan。
**例子**：输入"西乡段面积大于 5 平米的泛油有多少处" → 输出：
```
shape=count, subject=disease
conditions=[route=西乡段, area>5, damage_type=泛油]
```
后续所有步骤都按这个 plan 干，不再重读问题原文。

---

### 5. 字段触达（field_grounding.py）
**干什么**：本地（不调 LLM）算出"这题最可能落哪张表哪列"。
**例子**：输入"隧道净宽净高是多少"：
- 表级打分：命中"隧道"→ top_table=tunnels；
- 列级打分："净宽""净高"整段命中列注释，各 +3 分；
- 输出 → 落点 tunnels，列 tunnel_clear_width / tunnel_clear_height。
**对比**：问"各病害类型有多少种"，虽然也命中"病害类型"列，但因为是统计题，落点不翻去字典表，主体仍是病害。

---

### 6. 路线解析（route_resolver.py）
**干什么**：路线名 → 路线 id。
**例子**："西乡段" → 精确匹配 → `id=1b0b4a9f...`；
找不到时按前两字模糊，给相近路线（"宝安大道西乡段/宝安中心-恒明珠"）。
**现状**：只有路线有这步；桥隧边坡正在补（见《桥隧边坡资产名称ID解析方案》）。

---

### 7. 字段目录（schema_catalog.py）
**干什么**：所有表/列/注释/枚举的唯一事实源，从 information_schema 自动读。
**例子**：加了一张新表"边坡"，不用改代码，它自动出现在目录里，字段触达就能认。

---

### 8. 收集候选（capabilities.collect_capabilities）
**干什么**：按优先级收四类候选，摆成确认卡。
**例子**：问"西乡段泛油有多少"：
| 层 | 命中 | 说明 |
|---|---|---|
| preset | 某条手写模板 | 0 次大模型 |
| auto | 自动挖的模板 | 0 次大模型 |
| example | "恒明珠泛油有多少"这条已验证问法 | 相似度够就摆 |
| generic | 通用明细兜底 | 排最后 |
排序后第一条标"推荐"，但仍由你点。

---

### 9. 挖模板（templatizer.py）
**干什么**：把"答对了"的 SQL 里的字面量挖成参数槽。
**例子**：SQL `WHERE r.id='1b0b...' AND area>5`：
- 路线 id 挖成"路线"槽（换成恒明珠也能用）；
- area 的 5 挖成"面积阈值"槽（换成 10 也能用）——前提是 area 列在目录里标了 numeric。

---

### 10. 相似示例直达（direct_match.py）
**干什么**：找历史上答过、换个说法的同型问题。
**例子**：问"面积大于 5 平米占比多少" → 召回"面积大于 10 平米占比多少" → 相似度 0.88 ≥ 阈值 + 结构同型 → 摆这张卡，你点确认就把 10 换成 5。

---

### 11. 通用算子（generic.py）
**干什么**：前面都没命中时的兜底，按表拼标准 SQL。
**例子**：问"列出病害类型字典" → 直接拼 `SELECT DISTINCT problem_type FROM ai_problem_base`。

---

### 12. 执行 SQL（sql_engine / wren_engine / db.py）
**干什么**：把 SQL 跑到库里拿回行。
**例子**：拼好的 `SELECT COUNT(*) ... WHERE route=西乡段 AND area>5` → 库返回 48。

---

### 13. 校准（calibrate.py）
**干什么**：执行前/后探一下数据实际范围，避免错答。
**例子**：问"6 月全库病害"，实际数据从 7/15 才有 → 老实说"7/15 才开始，6 月没数据"，不硬凑。

---

### 14. 校验（sql_lint.py / verify_answer 提示词）
**干什么**：SQL 语法、结果对不对得上问题。
**例子**：问"面积>10 有多少"，SQL 却把 area 列漏了 → 校验拦住，不把错结果当答案。

---

### 15. 总结成自然语言（analysis.py / result_summary）
**干什么**：把行数据说成人话。
**例子**：`{count:48, avg:2.1}` → "共 48 处，平均面积 2.1 平米，范围 7/15~7/30"。

---

### 16. 记忆（memory.py）
**干什么**：把这一轮的关键对象记下来，供下一轮指代。
**例子**：R2 命中巡检 id=XCBH... → 记下 `巡检id=XCBH...`；R3 说"把那次明细调出来"，直接拿这个 id 当条件，不用你再说一遍。

---

## 三、设计原则
1. 确定性优先：模板/示例命中就不调 LLM；
2. 用户拍板：所有确定性路径只摆卡，不直接执行；
3. 诚实：超范围/空表就明说；
4. 字段目录为事实源：加表加列不改代码。
5. 禁止用正则、关键词或短语包含关系推断业务语义；强制规则见
   [项目原则-禁止正则与关键词硬匹配.md](./项目原则-禁止正则与关键词硬匹配.md)。
