# 前端界面 UI 优化方案

> 生成时间：2026-10-10
> 基于：ModelSettings.vue、App.vue、AdminPanel.vue 代码分析 + 用户实际使用反馈
> 目标：提升界面美观度、降低认知负荷、提高操作效率

---

## 一、当前 UI 问题汇总

### 1.1 整体布局问题

| 问题 | 位置 | 影响 |
|---|---|---|
| 导航栏功能分区不清晰 | App.vue 顶部导航 | 高频功能（对话/看板/快捷查询）和低频配置（知识库/数据库/模型设置/管理）混在一起，用户找不到设置 |
| 页面缺少面包屑/返回 | 所有子页面 | 从设置页回到对话页只能点顶部导航，没有明确的返回路径 |
| 响应式断点只有一个（1000px） | ModelSettings.vue | 中等屏幕（1024px）下两列布局拥挤 |
| 没有全局加载状态 | 所有页面 | 切换页面时不知道是否在加载 |

### 1.2 设置页问题（ModelSettings.vue）

| 问题 | 位置 | 影响 |
|---|---|---|
| 4 个卡片全部展开，页面过长 | ModelSettings.vue | 用户需要滚动很多才能找到想要的设置 |
| 对话行为 8 个开关堆在一个卡片里 | 第143-258行 | 认知负荷高，用户分不清哪些是常用的 |
| 说明文字过长（有的 3-4 行） | 多个开关的 p 标签 | 页面显得杂乱，重点不突出 |
| 相似度阈值开关和输入框挤在一起 | 第235-253行 | 布局不美观，开关和数字输入框对齐不好 |
| 保存按钮分散在每个卡片底部 | 多个 form-actions | 用户改了多个卡片的设置，需要分别保存，容易忘记 |
| 没有设置分组/折叠 | 全部展开 | 低频设置（如自动挖掘新模板）占用和高频设置一样的空间 |
| "当前生效"提示字号太小 | param-hint 12px | 用户不容易看到当前用的是哪个模型 |

### 1.3 对话页/确认卡问题

| 问题 | 位置 | 影响 |
|---|---|---|
| 确认卡（弹卡）不美观 | ChatPanel.vue | 用户反馈"特别的丑，不美观" |
| 推荐卡硬推荐，不相关的也推 | ChatPanel.vue | 用户反感，降低信任感 |
| 弹卡后又出现对话，速度慢 | ChatPanel.vue | 用户点了确认后还要等，体验不流畅 |
| 结果工作台显示执行引擎错误 | ResultPanel.vue | 用户选了模板查询，但显示"Wren 语义层"，误导 |
| 后续建议（"要不要我再帮你看看"）多余 | ChatPanel.vue | 用户反馈"不需要，直接总结结果就行" |
| 统计口径展示不够醒目 | 回复区域 | 外行用户看不懂 SQL，需要更直观的可信度展示 |

### 1.4 看板/快捷查询问题

| 问题 | 位置 | 影响 |
|---|---|---|
| 看板功能杂，很难看懂 | Workbench.vue | 用户反馈"感觉这一个版面的功能很杂" |
| 预置查询维护没有显示模板 SQL | PresetQueries.vue | 用户想仿造写模板时看不到示例 |
| 半自动筛选功能意义不明确 | PresetQueries.vue | 和确定性模板路径功能杂糅 |
| 固定看板没有置顶/分组的前端入口 | Workbench.vue | 接口已就绪（card-state），但前端没有操作入口 |
| 看板卡片刷新后没有明显反馈 | Workbench.vue | 用户不知道是否刷新成功 |

### 1.5 管理页问题

| 问题 | 位置 | 影响 |
|---|---|---|
| 自动模板表格信息密度低 | AdminPanel.vue 第67-130行 | 状态、槽位、审核结果挤在一起，不容易快速判断 |
| 审核结果只有 tooltip | AdminPanel.vue 第118-127行 | 用户需要悬停才能看到，不直观 |
| 没有"一键恢复误报模板"按钮 | AdminPanel.vue | 被误降的模板恢复操作复杂 |
| 操作按钮太多（6个），没有分组 | AdminPanel.vue 第35-58行 | 用户分不清哪些是常用的 |
| 模板 SQL 展示用 pre 标签，没有高亮 | AdminPanel.vue 第73行 | 长 SQL 不容易阅读 |
| 没有模板状态筛选 | AdminPanel.vue | 40 条模板全部展示，不能只看被降级的 |

### 1.6 视觉风格问题

| 问题 | 位置 | 影响 |
|---|---|---|
| 颜色使用不统一 | 全局 | 有的地方用 Element Plus 默认色，有的地方用自定义色 |
| 卡片间距不一致 | 多个页面 | 有的 18px，有的 20px，视觉不统一 |
| 字号层级不清晰 | 全局 | 标题、正文、说明文字的字号对比不够 |
| 没有空状态设计 | 多个页面 | 没有数据时只显示空表格，不友好 |
| 按钮风格不统一 | 全局 | 有的用 link，有的用 default，有的用 primary |

## 二、优化方案

### 2.1 整体布局与导航优化

#### 2.1.1 导航栏重构

**当前**：对话 / 固定看板 / 快捷查询 / 设置▾（下拉：知识库/数据库/模型设置/管理）

**优化后**：
- 左侧主导航（图标+文字）：对话、固定看板、快捷查询
- 底部配置区（折叠）：知识库、数据库、模型设置、管理
- 顶部只保留品牌名 + 服务状态 + 用户头像

**好处**：
- 高频功能一目了然
- 低频配置收起来，不占视觉空间
- 符合现代后台管理系统的交互习惯

#### 2.1.2 增加面包屑导航

在每个子页面顶部增加面包屑：
- 模型设置：首页 > 设置 > 模型设置
- 管理：首页 > 设置 > 管理

点击"首页"或"设置"可以快速返回。

#### 2.1.3 增加全局加载状态

- 切换页面时顶部显示进度条（类似 NProgress）
- API 请求时按钮显示 loading，防止重复点击
- 长时间操作（如模板审核）显示进度提示

#### 2.1.4 增加响应式断点

```css
/* 当前只有 1000px 一个断点 */
@media (max-width: 1000px) { ... }

/* 增加 */
@media (max-width: 1280px) { ... }  /* 中等屏幕：设置页改单列 */
@media (max-width: 768px) { ... }   /* 平板：导航折叠 */
@media (max-width: 480px) { ... }   /* 手机：全屏对话 */
```

### 2.2 设置页优化（ModelSettings.vue）

#### 2.2.1 卡片分组+折叠

把 4 个卡片分成 3 组，默认只展开第一组：

```
┌─ 模型配置（默认展开）────────────────────┐
│  角色模型（4个下拉）                      │
│  新增/更新模型（表单）                    │
│  已保存模型（表格）                       │
└──────────────────────────────────────────┘

┌─ 对话行为（默认展开）────────────────────┐
│  常用设置（思考/联网/反思/后续建议）       │
│  高级设置（折叠，默认收起）               │
│    - 确定性能力复用模式                   │
│    - 自动沉淀模板                         │
│    - 自动挖掘新模板                       │
│    - 相似问法直达 + 阈值                  │
└──────────────────────────────────────────┘
```

#### 2.2.2 统一保存按钮

- 去掉每个卡片底部的"保存"按钮
- 页面底部增加固定的"保存所有更改"按钮
- 有未保存更改时按钮高亮，显示"有 N 项更改未保存"
- 离开页面时提示"有未保存的更改，是否离开？"

#### 2.2.3 开关项优化

每个开关项改成：
```
┌─────────────────────────────────────────┐
│  [开关]  思考模式                        │
│          知识问答开启思考（慢但更完整）    │
│          当前：开启                       │
└─────────────────────────────────────────┘
```

- 开关在左，标题和说明在右
- 增加"当前：开启/关闭"状态提示
- 说明文字精简到 1 行，详细说明放 tooltip

#### 2.2.4 阈值设置优化

相似度阈值改成滑块+数字输入框：
```
相似度阈值  [滑块 0.5──────●───1.0]  0.85
≥ 阈值且结构同型 → 直接摆确认卡
```

- 滑块直观，数字输入框精确
- 去掉"高置信直摆"的独立开关，合并成一个设置

#### 2.2.5 模型选择优化

- 下拉框增加模型来源标签（如"阿里通义"、"DeepSeek"）
- 当前生效的模型用绿色标签标注
- 增加"测试当前模型"按钮，不用填表单就能测

### 2.3 对话页/确认卡优化

#### 2.3.1 确认卡（弹卡）美化

**当前问题**：用户反馈"特别的丑"。

**优化后**：
```
┌─ 找到 3 个现成口径 ──────────────────────┐
│                                          │
│  ┌─ 推荐 ─────────────────────────────┐  │
│  │ 某类病害规模（模板）                │  │
│  │ 西乡段泛油病害有多少处 → 534 处     │  │
│  │ 参数：路线=西乡段，类型=泛油        │  │
│  │ [查看 SQL]  [用这个口径查询]        │  │
│  └────────────────────────────────────┘  │
│                                          │
│  ┌─ 其他候选 ─────────────────────────┐  │
│  │ 相似问法：西乡段泛油有多少条（示例） │  │
│  │ 通用明细：病害明细（兜底）           │  │
│  └────────────────────────────────────┘  │
│                                          │
│  [都不合适，让 AI 自己查]                 │
└──────────────────────────────────────────┘
```

- 推荐项用卡片式，突出显示
- 其他候选用列表式，不抢视觉
- 每个候选显示：来源（模板/示例/通用算子）、参数、预计结果
- "查看 SQL"默认收起，点击展开
- 主按钮"用这个口径查询"用 primary 色，突出

#### 2.3.2 推荐卡准入收紧

- 不相关的候选不展示（不是"硬推荐"）
- 最多展示 3 个候选，超过的收进"更多"
- 每个候选显示匹配度（高/中/低），低的默认收起
- 用户连续 3 次选"都不合适"，自动降低推荐频率

#### 2.3.3 确认后直接出结果

- 用户点"用这个口径查询"后，直接执行 SQL 并展示结果
- 不再弹第二次对话
- 执行过程中显示加载动画和"正在查询..."
- 结果出来后直接展示，不需要用户再操作

#### 2.3.4 去掉多余的后续建议

- 去掉"要不要我再帮你看看"的自动建议
- 改成用户点击"继续追问"按钮才显示
- 或者在结果下方用小字显示 2-3 个相关问题，用户可点可不点

#### 2.3.5 执行引擎显示修正

- 用户选了模板查询，结果工作台显示"预置模板（已确认）"，不是"Wren 语义层"
- 引擎标签用不同颜色区分：模板=绿色、示例=蓝色、Wren=橙色、通用算子=灰色

#### 2.3.6 统计口径/可信度展示

外行用户看不懂 SQL，需要更直观的可信度展示：
```
┌─ 查询结果 ──────────────────────────────┐
│  共 534 处泛油病害                       │
│                                          │
│  ✓ 数据来源：MySQL 病害表                │
│  ✓ 查询范围：宝安大道西乡段              │
│  ✓ 过滤条件：del_flag=0，类型=泛油       │
│  ✓ 数据时间：截至 2026-07-30 17:26       │
│                                          │
│  [查看完整 SQL]  [导出结果]              │
└──────────────────────────────────────────┘
```

- 用勾选图标展示查询条件，让用户一眼看懂
- "查看完整 SQL"默认收起，给懂技术的用户看
- 增加"数据可信度"标签（高/中/低），基于数据完整性和查询复杂度

### 2.4 看板/快捷查询优化

#### 2.4.1 看板页面重构

**当前问题**：功能杂，很难看懂。

**优化后**，分成 3 个标签页：
1. **我的看板**：用户收藏的固定查询卡片，点击刷新出结果
2. **示例库**：系统预置的示例问题，点击直接查询
3. **模板管理**：手写模板的增删改查

#### 2.4.2 固定看板卡片优化

每张卡片：
```
┌─ 西乡段泛油病害总数 ────────────┐
│  534 处                         │
│  上次更新：2分钟前  [刷新]      │
│  [置顶] [编辑] [删除]           │
└─────────────────────────────────┘
```

- 大字号显示结果数字
- 显示上次更新时间
- 刷新按钮直观
- 增加置顶/分组操作（接口已就绪）

#### 2.4.3 预置查询维护显示 SQL

- 编辑模板时，右侧显示当前模板的 SQL 示例
- SQL 用代码高亮展示
- 增加"复制 SQL"按钮
- 增加"用这个模板测试查询"按钮，直接看结果

#### 2.4.4 去掉半自动筛选

- 用户反馈"半自动筛选意义不明确"
- 和确定性模板路径功能杂糅
- 建议去掉，或者合并到"模板管理"里

### 2.5 管理页优化

#### 2.5.1 模板表格优化

- 增加状态筛选标签：全部 / 启用（mature）/ 待观察（candidate）/ 已失效（broken）/ 冷门（cold）
- 状态列用彩色标签：启用=绿色、待观察=黄色、已失效=红色、冷门=灰色
- 审核结果列：有问题的显示红色感叹号，点击展开详情
- 增加"批量操作"：批量启用/禁用/删除

#### 2.5.2 审核结果展示优化

- 不用 tooltip，改成点击行展开详情
- 展开后显示：问题类型、严重程度、描述、位置、建议修复
- 区分"确定性问题"（红色，必须修）和"LLM 审核问题"（黄色，可能误报）
- 增加"一键恢复为启用"按钮（针对被误降的模板）

#### 2.5.3 操作按钮分组

把 6 个按钮分成两组：
- **常用操作**：刷新、重新校准、LLM 审核
- **高级操作**（折叠）：重建索引、同步问题库、生命周期巡检

#### 2.5.4 SQL 展示优化

- 用代码高亮组件（如 highlight.js）展示 SQL
- 增加"复制 SQL"按钮
- 长 SQL 默认折叠，点击展开
- 增加"在新窗口查看"按钮

### 2.6 视觉风格统一

#### 2.6.1 颜色系统

定义统一的颜色变量：
```css
:root {
  --primary: #409eff;        /* 主色：操作按钮 */
  --success: #67c23a;        /* 成功：启用/正确 */
  --warning: #e6a23c;        /* 警告：待观察/可能误报 */
  --danger: #f56c6c;         /* 危险：错误/已失效 */
  --info: #909399;           /* 信息：说明文字 */
  --bg-page: #f5f7fa;        /* 页面背景 */
  --bg-card: #ffffff;        /* 卡片背景 */
  --text-primary: #303133;   /* 主文字 */
  --text-regular: #606266;   /* 常规文字 */
  --text-secondary: #909399; /* 次要文字 */
  --border: #dcdfe6;         /* 边框 */
}
```

#### 2.6.2 字号系统

```css
:root {
  --font-size-title: 20px;     /* 页面标题 */
  --font-size-card-title: 16px; /* 卡片标题 */
  --font-size-body: 14px;      /* 正文 */
  --font-size-small: 12px;     /* 说明/辅助 */
  --font-size-tiny: 11px;      /* 标签/角标 */
}
```

#### 2.6.3 间距系统

```css
:root {
  --spacing-xs: 4px;
  --spacing-sm: 8px;
  --spacing-md: 12px;
  --spacing-lg: 16px;
  --spacing-xl: 20px;
  --spacing-2xl: 24px;
}
```

所有卡片间距、内边距统一用这些变量。

#### 2.6.4 空状态设计

每个没有数据的页面/表格都增加空状态：
```
┌─────────────────────────────┐
│         📭                   │
│     暂无数据                 │
│  点击"新增"添加第一条记录     │
└─────────────────────────────┘
```

- 图标 + 简短说明 + 操作引导
- 不同页面用不同的图标和文案

## 三、实施优先级

### P0（必须做，用户反馈强烈）

1. **确认卡美化**：用户多次反馈"特别的丑"
2. **确认后直接出结果**：用户说了三回"命中之后直接出结果"
3. **去掉多余的后续建议**：用户明确说"不需要"
4. **执行引擎显示修正**：用户选了模板但显示 Wren，误导
5. **推荐卡准入收紧**：用户反感"硬推荐"

### P1（应该做，提升体验）

1. **设置页分组+折叠**：页面太长，认知负荷高
2. **统一保存按钮**：改了多个设置要分别保存，容易忘
3. **管理页审核结果展示优化**：tooltip 不直观，没有一键恢复
4. **看板页面重构**：功能杂，很难看懂
5. **预置查询显示 SQL**：用户想仿造写模板时看不到示例

### P2（可以做，锦上添花）

1. **导航栏重构**：左侧导航 + 底部配置区
2. **面包屑导航**：子页面返回路径
3. **全局加载状态**：切换页面进度条
4. **视觉风格统一**：颜色/字号/间距系统
5. **空状态设计**：没有数据时的友好提示
6. **响应式断点增加**：中等屏幕适配

---

## 四、不做的边界

1. **不做完整的设计系统重构**：只优化现有页面，不引入新的 UI 框架
2. **不做暗色模式**：工作量大，优先级低
3. **不做多语言**：当前只有中文用户
4. **不做移动端适配**：主要在桌面端使用，移动端只保证基本可用
5. **不改后端接口**：所有优化基于现有接口，只改前端
