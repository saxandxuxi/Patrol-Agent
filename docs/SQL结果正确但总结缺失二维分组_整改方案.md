# SQL结果正确但文字总结缺失二维分组 系统性整改方案

> 覆盖的问题类型：SQL 查询结果是**二维分组（交叉表）**，但文字总结只渲染了一维（只挑了一个数值列），导致用户问的关键信息（各分组的数值）在总结里完全消失。

---

## 一、复现

**用户问题**：西乡段和恒明珠段里，人工巡检发现的病害和车辆巡检发现的各有多少？

**SQL 结果（控制台表格，正确）**：

| 路线 | 人工巡检发现病害数 | 车辆巡检发现病害数 | 总病害数 |
|---|---|---|---|
| 宝安中心--恒明珠 | 0 | 749 | 749 |
| 宝安大道西乡段 | 0 | 911 | 911 |

**AI 文字总结（错误）**：
> 分布：宝安中心--恒明珠 749处，宝安大道西乡段 911处，合计 1660处。（结论：宝安大道西乡段最多（911处），宝安中心--恒明珠最少（749处），相差 162处。）

**问题**：
1. 用户问的是"人工巡检和车辆巡检各有多少"，但总结里**完全没有提到人工巡检和车辆巡检的数值**；
2. 总结只说了总数（749/911），相当于把用户的二维问题降维成了一维问题；
3. 关键信息"人工巡检均为 0，全部是车辆巡检发现的"在总结里消失了——这恰恰是用户最想知道的。

---

## 二、根因

`_grouped_summary` 函数（agent.py 505-564 行）只支持**一维分组**：

```python
def _grouped_summary(rows, message, spec):
    numeric = _numeric_columns(rows)           # 找出所有数值列
    metric = _primary_metric(numeric, message, rows)  # ⚠️ 只挑一个数值列
    label = _label_column(rows, numeric)        # ⚠️ 只挑一个标签列
    # 然后按"标签 + 单个数值"渲染，每行一个标签一个值
```

对于二维分组的结果（一个标签列 + 多个数值列）：
- 数值列有 3 个：`人工巡检发现病害数`、`车辆巡检发现病害数`、`总病害数`
- `_primary_metric` 只挑其中一个（挑了"总病害数"，因为列名里有 count 或排在前面）
- 标签列是"路线"
- 所以渲染成"恒明珠 749，西乡段 911"——**人工巡检和车辆巡检的数值被完全忽略**

**本质**：总结函数假设结果是"一个标签列 + 一个数值列"的一维分组，但用户的问题产生了"一个标签列 + 多个数值列"的二维交叉表，函数没有能力处理多数值列。

---

## 三、系统性解决方案

### 3.1 检测二维分组（交叉表）

在 `_grouped_summary` 开头加一步检测：结果是否是二维分组（交叉表）？

**判断条件**（满足全部）：
1. 有且仅有一个非数值列（标签列，如"路线"）；
2. 数值列 ≥ 2 个；
3. 数值列的列名**共享同一个指标词根**（如"人工巡检发现病害数"/"车辆巡检发现病害数"都包含"巡检发现病害数"，或"上行处数"/"下行处数"都包含"处数"）；
4. plan 的 group_by 有 ≥ 2 个维度，或者 spec 里标记了 pivot/cross_tab。

**如果不满足**（比如数值列是不同指标：总数/平均面积/最大面积），走原有的一维总结逻辑，但要在总结里**列出所有数值列**，不能只挑一个。

### 3.2 二维分组的渲染格式

如果检测到是二维分组，按以下格式渲染：

```
分布：
- 宝安中心--恒明珠：人工巡检 0 处，车辆巡检 749 处（合计 749 处）
- 宝安大道西乡段：人工巡检 0 处，车辆巡检 911 处（合计 911 处）
合计 1660 处。
（结论：两条路的病害全部由车辆巡检发现，人工巡检均为 0；西乡段的车辆巡检发现数（911）高于恒明珠段（749）。）
```

**关键规则**：
1. **每个数值列都要念出来**，不能只挑一个；
2. 数值列的顺序按 plan 里的 group_by 顺序，或按列名排序；
3. 如果有"总计/合计"列，放在每行末尾括号里，不参与排名；
4. 结论要基于二维数据给，不能只基于总数给（比如不能只说"西乡段最多"，要说"两条路都是车辆巡检发现的，人工巡检均为 0"）。

### 3.3 多数值列但不是二维分组的情况

如果数值列是**不同指标**（如"总数/平均面积/最大面积"），不是同一指标的不同维度：

```
分布：
- 宝安大道西乡段：总数 911 处，平均面积 1.07 ㎡，最大面积 7.52 ㎡
- 宝安中心--恒明珠：总数 749 处，平均面积 2.35 ㎡，最大面积 7.52 ㎡
```

**关键规则**：
1. 所有数值列都要念出来，不能只挑一个；
2. 每个数值列带单位（处/㎡/米等）；
3. 结论可以只针对主要指标（用户问题里点名的指标），但其他指标也要在分布里列出来。

### 3.4 `_primary_metric` 的改造

当前 `_primary_metric` 只返回一个数值列，需要改造：

1. **新增 `_all_metrics(numeric, message, rows)`**：返回所有数值列，按"用户点名的指标优先 → 含 count 的列 → 其他列"排序；
2. `_primary_metric` 保留，但只用于"结论里主要对比哪个指标"，不用于"渲染哪些数值列"；
3. 渲染时用 `_all_metrics` 的全部列，结论时用 `_primary_metric` 的主要列。

### 3.5 结论生成的改造

`_extreme_conclusion` 当前只基于一维数据（标签 + 单个数值）给结论，需要支持二维：

1. **二维分组的结论**：先看各维度的趋势（"两条路都是车辆巡检多"），再看主要指标的排名（"西乡段总数最多"）；
2. **如果某个维度全是 0**，要明确指出来（"人工巡检均为 0，全部是车辆巡检发现的"）——这是用户最想知道的关键信息；
3. **如果有异常值**（如某条路的某个维度特别高/特别低），要指出来。

## 四、判断流程图

```
结果 rows
  │
  ▼
数值列有几个？
  │
  ├─ 1 个 → 走原有一维总结逻辑（不变）
  │
  └─ ≥2 个 → 是二维分组吗？
       │
       ├─ 是（数值列共享同一指标词根，如"人工巡检"/"车辆巡检"）
       │    → 按二维交叉表渲染：每行念所有数值列
       │    → 结论基于二维数据（含"某维度全为0"的关键信息）
       │
       └─ 否（数值列是不同指标，如"总数/平均面积/最大面积"）
            → 按多指标渲染：每行念所有数值列，各带单位
            → 结论只针对主要指标（用户点名的）
```

## 五、验收例子

### 例子 1：二维分组（本次复现的问题）
**问**：西乡段和恒明珠段里，人工巡检发现的病害和车辆巡检发现的各有多少？
**结果**：路线 × {人工巡检, 车辆巡检, 总数}
**期望总结**：
> 分布：宝安中心--恒明珠：人工巡检 0 处，车辆巡检 749 处（合计 749 处）；宝安大道西乡段：人工巡检 0 处，车辆巡检 911 处（合计 911 处）。合计 1660 处。
> （结论：两条路的病害全部由车辆巡检发现，人工巡检均为 0；西乡段的车辆巡检发现数（911）高于恒明珠段（749）。）

### 例子 2：二维分组（上下行）
**问**：西乡段上行和下行各有多少处病害？
**结果**：路线 × {上行, 下行}
**期望总结**：
> 分布：宝安大道西乡段：上行 911 处，下行 0 处。合计 911 处。
> （结论：病害全部集中在上行方向，下行没有记录。）

### 例子 3：多指标（不是二维分组）
**问**：西乡段和恒明珠段的病害总数、平均面积、最大面积分别是多少？
**结果**：路线 × {总数, 平均面积, 最大面积}
**期望总结**：
> 分布：宝安大道西乡段：总数 911 处，平均面积 1.07 ㎡，最大面积 7.52 ㎡；宝安中心--恒明珠：总数 749 处，平均面积 2.35 ㎡，最大面积 7.52 ㎡。
> （结论：西乡段病害总数更多，但恒明珠段的平均面积更大。）

### 例子 4：一维分组（回归，不退化）
**问**：西乡段各类型病害有多少？
**结果**：病害类型 × {处数}
**期望总结**：（和现在一样，不变）
> 分布：泛油 534 处，未识别 377 处，合计 911 处。（结论：泛油最多。）

## 六、不做的（明确边界）
1. 不做三维及以上分组（行 × 列 × 页）——这类结果直接让用户看表格，文字总结只给主要发现；
2. 不改变 SQL 生成逻辑——只改结果总结渲染，SQL 该怎么生成还怎么生成；
3. 不做 LLM 总结——仍然用确定性模板渲染，不额外调 LLM（控制成本和延迟）；
4. 不改变 list/detail 类结果的渲染——只改 distribution/count/top 类的聚合结果。

---

## 七、实施顺序
1. **第一步**：`_grouped_summary` 加二维分组检测 + 二维渲染格式（核心改动）；
2. **第二步**：新增 `_all_metrics`，改造 `_primary_metric` 只用于结论；
3. **第三步**：`_extreme_conclusion` 支持二维数据结论（含"某维度全为0"的关键信息）；
4. **第四步**：多指标（非二维分组）的渲染格式；
5. 每步做完跑验收例子，确认不回归。
