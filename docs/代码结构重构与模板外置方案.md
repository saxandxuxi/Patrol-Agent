# 代码结构重构与提示词 / 模板 / 词表外置方案（给 codex）

本文只做**结构重构与知识外置**，不改任何业务判定逻辑、不换模型、不动 Wren/MDL。
目标是让"会变的业务知识"全部离开 `.py`，让两个超大文件按职责拆开，做到：
改提示词、改 SQL 模板、改词表、改字段口径都不用翻 Python；项目结构一眼能看懂。

行号是写作时的快照，**搬迁一律以函数名 / 常量名为准**，不要对行号。

---

## 一、结论：需不需要把模板等放到单独文件加载

需要，但**不是推倒重来**。项目已经把"角色级提示词"这一层做对了：

- `backend/app/services/prompts.py` 是统一加载器（读项目根 `prompts/*.md`，支持 `[system]/[user]` 分段、`<<占位符>>`、`lru_cache`、`clear_cache()` 热更新、占位符漏填写日志）。
- 项目根 `prompts/` 已有 18 个 `.md`，且 `prompts/README.md` 维护了清单和"已知坑"。

问题在于**同样属于"会变的业务知识"的另外四类东西还埋在代码里**，只迁完了一类。本方案就是把剩下四类按同一套思路外置，并顺手拆掉两个上帝文件。

一条总原则：

> **`.py` 里只留"流程编排"和"确定性算法"；凡是会随业务/问法/库结构变化而需要改的——提示词、SQL 模板、触发词表、语义键到 SQL 片段的映射、字段中文口径与编码映射——一律放外部资源文件，由统一加载器读取。**

## 三、目标目录结构

静态、随 git 版本管理的"知识资源"统一到项目根 `resources/`（与 `prompts/` 平级）；
运行期产物继续放 `backend/data/`，两者彻底分开。

```
巡检智能体/
├─ prompts/                        # ① LLM 提示词（已存在，原位保留，加载器不动）
│  └─ fragments/                   #    新增：可复用 hint 片段（_business_hint 等的文本本体）
│
├─ resources/                      # 【新增】所有确定性知识 / 配置，随 git 管理
│  ├─ sql_templates/               # ② 内置确定性 SQL 模板（由 24 个 _build_* 声明化迁入）
│  │  ├─ _index.yaml               #    注册表：id / 标题 / 触发语义 / 方言 / 守卫 / 模板文件
│  │  ├─ route.yaml                #    路线信息、路线总数等
│  │  ├─ density.yaml              #    每公里密度
│  │  ├─ bucket.yaml               #    分档对比（参数外置，算法仍在代码）
│  │  ├─ patrol.yaml               #    巡检任务 / 巡检分组 / Top
│  │  └─ ...                       #    一个模板一个文件，文件名即模板 id
│  ├─ lexicon/                     # ③ 词表与语义映射
│  │  ├─ semantics.yaml            #    shapes / subjects / group_by / metrics / derived / order
│  │  ├─ metrics.yaml              #    指标键→SQL 片段、维度、数值字段、时间桶
│  │  ├─ operators.yaml            #    聚合算子 / 分档粒度 / 分档聚合 的键→表达式
│  │  ├─ trigger_words.yaml        #    分组/对比/图片/弃权/领域信号/归因/衍生指标等兜底词
│  │  └─ result_words.yaml         #    agent 侧结果标签、度量词、分组域、可修复 issue 等
│  └─ field_meta/                  # ④ 字段元数据的"静态覆盖层"
│     └─ code_map_overrides.json   #    由 backend/app/data 迁入；事实源仍是 DB 列注释
│
├─ backend/data/                   # 只放运行期产物：agent.db、schema_catalog.json 缓存
│
└─ backend/app/services/
   ├─ resource_loader.py           # 【新增】通用资源加载器（仿 prompts.py，见 §5）
   ├─ schema_catalog.py            # 字段元数据唯一事实源（DB 注释 + resources 覆盖）
   ├─ nl2sql/                      # 【由 nl2sql.py 改成的包】见 §4.1
   ├─ agent/                       # 【由 agent.py 改成的包】   见 §4.2
   └─ ...（其余 service 不动）
```

`preset_queries.json` 的归属：它是"用户在前端手配的模板"，与"系统内置模板"是两类，
建议迁到 `resources/sql_templates/presets.json`（或保留 `backend/app/data/` 但在 `_index` 里登记路径），
由同一个 `TemplateRegistry` 加载，界面上分区展示（系统内置只读、用户自建可编辑）。

## 五、四类知识的外置规格（给 codex 的具体做法）

### 5.1 通用资源加载器 `resource_loader.py`

完全仿照现有 `prompts.py` 的成熟做法，不要另造一套：

- `load_yaml(name) -> dict` / `load_json(name)`，基于 `PROJECT_ROOT/resources/...` 解析路径。
- `@lru_cache` 缓存；提供 `clear_cache()` 热更新（和 `prompts.clear_cache()` 一起挂到同一个重载入口）。
- 文件缺失 / YAML 语法错 / 引用了不存在的模板 id 时，**写 error 日志并回退到安全默认（通常是转 Wren/LLM 路径），不许静默、不许抛 500**。
- 启动时做一次**资源自检**：所有 `_index` 引用的文件存在、所有模板 id 唯一、所有词表 YAML 可解析，结果打印到启动日志。

### 5.2 SQL 模板声明化（②，工作量最大，也最值）

把 24 个 `_build_*` 的"SQL 字符串"搬到 `resources/sql_templates/*.yaml`，
Python 里只保留：注册表加载、按语义 plan 选模板、槽位填充、白名单/守卫校验。
**含算法的（bucket 分档中位数、generic_metric、通用明细/聚合/画像）不强行声明化**——
算法留代码，参数（粒度键、聚合表达式、别名、触发词）外置到 YAML。

模板文件规格（`_index.yaml` 登记，一个模板一个文件）：

```yaml
id: route_density                 # 与原 _build_density_template 对应，唯一
title: 路线病害密度（处/公里）      # 中文名，前端"内置模板"只读展示用
dialects: [physical, mdl]         # 适用方言；只适用一种就写一种
match:                            # 声明式触发依据——用语义结构，不用用户原话
  shapes: [density]               # 对应 plan 的 shape / metric / subject
  subjects: [disease]
params:                            # 槽位及来源（实体解析 / plan 条件 / 用户输入）
  route_id: { from: entity, entity: route, required: true }
guards:                            # 对应现有 _template_unsafe_condition / _TEMPLATE_SAFE_GROUPS
  safe_groups: [route]             # 分组维度在白名单内才允许走模板
  require_route_id: true           # 必须解析出路线 id
fallback: wren                     # 不满足守卫 / 缺槽位时交 Wren，不硬套
sql:
  physical: |
    SELECT ... FROM ai_problem p JOIN basic_facilities_routes r ON ...
    WHERE p.del_flag=0 AND r.id = '<<route_id>>'
    ...                            # SQL 正文：从现有 _build_* 函数原样搬迁，不许改逻辑
  mdl: |
    ...
scope_label: 病害密度 = 病害总数 / 路线里程(公里)   # 给口径卡用
```

硬性要求：

1. **SQL 正文必须从现有 24 个函数逐字搬迁**，本阶段不"顺手优化 SQL"，避免把重构和改逻辑搅在一起。
2. 槽位值仍走现有的实体解析和白名单绑定（`route_id` 用 id 不用名称、编码值中文转 code 等现有规则一条不能丢）。
3. 模板选择依据 `match`（语义 shape/subject/metric），**不允许退回到按用户原话关键词端到端匹配**；关键词只作为"语义层不可用（LLM 挂/超时）时的兜底"，且兜底词表本身也在 `resources/lexicon/trigger_words.yaml`。
4. 注册表同时收录三类确定性能力，统一由一个 `TemplateRegistry` 加载、统一在前端可见：
   - `builtin`：本次外置的 24 个系统内置模板（前端**只读**展示 SQL，作为"照着写"的示例，呼应预置查询维护的需求）；
   - `preset`：用户在前端自建的 `preset_queries.json`（可增删改）；
   - `generic`：`generic.py` 的通用明细/聚合/画像算子（无需 SQL 模板，登记能力说明即可）。

### 5.3 词表 / 语义映射外置（③）

- `resources/lexicon/semantics.yaml`：放 `_SEMANTIC_SHAPES/_SUBJECTS/_GROUP_BY/_METRICS/_DERIVED/_OUTPUT_FIELDS/_ORDER`、`_CONDITION_OPS`。
- `resources/lexicon/metrics.yaml`：放指标键→SQL 表达式、维度、数值字段/操作符、时间桶表达式（`_METRIC_EXPRESSIONS/_DIMENSIONS/_NUMERIC_*`、`_TIME_BUCKET_EXPRS`、各类 `_EXPR/_CASE`）。
- `resources/lexicon/operators.yaml`：放分档粒度、分档聚合、默认档名/别名（`_BUCKET_*`）。
- `resources/lexicon/trigger_words.yaml`：放所有"兜底触发词 / 弃权词 / 图片词 / 对比词 / 领域信号词"（2.3 节 nl2sql 部分 + `templates/keywords.py` 现有内容合并，`keywords.py` 改为从该文件加载的薄壳或删除）。
- `resources/lexicon/result_words.yaml`：放 agent 侧 `_RESULT_LABELS/_METRIC_TERM_MAP/_KNOWN_GROUP_DOMAINS/_REFINABLE_ISSUES` 等。

原则：**这些 YAML 是数据，不是代码**；新增一种说法 / 一个指标 / 一个维度，只改 YAML，不发版、不动 `.py`。

### 5.4 字段元数据统一为单一事实源（④，消除双轨）

- 唯一事实源 = 数据库 `COLUMN_COMMENT`（由 `schema_catalog.py` 拉取并缓存）+ 静态覆盖 `resources/field_meta/code_map_overrides.json`。
- 删除 `nl2sql/schema_meta.py` 里那套硬编码字段表，改为**从 schema_catalog 派生**：
  物理列、中文名、是否图片列、是否经纬度列、编码 code→中文、需要的 JOIN、字段类型，全部来自 catalog / overrides。
- `dictionary.py` 已实现"code→名称从列注释解析"，沿用；`code_map_overrides.json` 只在注释解析不全时做人工兜底。
- 验收红线：以后新增一个有注释的字段，**不改任何 Python、不改词表**，条件过滤 / 明细 select / 编码翻译就能覆盖（这正是"全字段明细 generic_detail"方案要的效果，两份方案在 schema_meta 这一层汇合）。

### 5.5 残留提示词片段归位（①收尾）

§2.2 表中那 12 处 `.py` 内 hint/feedback 文本：

- 属于"固定规则话术"的（`_business_hint`、`_damage_code_hint`、`_length_hint`、`_output_fields_hint`、`_CAPABILITY_HINT`、`_COMPARISON_FEEDBACK`）→ 放 `prompts/fragments/*.md`，用 `prompts.render("fragments/xxx")` 读取，再由 `hints.py` 拼接动态数据。
- 属于"从数据动态算出来"的（`value_samples`、`_sampled_hint`、error memory）→ 文本模板放 fragment，数值仍运行期计算后填槽。
- 纯词表（`COMPARISON_HINT_WORDS` 等）→ 去 `resources/lexicon`，不进 prompts。

## 六、分阶段迁移（每阶段独立可回归，不准攒一个大 PR）

回归命令（每个阶段后都跑，通过率必须持平或上升）：

```
cd backend
.\.venv\Scripts\python.exe run_eval.py        # 90 题
.\.venv\Scripts\python.exe run_hard_eval.py   # 15 题高难度
```

- **阶段 0｜资源加载器与目录骨架**：建 `resources/`、`resource_loader.py`、启动自检；不搬任何东西，先证明加载/热更/缺失回退可用。
- **阶段 1｜词表与语义映射外置（最低风险）**：把 2.3 的常量迁到 `resources/lexicon/*.yaml`，`keywords.py` 与 nl2sql/agent 改为加载 YAML；行为应完全不变（纯数据搬家）。跑回归。
- **阶段 2｜拆 `nl2sql.py` 为包（只搬代码，不碰 SQL）**：按 §4.1 建包、`__init__` re-export，24 个 `_build_*` 原样进 `nl2sql/templates/`，先不声明化。import 全绿、回归全绿后再进入下一步。
- **阶段 3｜SQL 模板声明化**：按 §5.2 把 24 个模板逐个迁成 YAML，**迁一个跑一次相关用例**；含算法的 bucket/generic 只外置参数。完成后内置模板能在前端只读展示。
- **阶段 4｜字段元数据并轨**：按 §5.4 删硬编码双轨、统一走 schema_catalog；重点回归冷门字段、收藏/工单状态/经纬度、problem_type_name 这类曾经踩过的点。
- **阶段 5｜拆 `agent.py` 为包 + 残留 hint 归位**：按 §4.2 拆；12 处 hint 文本进 `prompts/fragments`。
- **阶段 6｜资源目录归并与收尾**：`preset_queries.json / code_map_overrides.json` 归位到 `resources/`，`backend/app/data` 与 `backend/data` 边界理清；更新 `prompts/README.md`，新增 `resources/README.md`（资源清单 + 如何热更 + 如何加模板/词表）。

每个阶段遵循"先搬并保持绿 → 再删旧代码"，不允许在同一阶段既搬家又改判定逻辑。

## 七、验收标准

**结构红线（grep 级）**

- `services/` 下不再出现大段 SQL 字符串拼装（SQL 只存在于 `resources/sql_templates/` 与 Wren MDL）。
- `services/` 下不再出现顶层业务词表元组 / 语义键→SQL 映射字典（统一在 `resources/lexicon/`）。
- 不再存在 `_SPECIAL_FIELDS`、`_LazyFieldTable` 硬编码字段双轨；字段信息一律经 `schema_catalog`。
- 发给 LLM 的中文规则/话术只能来自 `prompts/`，`.py` 里不再有成段中文 prompt。

**文件体量目标**

- `nl2sql/__init__.py` 门面 < 300 行；拆出的每个子模块原则上 < 800 行（`examples.py`、`templates/` 如超限可再分，但不得回到单文件 2000+）。
- `agent/flow.py` 主编排 < 500 行；总结、反思、payload 各自独立。

**行为不退化**

- `run_eval.py`（90 题）与 `run_hard_eval.py`（15 题）通过率与重构前持平或更高；任一阶段下降即停下定位，不允许带病进入下一阶段。
- 前端三条零/低成本路径（看板卡片、快捷查询、预置模板）响应与结果不变。
- 前端"预置查询维护"能看到内置 24 个模板的 SQL（只读），用户自建模板可编辑。

**可维护性自检**

- 新增一个问法同义词：只改 `lexicon/trigger_words.yaml`。
- 新增一个指标/维度：只改 `lexicon/metrics.yaml`（或 schema 注释），不碰 `.py`。
- 新增一个带注释的字段：不改 Python 即可过滤 / 查明细 / 翻译编码。
- 改一句模型话术：只改 `prompts/`，`clear_cache()` 即生效。

## 八、本方案明确不做（边界）

- 不改任何业务判定、不调模型、不动 Wren 引擎与 MDL 定义、不改接口出入参。
- 不做脏数据清洗（area=5000 占位记录、宽高 100/50 等另行处理）。
- bucket 分档、generic 通用算子这类**含中位数/动态边界算法**的，保留 Python 代码，只把参数和词表外置，不追求"一切皆 YAML"。
- 不重写前端，只在现有"预置查询维护"页增加内置模板只读展示（具体前端改动另出小方案）。
