# 自动模板可视化 + 并入快捷查询方案（给 codex）

## 一、问题（已逐行核验，2026-09-22）

现在系统里有三类"确定性模板"，但自动沉淀的那一类在前端基本不可见、也不能手动点查：

| 来源 | 存储 | 匹配/执行 | 前端可见性 |
|---|---|---|---|
| 内置 builtin | `resources/sql_templates/_index.yaml` + nl2sql builder | plan 语义匹配，代码拼 SQL | 管理页只读列表 |
| 人工预置 preset | `data/preset_queries.json`（全局 params 段 + queries[]） | `preset_lib.match_templates` / `preset_lib.bind` | **快捷查询 PresetQueries.vue 一键点查 + 管理页增删改** |
| 自动沉淀 auto | `data/auto_templates.json`（每条内联 params、match、variants、samples、status） | `templatizer.match` / `templatizer.bind`，只在对话确认卡里走 | 仅管理页一张简表 |

核验到的具体缺口：

1. **快捷查询看不到自动模板**：`PresetQueries.vue` 只调 `GET /api/preset-queries`（preset_queries.json），auto 一个都不出现。当前 5 条 mature、enabled=true 的自动模板 `usage` 全是 0，从来没被点过。
2. **自动模板没有"执行"的 HTTP 接口**：后端只有 `POST /templates/auto`（启停）、`DELETE /templates/auto/{id}`、`POST /templates/auto/rebuild`、`POST /templates/auto/{id}/promote`。执行逻辑 `capabilities.execute(kind="auto") → templatizer.find + templatizer.bind + bump_usage` 只在对话链路里能跑到，对话外无法零 LLM 直接出数。
3. **registry 给前端的 auto 是简表**（generic_api.py:126-150）：不含 SQL，params 只回 name/label/type/confirmed_by/首样本值，**没有 options/source/form/op/required**，前端既看不到模板 SQL 样例，也渲染不出参数下拉。
4. **"转正"语义不是进快捷查询**：`templatizer.promote`（templatizer.py:107）只是把 candidate 改成 mature（进对话推荐），不会进 preset_queries.json，也不会出现在快捷查询。
5. **看不出"问答库题目 → 模板"的转化关系**：auto 里其实带了 `variants`（沉淀它的多条问法）、`samples`（原始问题/SQL/取值）、`fingerprint`、`fixed`（写死条件），但管理页没把这些展示出来。

用户的判断是对的：**一条问答一旦 mature 成了自动模板，本质就和确定性模板一样，只是参数不同**。它应当和人工预置一样能在快捷查询里选参数、一键出数，并在维护页能看 SQL、看来源、能管理。

## 二、目标

- mature 且 enabled 的自动模板，在"快捷查询"里和人工预置**同构展示**：卡片 + 参数表单（路线/病害/月份/阈值等，选项连库现查）+ 一键执行，毫秒级、零 LLM。
- 维护页能直观看到"哪些问答库题目已转成模板"：来源问法（variants）、样本、SQL、参数槽、写死条件、状态、使用次数、方言，并能看 SQL、启停、转正、（可选）转成人工预置、删除、重挖。
- candidate 仍只在维护页"待确认"区，不进快捷查询。
- 存储**保持分离**（auto 由重挖维护、preset 人工维护），统一的是前端视图和执行入口，避免重挖覆盖人工模板。

## 三、后端改动

### 3.1 自动模板详情接口（补 SQL 和完整参数）

新增 `GET /api/templates/auto`（管理态 `?with_sql=1` 才回 SQL，对齐 preset 的安全做法），或在现有 registry 上按 `detail=1&with_sql=1` 展开。每条 auto 返回：

```json
{
  "id": "auto_1dfe118d5007203b",
  "title": "宝安大道西乡段 泛油 有多少条",
  "question": "宝安大道西乡段 泛油 有多少条",
  "variants": ["...", "..."],
  "status": "mature",
  "enabled": true,
  "promoted_at": null,
  "usage": 0,
  "dialect": "physical",
  "fingerprint": "...",
  "fixed": {},
  "conditions": [],
  "created_at": "...",
  "params": [
    {"name": "route_id", "label": "路线", "type": "entity", "form": "select",
     "required": true, "column": "routes_id", "table": "ai_problem",
     "options": [{"label": "宝安大道西乡段", "value": "1b0b..."}, {"label": "宝安中心--恒明珠", "value": "d74b..."}]},
    {"name": "damage_type", "label": "病害类型", "type": "entity", "form": "select",
     "required": true, "options": []}
  ],
  "sql": "SELECT ... WHERE r.id = '{route_id}' AND b.problem_type IN ('{damage_type}') ..."
}
```

要点：

- 参数选项直接用 `templatizer.card_slots` / params 里已有的内联 `options`；`source` 型（路线、月份）连库现查，逻辑 templatizer 里已有（card_slots 对 months/routes 的处理），不要在路由里重写。
- 快捷查询态（不带 with_sql）不回 SQL，只回渲染表单所需字段。
- 热加载：沿用 templatizer 基于 mtime/size 的 load，重挖/启停后不必重启。

### 3.2 新增"执行自动模板"接口（关键缺口）

`POST /api/templates/auto/run`，请求体 `{ "id": "auto_xxx", "params": {"route_id": "...", "damage_type": "..."} }`：

1. `templatizer.find(id)`；不存在、`status != "mature"` 或 `enabled=false` → 404/403（candidate 不允许在快捷查询跑）。
2. `templatizer.bind(template, params)` 绑定并做白名单校验（它已按 entity/enum/numeric/int/time/op 各类型校验，值必须命中 options/source 合法域）；绑定失败 → 400 返回原因。**前端永远不能提交 SQL，只传 id + 参数值**（安全红线对齐 `/api/preset-query`）。
3. 按 `dialect` 分流执行：`physical` 走 `sql_engine.execute_sql("mysql", sql)`；`mdl` 走 `wren_engine.compile_mdl_sql` 后执行。执行前再做一次只读校验（只允许 SELECT/WITH），复用 preset/generic 已有的只读约束。
4. `templatizer.bump_usage(id)`，让使用次数反映真实点查（目前只在对话 execute 里加）。
5. 返回结构与 `/api/preset-query` 同构，前端结果表格零改动复用：

```json
{
  "reply": "…（共 N 行，见结果表格）",
  "source": "auto",
  "engine": "auto",
  "template_id": "auto_xxx",
  "sql": "实际执行 SQL",
  "columns": [...],
  "rows": [...],
  "row_count": 12,
  "scope": "口径说明"
}
```

### 3.3 统一"确定性模板目录"读模型（建议）

在 service 层加一个聚合函数（可放 capabilities 或新建 template_catalog），把 builtin/preset/auto/generic 统一成卡片视图给前端：每条带 `source`、`id`、`title/question`、`category`、`status/enabled`、`params 表单描述`、`usage`、`variants`、`runnable`（能否一键点查）。快捷查询和维护页都读它，避免前端自己拼 registry + preset 两份数据。builtin/generic 本阶段仍标只读/按需接入，重点先把 auto 跑通。

### 3.4 candidate 审批与"转人工预置"

- candidate→mature 已有 `promote`，维护页"待确认"区接上即可；丢弃复用现有 DELETE。
- **可选（P1）**：新增 `POST /templates/auto/{id}/promote-to-preset`，把人审过、想纳入人工维护体系（命名/分类/在预置维护页编辑）的 auto 固化进 `preset_queries.json`：
  - 仅支持与 preset 参数体系兼容的槽（entity/time/enum）；含 numeric 自定义阈值、op 槽、或 dialect=mdl 的自动模板，明确返回"含预置不支持的槽/方言，不能转预置，仅可在快捷查询使用"。
  - 写入后给该 auto 标 `promoted_to_preset=true` 并默认停用，避免同一条在两处重复推荐。

## 四、前端改动

### 4.1 快捷查询 `PresetQueries.vue`

- 在现有"分类"下拉之外加"来源"分组或 Tab：**人工预置 / 自动沉淀**（自动沉淀只列 mature & enabled）。
- 自动沉淀卡片与预置卡片同构：
  - 标题用 title；副标题/tooltip 展示来源问法（question + variants，标注"由 N 条已验证问法沉淀"）。
  - 参数表单按 params[].type/form 渲染：entity/enum → 下拉（options 连库现查）、time → 月份选择、numeric/int → 数值输入（限定合法域）、op → 对应控件。
  - 点"查询"调 `POST /templates/auto/run`，结果复用现在 preset 的结果表格/渲染分支。
- 空态：没有 mature 自动模板时，提示"去对话里提问并固化，系统会自动沉淀成模板"。

### 4.2 维护页 `AdminPanel.vue` 自动模板区 → "问答→模板转化台账"

表格/分组呈现：

- 列：标题、来源问法（variants 多条可展开）、状态（mature/candidate）、启用、使用次数、参数槽（label/类型）、写死条件 fixed、方言、创建时间。
- 操作：查看 SQL（with_sql=1，弹窗展示，当仿写样例）、查看样本取值、启用/停用、转正（candidate）、转人工预置（3.4，可选）、删除；顶部保留"重新挖掘"。
- candidate 单独放"待确认"分组，mature 放"已生效（快捷查询可见）"分组，让"哪些题已经变成模板"一目了然。

### 4.3 api.js

新增：`getAutoTemplates(withSql)` → GET /templates/auto；`runAutoTemplate(id, params)` → POST /templates/auto/run；（可选）`promoteAutoToPreset(id)`。现有 setAutoTemplate/deleteAutoTemplate/rebuildAutoTemplates/promoteAutoTemplate 保留。

## 五、安全与不回归

- 存储不合并：auto_templates.json 仍由重挖/approve 异步挖掘维护，preset_queries.json 仍人工维护；统一的是目录视图和执行入口。
- 安全红线与 preset 一致：SQL 不落地前端，前端只传 id + 参数值；值走 options/source 白名单；执行前只读校验（SELECT/WITH）。
- 对话链路 `templatizer.match/execute`、整题闸、确认卡逻辑一律不动；快捷查询是旁路消费。
- 自动模板时间槽当前是月粒度（time_start/time_end），快捷查询表单先按月；日粒度以后再说。
- 重挖产生新 mature 模板后，快捷查询靠热加载自动出现，无需重启。

## 六、验收

1. 快捷查询"自动沉淀"分组列出当前 5 条 mature 模板；选路线/病害/月份后一键出数，结果与对话/Wren 一致（如西乡段泛油计数等已知值），过程零 LLM、亚秒级返回，每次点查 usage +1。
2. 停用或非 mature（candidate）的模板不出现在快捷查询；candidate 只在维护页"待确认"区。
3. 维护页能展开看到每条模板的来源问法（variants）、SQL、参数槽、写死条件、使用次数；查看 SQL/启停/转正/删除/重挖均生效且热加载。
4. `/templates/auto/run` 传越界参数值、缺参数、或试图传自定义 SQL 时被拒绝（400/403）。
5. 重挖新增一条 mature 模板后，不重启即可在快捷查询看到并点查。
6. 人工预置快捷查询、对话里的模板命中与确认卡行为不回归。
