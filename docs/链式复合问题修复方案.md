# 链式复合问题修复方案（TopN答案作为下一个子问题的条件）

> 背景：用户问"哪个星期西乡段泛油数量是最多的？把相关的数据全部列出来"，系统只回答了"第31周最多"，但没有列出第31周的泛油病害明细。这是一个链式复合问题：第一个子问题的答案（第31周）是第二个子问题的输入条件，需要先算 TopN，再用 TopN 的结果作为条件查询明细。
> 核心思路：识别链式复合问题，先执行第一个子问题（TopN），用答案作为条件执行第二个子问题（明细），回答时既说明极值，又列出极值对应的明细数据。
> 生成时间：2026-10-12

---

## 一、问题诊断

### 1.1 案例分析

**用户问法：** "哪个星期西乡段泛油数量是最多的？把相关的数据全部列出来"

**用户的真实意图（链式复合问题）：**
1. **第一个子问题**："哪个星期西乡段泛油数量是最多的？" → 按周分组统计，找出泛油数量最多的那一周 → 答案：第31周（401处）
2. **第二个子问题**：用第一个子问题的答案作为条件 → "2026年第31周西乡段泛油相关的数据全部列出来" → 列出第31周的泛油病害明细（每一条记录：桩号、面积、采集时间等）

**系统的错误回答：**
- 只回答了第一个子问题："第31周最多，401处"
- 没有执行第二个子问题：没有列出第31周的泛油病害明细
- 回答里还说"无法与其他周次进行横向对比"（完全偏离了用户的真实意图）

**正确的回答应该是：**
```
2026年第31周（2026-07-27 ~ 2026-08-02）是西乡段泛油数量最多的星期，共401处。

第31周西乡段泛油病害明细如下（共401条，前10条）：
1. 桩号 K1+200，面积 2.5㎡，采集时间 2026-07-28 10:30
2. 桩号 K1+350，面积 1.8㎡，采集时间 2026-07-28 11:15
...
（完整401条请在结果工作台查看表格）
```

### 1.2 这类问题的共性

**链式复合问题的特征：**

| 特征 | 说明 | 例子 |
|---|---|---|
| 第一个子问题是 TopN/极值查询 | 哪个/什么 最/最多/最少/最高/最低/最早/最晚 | "哪个星期最多"、"哪条路最长"、"面积最大的病害" |
| 第二个子问题依赖第一个子问题的答案 | "把相关的数据列出来"、"列出它的明细"、"分别是多少" | "把相关的数据全部列出来"、"列出它的病害明细" |
| 两个子问题有依赖关系 | 第二个子问题的条件 = 第一个子问题的答案 | 第31周 → 列出第31周的明细 |
| 不是简单的并列复合 | 不是"分别统计A和B"，而是"先算A，再用A算B" | "哪个最多？把它的明细列出来" |

### 1.3 根因分析

#### 根因 1：没有识别链式复合问题

- 语义规划（plan）把整个问题当成了一个 TopN 问题
- 没有识别出这是两个有依赖关系的子问题
- 没有在 plan 里标记 `chain=True` 或 `dependent_subquestions=True`

#### 根因 2：没有执行第二个子问题

- 系统只执行了第一个子问题（TopN）
- 没有用第一个子问题的答案作为条件，执行第二个子问题（明细）
- 导致回答只有 TopN 的结果，没有明细数据

#### 根因 3：回答生成偏离用户意图

- 回答生成的 LLM 看到只有 TopN 的结果（一行）
- 就自己编了"无法与其他周次进行横向对比"的话
- 完全没有理解用户要的是"最多的那一周的明细"

## 二、解决方案

### 2.1 核心思路

**识别链式复合问题，分两步执行：**

1. **第一步**：执行第一个子问题（TopN/极值查询），得到答案（如第31周）
2. **第二步**：用第一步的答案作为条件，执行第二个子问题（明细查询），得到明细数据
3. **回答**：既说明极值（哪一周最多），又列出极值对应的明细数据

### 2.2 阶段 1：语义规划识别链式复合问题

**文件：** `prompts/query_semantic.md`、`backend/app/services/nl2sql.py`

**改动：**

1. **在语义规划提示词中增加链式复合问题识别**：
   - 当用户问法同时包含：
     - 第一个子问题："哪个/什么 最/最多/最少/最高/最低/最早/最晚"
     - 第二个子问题："把相关的数据列出来/列出它的明细/分别是多少/看看它的情况"
   - 标记为链式复合问题
   - 在 plan 里增加：
     - `chain=True`：是否是链式复合问题
     - `chain_first_subject`：第一个子问题的主体（如"week"）
     - `chain_first_metric`：第一个子问题的指标（如"count"）
     - `chain_second_type`：第二个子问题的类型（如"detail"、"list"）
     - `chain_second_scope`：第二个子问题的范围（如"all"、"top_n"）

2. **链式复合问题的例子**：
   - "哪个星期西乡段泛油数量是最多的？把相关的数据全部列出来"
     - `chain=True`, `chain_first_subject="week"`, `chain_first_metric="count"`, `chain_second_type="detail"`, `chain_second_scope="all"`
   - "哪条路病害最多？列出它的病害明细"
     - `chain=True`, `chain_first_subject="route"`, `chain_first_metric="count"`, `chain_second_type="detail"`
   - "面积最大的病害是哪条？把它的详细信息列出来"
     - `chain=True`, `chain_first_subject="disease"`, `chain_first_metric="max_area"`, `chain_second_type="detail"`

### 2.3 阶段 2：分两步执行

**文件：** `backend/app/services/agent.py`

**改动：**

1. **当 `chain=True` 时，分两步执行**：

   **第一步：执行第一个子问题（TopN）**
   - 按第一个子问题的主体分组统计（如按周分组统计泛油数量）
   - 找出极值（最多的那一周）
   - 得到答案：`{ "week": "202631", "count": 401, "date_range": "2026-07-27 ~ 2026-08-02" }`

   **第二步：用第一步的答案作为条件，执行第二个子问题（明细）**
   - 把第一步的答案转换成 SQL 条件（如 `YEARWEEK(collection_time, 1) = '202631'`）
   - 执行明细查询（列出第31周的泛油病害明细）
   - 得到明细数据：`[{ "pile_number": "K1+200", "area": 2.5, "collection_time": "..." }, ...]`

2. **第一步答案到第二步条件的转换逻辑**：
   - 按周 TopN → `YEARWEEK(collection_time, 1) = '{week}'`
   - 按月 TopN → `DATE_FORMAT(collection_time, '%Y-%m') = '{month}'`
   - 按天 TopN → `DATE(collection_time) = '{date}'`
   - 按路线 TopN → `routes_id = '{route_id}'`
   - 按病害类型 TopN → `damage_type = '{damage_type}'`
   - 通用：根据第一个子问题的主体和答案，自动生成对应的 SQL 条件

3. **第二步明细查询的字段选择**：
   - 默认列出该表的主要字段（如病害表：桩号、面积、采集时间、病害类型、置信度等）
   - 如果用户点名了具体字段，按用户点名的字段列出
   - 明细数量超过 500 条时，只返回前 500 条，提示"完整数据请在结果工作台查看"

### 2.4 阶段 3：回答生成标准化

**文件：** `backend/app/services/agent.py`、回答生成提示词

**改动：**

1. **链式复合问题的回答模板**：
   ```
   {极值说明}：{第一个子问题的答案}（{指标值}）
   
   {极值对应的明细}：
   {明细数据，前10条}
   （完整{总数}条请在结果工作台查看表格）
   ```

2. **例子**：
   ```
   2026年第31周（2026-07-27 ~ 2026-08-02）是西乡段泛油数量最多的星期，共401处。
   
   第31周西乡段泛油病害明细如下（共401条，前10条）：
   1. 桩号 K1+200，面积 2.5㎡，采集时间 2026-07-28 10:30
   2. 桩号 K1+350，面积 1.8㎡，采集时间 2026-07-28 11:15
   ...
   （完整401条请在结果工作台查看表格）
   ```

3. **回答生成提示词中增加链式复合问题的回答规范**：
   - 必须先说明极值（第一个子问题的答案）
   - 然后列出极值对应的明细数据（第二个子问题的结果）
   - 不允许说"无法对比"或其他偏离用户意图的话
   - 明细超过 10 条时，列出前 10 条，提示"完整数据请在结果工作台查看"

### 2.5 阶段 4：弹卡确认

**文件：** `backend/app/services/agent.py`、前端

**改动：**

1. **链式复合问题也需要弹卡确认**：
   - 卡片上显示：
     - 第一个子问题：按周分组统计泛油数量，找出最多的那一周
     - 第二个子问题：列出最多的那一周的泛油病害明细
   - 用户确认后才执行

2. **弹卡内容**：
   - 查询口径：链式复合问题（先算 TopN，再用 TopN 结果查明细）
   - 涉及的表：ai_problem、basic_facilities_routes 等
   - 第一步：按周分组统计泛油数量
   - 第二步：列出最多的那一周的泛油病害明细
   - SQL 预览：可以展开查看两步的 SQL

## 五、扩展：其他链式复合问题

这类修复不仅适用于"哪个星期最多"，还适用于所有链式复合问题：

| 链式复合问题类型 | 例子 | 第一步（TopN） | 第二步（明细） |
|---|---|---|---|
| 按时间 + TopN + 明细 | "哪个星期泛油最多？把相关的数据列出来" | 按周分组统计，找最多的周 | 列出那一周的泛油病害明细 |
| 按路线 + TopN + 明细 | "哪条路病害最多？列出它的病害明细" | 按路分组统计，找最多的路 | 列出那条路的病害明细 |
| 按病害类型 + TopN + 明细 | "哪种病害最多？列出它的明细" | 按病害类型分组统计，找最多的类型 | 列出那种类型的病害明细 |
| 按指标 + TopN + 明细 | "面积最大的病害是哪条？把它的详细信息列出来" | 找面积最大的病害 | 列出那条病害的详细信息 |
| 按巡检 + TopN + 明细 | "哪次巡检发现的病害最多？列出那次巡检的所有病害" | 按巡检分组统计，找最多的巡检 | 列出那次巡检的所有病害明细 |

**核心原则：只要用户问了"哪个最/最多" + "把它/相关的数据列出来"，就是链式复合问题，需要先算 TopN，再用 TopN 的结果查明细。**

## 六、与并列复合问题的区别

| 类型 | 特征 | 例子 | 处理方式 |
|---|---|---|---|
| **链式复合问题** | 第二个子问题依赖第一个子问题的答案 | "哪个星期最多？把它的明细列出来" | 先算 TopN，再用 TopN 结果查明细 |
| **并列复合问题** | 两个子问题独立，没有依赖关系 | "西乡段和恒明珠段分别有多少处病害" | 分别执行两个子问题，结果合并 |
| **简单 TopN 问题** | 只有 TopN，没有明细需求 | "哪个星期泛油最多" | 只执行 TopN，返回极值 |
| **简单明细问题** | 只有明细，没有 TopN | "列出西乡段7月的泛油病害明细" | 只执行明细，返回明细数据 |

**识别关键：**
- 链式复合问题：第二个子问题的主语是"它/相关/那个"（指代第一个子问题的答案）
- 并列复合问题：两个子问题有明确的、独立的主语（如"西乡段和恒明珠段"）

## 七、风险与应对

| 风险 | 应对 |
|---|---|
| 语义规划识别不准，把简单 TopN 问题误判为链式复合问题 | 收集 bad case，持续优化提示词；可以先用关键词规则兜底（"把它/相关的数据列出来"等词） |
| 第一步答案到第二步条件的转换逻辑覆盖不全 | 先支持常见类型（按周/月/天/路线/病害类型），遇到不支持的类型退回 Wren 或提示用户 |
| 第二步明细查询的字段选择不准 | 默认列出该表的主要字段；如果用户点名了具体字段，按用户点名的字段列出 |
| 链式复合问题执行时间较长（两步查询） | 可以并行执行第一步和"假设性"的第二步，但推荐串行执行（第二步依赖第一步的答案） |
| 弹卡确认增加用户操作 | 高置信度的链式复合问题可以直接执行（但仍然需要用户确认）；或者在卡片上明确显示两步的查询口径 |
