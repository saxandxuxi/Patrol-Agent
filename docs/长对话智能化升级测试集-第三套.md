# 长对话智能化升级测试集-第三套（全库视角版）

> 第三套测试集，和前两套不一样。
> 从全库/全局视角出发，然后下钻到具体路线/类型/时间，做管理决策类的分析。
> 覆盖所有有数据的表：病害、路线台账、路段台账、病害类型字典。

---

## 长对话9：全库路线概览 → 下钻最差路线 → 原因分析 → 养护建议

**测试点：从全库角度下钻、多路线对比、原因分析、管理建议**

```
R1：我们管的所有路线里，病害数量最多的前3条是哪几条？各有多少处？

R2：这3条里，病害密度最高的是哪条？（要算密度，不是只看总数）

R3：它比其他两条高这么多，是因为路长所以病害多，还是真的密度高？

R4：这条密度最高的路，主要是什么类型的病害？是路面病害还是沿线设施病害？

R5：如果下半年要安排一次专项养护，优先投这条路的哪个路段？为什么？
```

**测试目标：**
- R2：从"总数"到"密度"，需要做后置计算（数量÷长度）
- R3：二选一的原因分析（路长 vs 密度高）
- R4：从路线 → 下钻到病害类型大类（路面/沿线设施）
- R5：从全库对比 → 下钻到具体路段 → 养护建议

---

## 长对话10：病害类型全局分布 → 下钻某类型 → 为什么多 → 预防建议

**测试点：从病害类型字典角度出发、类型分布、占比分析、原因分析**

```
R1：全库一共有多少种病害类型？其中路面病害有多少种？沿线设施病害有多少种？

R2：实际出现过的病害里，数量最多的前3种是哪几种？各有多少处？

R3：数量最多的那种病害，总面积有多大？平均每处多大？

R4：为什么这种病害会这么多？是路面材料问题还是交通荷载问题？

R5：针对这种病害，有什么预防措施？养护规范里有什么要求？
```

**测试目标：**
- R1：从字典表角度出发（一共有多少种），不是从实际数据角度
- R2：从字典 → 实际数据，下钻到真实出现的类型
- R3：从数量 → 下钻到面积、平均规模
- R4：数据 + 原因分析
- R5：数据 + 知识问答 + 建议

## 长对话11：月度病害趋势 → 找异常月份 → 为什么 → 管控建议

**测试点：时间维度趋势分析、找异常、原因分析、管控建议**

```
R1：7月份全库一共记录了多少处病害？平均每天多少处？

R2：7月份里，哪几天的病害数量明显比其他天多？（找异常高峰）

R3：数量最多的那一天，主要是什么类型的病害？集中在哪条路？

R4：为什么那天突然冒出来这么多？是那天巡检特别仔细，还是真的出了大面积病害？

R5：针对这种"某天集中爆发"的情况，巡检质量管控上应该注意什么？
```

**测试目标：**
- R1：从月度 → 日均，后置计算
- R2：找异常值（比其他天多很多的）
- R3：从天数 → 下钻到病害类型、路线
- R4：二选一原因分析（巡检仔细 vs 真的出了大面积病害）
- R5：数据 + 知识 + 管理建议

## 长对话12：管养单位对比 → 哪个压力大 → 为什么 → 资源调配

**测试点：按管养单位分组对比、找压力最大的、原因分析、资源调配建议**

```
R1：全库的病害，按管养单位分，哪个单位管的病害最多？有多少处？

R2：这个单位管的路总长是多少公里？它的病害密度是多少？

R3：它的密度比其他单位高多少？主要是什么类型的病害？

R4：为什么这个单位管的路病害这么多？是路本身差，还是巡检频率太高？

R5：如果要调配养护人员，是不是应该多派点人去这个单位？为什么？
```

**测试目标：**
- R1：按管养单位分组统计
- R2：从数量 → 密度，后置计算
- R3：从整体密度 → 下钻到病害类型
- R4：二选一原因分析（路差 vs 巡检勤）
- R5：管理决策建议

## 检查点（每一轮都要检查）

| 检查项 | 为什么要查 |
|--------|-----------|
| 下钻有没有断 | 从全库 → 单条路线，有没有正确继承条件 |
| 后置计算对不对 | 密度=数量÷长度，日均=总数÷天数 |
| 分组维度对不对 | 按管养单位/按类型/按天分组，有没有漏组 |
| 结论有没有下 | 用户要分析/判断的，是不是只列了数据 |
| 原因分析有没有 | 二选一的问题，有没有给结论+理由 |
| 建议有没有落地 | 不要说空话，要说具体怎么做 |
