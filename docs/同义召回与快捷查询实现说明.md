# 同义召回 + 自动模板并入快捷查询（2026-09-22 实现）

配套设计：`docs/自动模板可视化与快捷查询并入方案.md`（那份是改造方案，这份是**已落地的实现**与
召回/排序机制说明）。相关 bug 背景见 `docs/推荐模板链路Bug清单.md`。

## 一、同义召回怎么做（不建同义词表、不靠关键词）

一句话：**"换个说法"的召回交给示例库的向量召回，落到模板靠"身份对齐"，口径判定靠结构。**

数据流（`capabilities._synonym_template_candidates`）：

1. **召回**：用户问题 → `direct_match.gate()`（示例库向量召回 + 便宜模型严格同问判定）。
   这一段本来就有，专门承接"同义不同字"，不需要维护任何同义词/触发词表。
   它返回的是"这条问法"（已验证问法）+ 相似度分，而不是 SQL 片段。
2. **身份对齐**：`templatizer.find_by_question(question)` 在自动模板库里按
   `question / variants / samples[].question` 找"这条问法沉淀出的模板"。
   归一化复用 `nl2sql._example_key`（与全系统"是不是同一句"的判定同一套规则）。
3. **口径重绑**：`templatizer.card_for_template(template, plan)` 用**本次问题**的语义计划
   重新绑槽（而不是照抄示例里的值）：结构（shape/主体/分组/指标）不符、固定值冲突、
   计划里有条件模板表达不了 —— 一律不摆卡。
4. **展示**：摆的是**模板卡**（参数可改、0 次大模型），同一条问法不再重复摆"原始示例卡"。

为什么这样比"同义词表"稳：召回的宽松度由向量+打分控制（能容忍改写），
而**能不能用**由结构判定控制（不会因为"字面像"就把口径不同的模板推出去）。

## 二、最相关怎么排（可解释的确定性打分）

同一批候选按 `(tier, -score)` 排：

| 维度 | 取值 | 说明 |
|---|---|---|
| tier | 模板 0 / 相似问法 1 / 通用算子·代码模板 2 | 确定性模板优先，通用算子垫底 |
| 结构契合 | 命中即通过硬门槛（shape/主体/分组/指标/条件覆盖） | 不参与打分，是**准入**：宁可不匹配也不错匹配 |
| 槽位完备度 | `4.0 + 0.6 × 已填槽/总槽 − 0.15 × 缺槽数` | 槽越全越靠前，缺槽标"待补" |
| 同义召回 | `+ 0.4 × 召回相似度` | 由示例库向量/打分给出，越像越靠前 |
| 历史使用 | `+ min(usage,10)/100` | 被真实用过、验证过的模板略优先 |
| 固定值冲突 | 命中即淘汰 | 模板写死"上行"、问题问"下行"直接不摆卡 |

确认卡上第一条标 `recommended`；候选按 `(kind, id)` 去重，避免同一口径被
"结构匹配"和"同义召回"两条入口各摆一张。

## 三、RAGFlow 里的问答→模板，并入快捷查询

挖掘侧不变（RAGFlow 示例库 / 本地示例池 → `templatizer.mine_all` → `auto_templates.json`），
新增的是**消费入口**：

| 接口 | 用途 |
|---|---|
| `GET /api/templates/auto?with_sql=0&runnable_only=1` | 快捷查询用清单：只回 mature + 启用，默认不回 SQL；`runnable_only=0` 给维护页看全部（含 candidate） |
| `POST /api/templates/auto/run` | 一键出数：前端只传 `{id, params}`，后端 `bind` 绑定 + 只读校验 + 执行 + `usage+1` |

参数描述统一由 `templatizer.form_params()` 生成（路线/月份/名次连库现查选项；
数值阈值返回空 options，前端渲染输入框），与确认卡共用同一套 `_options` 逻辑。

前端（`frontend/src/components/PresetQueries.vue`）：标准模板页签加"来源"切换
（人工预置 / 自动沉淀），自动沉淀卡片同构渲染，数值槽用输入框，结果表格复用原渲染分支；
`api.js` 增加 `autoTemplates()` / `runAutoTemplate()`。

## 四、验证（2026-09-22 16:5x）

- 回归：线上 34 条 mature 模板自匹配全部命中（44/44 断言）；写死"上行"的模板问"下行"
  不命中、问"没提方向"也不命中。
- 接口：清单 34 条可点查 / 35 条含 candidate；`with_sql=1` 才回 SQL；
  用样本取值调 `/templates/auto/run` 得到 `西乡段7月30日有多少处泛油？：185`，`usage` +1；
  缺参数、注入 `'; DROP TABLE ...` 都被 400 拒绝。
- 同义召回：`find_by_question` 命中来源问法、不误命中无关句；合成召回命中时给出的卡片是
  `kind=auto`、理由写明"同义问法召回（「…」已沉淀成模板）"。
- 前端：`vite build` 通过（2173 modules）。

## 四之二、表单可读性：从"看不懂要填什么"到"有默认值、说人话"

第一版把自动模板接进快捷查询后暴露的问题：参数标签是列名/列注释（`路线id`、`problem_type`、
`解析桩号米数`），起止两个时间槽同名（都叫"病害采集时间"），时间只能选年月，
桩号/阈值类槽没有默认值 —— 用户不知道要回答什么。

修法（都在 `templatizer`，快捷查询与对话确认卡共用同一份参数描述）：

| 问题 | 现在 |
|---|---|
| 标签是列名/列注释 | `_param_label()` 按角色给词：`route_id→路线`、`damage_type→病害类型`、`pile_distance→桩号（米）`；列注释只在没有角色词时兜底 |
| 起止时间同名 | 时间槽带角色后缀：`病害采集时间·从` / `·到`（`_low/_high` 同理给"下限/上限"） |
| 只有年月、填不了"7月30日" | 时间槽改成**按天**：`form_params` 回 `value`（闭区间日期）+ `hint`，前端用 `el-date-picker(type=date)` |
| 不知道要填什么 | `_param_default()` 用**这条模板验证过的那次取值**当默认值（桩号 1802/2801、置信度 0.5…），`_param_hint()` 每个槽给一句说明（"K1+802 填 1802"） |
| 日期边界算错 | `_bind_time()`：终点按闭区间补边界——比较符 `<` 补到次日 00:00:00、`<=` 补到当天 23:59:59；起点补 00:00:00。只给月份仍按整月（老行为不变） |

实测（`auto_ad15c8103f48c2a7`「西乡段7月30日有多少处泛油？」）：

```
路线 = 宝安大道西乡段        病害类型 = 泛油
病害采集时间·从 = 2026-07-30   病害采集时间·到 = 2026-07-30
→ 运行：185（与对话/原样本一致）
```

三种输入都对：表单发日期（7/30~7/30）→ `>= '2026-07-30 00:00:00' AND < '2026-07-31 00:00:00'`；
调用方发原样本整天时间 → 同上；只给月份 → 整月边界。全量 34 条可点查模板：**没有缺默认值的槽，
也没有残留技术标签**。

## 五、还没做（按优先级）

1. `promote-to-preset`：把审核过的 auto 模板固化进 `preset_queries.json`（含 numeric/op 槽的要明确拒绝）。
2. 维护页 `AdminPanel.vue` 按"已生效 / 待确认"分组，展示 variants / SQL / fixed / 使用次数。
3. 自动模板时间槽目前是月粒度（time_start/time_end），日粒度要等槽位带上 `granularity`。
4. 同义召回目前只在"结构匹配没有出模板卡"时才跑（省掉 RAGFlow 召回的延迟）；
   若要做"结构命中也补充同义候选"，需要先给召回加缓存。

## 六、管理页：模板刷新（增量）/ 全量重挖 / 双集同步

| 按钮 | 接口 | 语义 |
|---|---|---|
| 模板刷新（只挖新问答） | `POST /api/templates/auto/refresh` | **增量**：只处理"已挖掘台账"里没有的问答对；已挖过的跳过、已有模板原样保留（不重算、不降级、`promoted_at` 不丢） |
| 全量重挖 | `POST /api/templates/auto/rebuild` | `force`：清空台账，按最新规则把示例库每条问答重算一遍（挖掘器改进后用它重试失败的那批） |
| 同步问题索引集 | `POST /api/examples/question-index/sync` | 对账 RAGFlow「SQL问题索引」集：补缺失的问题、清掉问答示例集里已经没有的孤儿 |

**已挖掘台账**存在 `auto_templates.json` 的 `mined` 字段里，键是问答对的文档名，值是
`{template: 模板id 或 "", reason, at}`——成功的记"成了哪条模板"，失败的记"什么原因没成"。
所以：

- 刷新可以放心频繁点，不会重复跑旧的（实测第二次点：`pending=0`，秒回）；
- 失败的不会被反复重试（想重试就点"全量重挖"，或等挖掘器修好后全量来一遍）；
- 第一次点刷新会把台账建起来，等于跑一遍全量（本例 65 条问答 ≈ 3 分钟，之后新问答都是秒级）。

**自动同步**：对话里点"答对了/固化"（approve）与「管理 → 示例库同步 → 立即同步」之后，
都会在后台跑一次**增量**挖掘；新成熟的模板靠注册表 mtime 热加载 + 快捷查询页 `onActivated`
重新拉取，自动出现在「快捷查询 → 来源：自动沉淀」里，不需要重启、不需要额外操作。

> 说明：设置里的「自动挖掘」开关只管**自动触发**（approve/同步那两条路）。管理页的
> 「模板刷新 / 全量重挖」是人工按钮，不受该开关限制。

### 两个 RAGFlow 数据集同进同出

| 数据集 | 内容 | 用途 |
|---|---|---|
| 《SQL问答示例》 | 问题 + 查询意图 JSON + 归一化 SQL + 解读 | few-shot / 重放 / 挖模板的事实源 |
| 《SQL问题索引》 | **只有问题正文**（一个字符都不多） | 相似问法向量召回（混进 JSON/SQL 会把问题向量拉平） |

- 新增（approve / 固化）：`save_successful_pair` 两个集都写；
  **去重命中**时用 `upsert_question_index(force=False)` 补一次索引（幂等：已在索引里就不重传）——
  修掉"老条目只在问答示例集、问题索引集缺这条"的对不齐。
- 删除（purge）：两个集的同名文档**一起删**，否则索引里留下孤儿，相似问法召回会打到已经删掉的问题。
- 对账：`backfill_question_index()` 会补齐缺失、清理孤儿；后端启动时跑一次，管理页按钮可随时手动跑。
