# 长对话上下文补全重构方案（v2）

> 核心思路：不是靠枚举示例覆盖所有场景，而是让 LLM 理解"条件继承/替换"的逻辑。
> 示例永远列不完，逻辑通了，什么场景都能补对。

---

## 一、核心逻辑：三步法

```
第一步：拆上一轮的条件
   把上一轮用户问题里的条件拆出来：
   - 路线/路段
   - 时间范围
   - 病害类型
   - 过滤条件（面积/置信度/图片）
   - 查询对象（病害数/图片/GPS轨迹）

第二步：判断当前这句话是哪种操作
   - 【替换】用户在纠正/修改某个条件 → 替换掉那个条件，其他继承
   - 【继承】用户追问其他指标/其他对象 → 继承所有条件，只换指标/对象
   - 【新增】用户加新的过滤条件 → 继承所有旧条件，加上新条件
   - 【比较】用户问"多了多少/少了多少/加起来" → 需要把前两轮的答案数字带进来
   - 【新话题】完全不相关 → 不继承，直接输出原话

第三步：拼成完整问题
   把替换/继承/新增后的条件，拼成一句完整独立的问题。
```

---

## 二、答案数字什么时候才有用？

**绝大多数时候，上一轮的答案数字没用。**

比如：
- R1: 西乡段有多少处泛油？ → 534
- R2: 它的平均面积呢？
  - 534 这个数字没用
  - 有用的是条件：西乡段 + 泛油

**只有一种情况答案数字有用：用户问比较/差值。**

比如：
- R1: 恒明珠6月泛油多少？ → 143
- R2: 7月呢？ → 259
- R3: 多了多少？
  - 这时候 143 和 259 才有用
  - 补全成：恒明珠6月泛油143处，7月259处，6月比7月少了多少处？

## 三、新的 context_rewrite.md 提示词

```markdown
[system]
你是道路巡检智能体的多轮对话上下文补全器。
把用户这句带指代词/省略/纠正的短问句，补成一句完整独立的问题。
只输出补全后的问题，不要解释。

核心原则：**先拆上一轮的条件，再判断当前这句话是要替换、继承、还是新增条件。**

### 第一步：拆上一轮的条件

从上一轮用户问题里，拆出这些条件：
- 路线/路段（比如：宝安大道西乡段）
- 时间范围（比如：7月、7月30日）
- 病害类型（比如：泛油、裂缝）
- 过滤条件（比如：面积>5、置信度<0.7、有图片）
- 查询对象（比如：病害数量、病害图片、GPS轨迹）

### 第二步：判断操作类型

用户这句话属于哪种操作：

1. 【替换条件】用户在纠正/修改某个条件
   - 特征词：错了、不对、不是、我说的是、应该是、改成
   - 做法：把对应的旧条件替换成新的，其他条件全部继承

2. 【继承条件，换指标】用户追问另一个指标
   - 特征词：呢？、的平均面积呢？、最大的有多大？、是什么类型？
   - 做法：所有旧条件全部继承，只换指标

3. 【继承条件，换对象】用户追问另一种数据
   - 特征词：照片呢？、GPS轨迹呢？、也一起看看、还有呢？
   - 做法：所有旧过滤条件全部继承，只换查询对象

4. 【继承条件，加新过滤】用户在前面基础上缩小范围
   - 特征词：其中XX的？、这里面XX的、XX的有多少？
   - 做法：所有旧条件全部继承，加上新的过滤条件

5. 【比较差值】用户问两个结果的差异
   - 特征词：多了多少？、少了多少？、差多少？、加起来？
   - 做法：把前两轮的答案数字带进来，说清楚比较的两个对象

6. 【新话题】完全不相关
   - 做法：不继承任何条件，直接输出原话

### 第三步：拼成完整问题

把处理后的条件，拼成一句完整独立的中文问题。
不要加"根据上一轮"之类的说明。
```

## 四、示例（不是让你背，是帮你理解逻辑）

### 示例1：替换条件

**对话：**
```
R1: 西乡段有多少处泛油？ → 534处
R2: 不是，我是说未知类型的。
```

**拆解：**
- R1的条件：路线=西乡段，病害类型=泛油
- R2说"不是未知类型" → 替换病害类型条件
- 答案数字534没用，不用带进来

**补全后：** 西乡段有多少处未知类型的病害？

---

### 示例2：继承条件，换指标

**对话：**
```
R1: 西乡段泛油有多少处？ → 534处
R2: 那它的平均面积呢？
```

**拆解：**
- R1的条件：路线=西乡段，病害类型=泛油
- R2问平均面积 → 换指标，其他条件继承
- 答案数字534没用

**补全后：** 西乡段泛油的平均面积是多少？

---

### 示例3：继承条件，换查询对象

**对话：**
```
R1: 西乡段7月30日有多少处泛油？ → 185处
R2: 能看看这些病害的照片吗？
R3: GPS轨迹也一起看？
```

**拆解：**
- R1的条件：路线=西乡段，时间=7月30日，病害类型=泛油
- R2问照片 → 换查询对象（病害→照片），所有过滤条件继承
- R3问GPS轨迹 → 再换查询对象（照片→GPS轨迹），所有过滤条件还是继承

**补全后：**
- R2：西乡段7月30日的泛油病害，有哪些照片？
- R3：西乡段7月30日的泛油病害，对应的GPS轨迹有哪些？

---

### 示例4：继承条件，加新过滤（缩小范围）

**对话：**
```
R1: 全库泛油里面积正好7.52㎡的有几处？ → 17处
R2: 其中西乡段的有多少？
```

**拆解：**
- R1的条件：病害类型=泛油，面积=7.52㎡
- R2说"其中西乡段的" → 加路线过滤条件，其他继承

**补全后：** 全库泛油里面积正好7.52㎡的病害中，西乡段的有多少处？

---

### 示例5：比较差值（这时候答案数字才有用）

**对话：**
```
R1: 恒明珠6月有多少处泛油？ → 143处
R2: 7月呢？ → 259处
R3: 多了多少？
```

**拆解：**
- R1的条件：路线=恒明珠，病害类型=泛油，时间=6月
- R2换时间条件 → 7月泛油259处
- R3问"多了多少" → 这时候答案数字才有用
- 两个比较对象：6月143处 vs 7月259处

**补全后：** 恒明珠6月泛油143处，7月259处，7月比6月多了多少处？

---

### 示例6：指代Top结果

**对话：**
```
R1: 全库置信度最高的病害是哪条？ → 最高0.9457，共20条并列
R2: 它是什么类型的病害？
```

**拆解：**
- R1的条件：全库，按置信度排Top1
- R2问"它是什么类型" → 换指标（位置→类型），其他条件继承

**补全后：** 全库置信度最高的病害是什么类型的病害？

## 五、代码逻辑改什么

### 5.1 补全输入要带完整对话历史

**现在的输入：** 最近几轮的用户问题

**改成：** 最近几轮的完整对话（用户问的 + 系统答的）

**为什么：** LLM 需要知道上一轮的答案是什么，才能判断：
- 哪些答案数字要带进来（比较类）
- 哪些条件要继承（路线/时间/病害类型）

---

### 5.2 废弃对话状态池

**现在的问题：** 两套机制（规则状态池 + LLM补全），容易冲突。

**改法：** 全部走 LLM 补全，废弃：
- subject_pool
- pool_intent
- _subject_field_answer
- _pool_answer

**好处：** 一套机制，不会冲突，新场景只要改提示词。

---

### 5.3 补全后走完整流程

**现在的问题：** 有些快捷路径跳过了完整流程。

**改法：** 补全之后，就当成一个新的独立问题，走完整流程：
1. 意图分类
2. 拆分器判断
3. build_query_plan
4. 模板/Wren 生成 SQL
5. 执行
6. 结果解读

不要走任何快捷路径。
