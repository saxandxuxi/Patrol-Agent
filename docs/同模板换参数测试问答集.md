# 同模板换参数测试问答集

用途：检验"自动模板（L1）"在**换参数、换说法、复合条件、长对话追问**下，能不能把问题推荐到同一条模板，并把槽位填对。

测试方法：在对话页逐题发送，观察系统弹出的"模板/示例确认卡"：

1. 有没有推荐到模板（而不是直接走 Wren 重新写 SQL）。
2. 推荐的是不是本表"期望命中模板"那一条。
3. 确认卡里识别出的槽位值，和本表"期望槽值"是否一致。
4. 复合题如果缺槽，确认卡是否把缺失槽列出来让我补（而不是直接放弃模板）。

铁律：模板用不用、用哪条，最终由我在确认卡点确认；系统只负责推荐和预填，不准自动拍板。

## 现状基线（2026-09-21 连库实测，改造前）

| 类型 | 题数 | 自动模板命中 | 说明 |
|---|---|---|---|
| 简单换参数（路线/月份/类型） | 8 | 8 | 计数、分布、明细都能复用同一条模板 |

# 第二部分　复合模板族（改造目标，现状基本不命中）

这部分每条都同时带多个过滤条件，且常带分组、排序、TopN。单条模板能被自动挖出来，但换参数后运行期推荐不到，原因逐题标注。

## 族 F：路线 + 方向 + 月份 + 面积阈值 + 按类型分组 + TopN

基准问法（用于先沉淀模板）：

> F0：西乡段7月份上行方向、面积大于5平方米的病害，按病害类型统计处数，取前5种。

期望模板槽位：路线、上下行(up_or_down)、月份(time_start/time_end)、面积阈值(area+op)、分组=病害类型、排序=count 降序、top_n=5。

换参数变体（用于检验能否复用 F0 模板）：

| 编号 | 问法 | 期望槽值 | 现状不命中原因 |
|---|---|---|---|
| F1 | 恒明珠段6月下行方向面积超过10平方米的病害，按类型排个前3 | 路线=恒明珠，方向=下行(2)，月份=2026-06，面积>10，top_n=3 | plan 抽不到 up_or_down 过滤；面积阈值、top_n 也未必齐 |
| F2 | 西乡段7月上行，面积5平以上的，哪几种病害最多，前5 | 同 F0 | 同上 |
| F3 | 把 F1 的下行改成上行看看 | 方向=上行(1)，其余继承 F1（长对话） | 追问改槽，方向仍抽不到 |
| F4 | 西乡段7月上行大面积（>5㎡）病害类型分布 | 同 F0，不要 top_n | 措辞变化导致 metrics 在 count/total_area 间摇摆 |
| F5 | 恒明珠7月下行，面积大于10平的，每种类型多少处、总面积多少 | 同 F1，metrics 需同时含 count 和 total_area | 模板自画像只记了 count，漏了 SUM(area) |

## 族 G：含 AI 置信度（JSON 字段）阈值

基准问法：

> G0：西乡段面积大于5平方米、AI识别置信度低于0.7的病害有多少处。

槽位：路线、面积>5、confidence<0.7（confidence 是 `pic_position` JSON 里的字段，物理写法是 `CAST(JSON_UNQUOTE(JSON_EXTRACT(pic_position,'$.confidence')) AS DECIMAL(10,6))`）。

| 编号 | 问法 | 期望槽值 | 现状问题 |
|---|---|---|---|
| G1 | 西乡段面积>5、置信度低于0.7、且没有采集图片的病害，列出桩号、面积、置信度 | 在 G0 上加 has_image=否 | 规则挖槽遇到 JSON/函数包裹列，整条交给 LLM 兜底；"没图"无过滤通道 |
| G2 | 恒明珠置信度高于0.9的病害有多少 | 路线=恒明珠，confidence>0.9 | JSON 列沉淀不稳 |
| G3 | 西乡段置信度在0.4到0.6之间的泛油有多少处 | 路线=西乡段，类型=泛油，confidence between | between + JSON 组合 |

## 族 H：多对象对比 / 同环比（comparison、multi_route）

现状：`templatizer.match` 遇到 plan.comparison 或 multi_route 直接返回空，不进自动模板。这类整题不强求模板化，但**拆出来的每个单对象子问题应该能命中模板**。

| 编号 | 问法 | 期望处理 |
|---|---|---|
| H1 | 西乡段和恒明珠7月各发现多少处泛油 | 拆成两个 count(路线+类型+月份) 子问题，各自命中族A类模板，再拼对比 |
| H2 | 西乡段7月比6月泛油多了多少处 | 两个 count(月份不同) 子问题各命中，再做差 |
| H3 | 两条路哪条病害密度高 | 子问题：各路线总数、各路线长度（长度走模板/查询），密度后置计算 |
| H4 | 西乡段泛油占全部病害的比例 | 两个 count（带类型 / 不带类型）子问题，再相除 |

## 族 I：枚举 / 布尔冷门字段条件

这些字段在表里一直存在，但运行期 plan 基本抽不到对应过滤条件。

| 编号 | 问法 | 期望槽位 | 现状问题 |
|---|---|---|---|
| I1 | 西乡段上行方向有多少处病害 | 路线=西乡段，up_or_down=1 | 方向只被当成分组维度，没当成过滤条件 |
| I2 | 西乡段下行和上行分别多少处 | 分组=方向（这个应能走分布），不是过滤 | 用来对照 I1，别混 |
| I3 | 西乡段收藏了的病害有多少处 | 路线=西乡段，collect=1 | "收藏"在简单计数里被忽略，回了全部911 |
| I4 | 哪些病害收藏了但还没转工单 | collect=1 且 problem_status=0（可不限路线，全库） | 多布尔条件 + 无路线反问 |
| I5 | 西乡段已经转了工单的病害有多少 | problem_status=10 | 状态 code 映射 |
| I6 | 西乡段车辆巡检发现的病害有多少 | problem_source=5 | 来源 code 映射 |
| I7 | 西乡段没有采集图片的病害有多少处 | problem_url 为空（has_image=否） | has_image 不在可过滤字段表 |
| I8 | 西乡段有现场照片的泛油，列出桩号和照片 | 类型=泛油，has_image=是，list | 布尔 + 明细 + 取图 |

# 第三部分　长对话链式换槽（同一模板在追问里复用）

检验多轮里"继承哪些槽、替换哪个槽、哪些上一轮答案其实没用"。

## 链 J：计数 → 改类型 → 改时间

| 轮次 | 问法 | 补全后应是 | 期望命中 |
|---|---|---|---|
| J1 | 西乡段有多少处泛油 | 西乡段泛油计数 | 族A |
| J2 | 不是，我是问未知类型的 | 西乡段"未识别类型"病害计数（上一轮534这个数字无用，只换类型槽） | 族A换类型 |
| J3 | 那7月30日当天的呢 | 西乡段未识别类型、7月30日计数（加日期槽） | 族E类/加时间 |

## 链 K：巡检 → 最多那次 → 明细

| 轮次 | 问法 | 补全后应是 | 期望处理 |
|---|---|---|---|
| K1 | 西乡段7月巡检了几次，每次多少处 | 巡检次数 + 每次计数 | 族C + 分组明细 |
| K2 | 哪次最多 | 在上一步结果里取 count 最大的那次 patrol_id | 后置计算，不重查 |
| K3 | 把那次的病害明细调出来 | 用 K2 的 patrol_id 作为实体槽查明细（编号里的数字是编号不是时间，不许加时间范围，也不许丢西乡段） | list 模板按 patrol_id 过滤 |

## 链 L：多条件明细 → 改阈值 → 换路线对比

| 轮次 | 问法 | 补全后应是 |
|---|---|---|
| L1 | 西乡段7月上行面积大于5平的病害明细 | 路线西乡+7月+上行+area>5，list |
| L2 | 把面积等于7.52的调出来 | 同条件，area 槽由 >5 换成 =7.52（替换，不是叠加） |
| L3 | 不对，我是说大于10的 | area 槽换成 >10 |
| L4 | 恒明珠也按这个条件筛一下，对比两条路 | 同样的 月份+上行+area>10，路线换成恒明珠，再并排对比（H 类拆子问题） |

## 链 M：先全库筛 → 追问其中某路线

| 轮次 | 问法 | 补全后应是 |
|---|---|---|
| M1 | 全库泛油里面积正好7.52的有几处 | 全库、类型泛油、area=7.52，count |
| M2 | 其中西乡段的有多少 | 在 M1 条件上加 路线=西乡 |
| M3 | 把西乡段这些的明细全调出来 | M2 全部条件 + list（不能退回成西乡段全部泛油） |
