# 收紧通用算子（generic）的触发规则（给 codex）

## 一、目标
用户反馈"通用算子模板推荐太烦人、总排在前面"。当前 `_generic_candidates`（capabilities.py:472-）门槛太宽：只要表能落到某张白名单表、shape 是 list/detail/distribution/count/top、且条件都能翻成列，就无脑拼一条 generic。它适合的其实只有"简单、单主体、单指标、口径明确的明细/计数"，其余问题它要么答一半、要么张冠李戴。本方案收紧它的准入，让 generic 退回到"真正简单题的兜底"，复杂/对比/评价/分组题一律交给 Wren 或专门模板。

## 二、现有门槛（保留）
- 表解析不到 → return []（484-486）；
- shape 不在 {list,detail,distribution,count,top} → return []（487-489）；
- 有条件翻不成列（unresolved）→ return []（490-492）；
- 同类上限 generic≤2、分层排序 generic=2 在模板/示例之后（collect_capabilities）。

## 三、要新增的收紧规则（命中任一即 return []，不摆 generic）

### R1 排除"需要理解/推理/多步"的意图
plan 出现以下任一信号，generic 直接弃权（交给 Wren 或 analysis 链路）：
- 问原因、评价、好坏、建议、养护对策（"为什么""哪条路更好""该怎么养护"）；
- 有后置计算/derived：对比结论、增长率、占比解释、趋势、排名后的解读；
- 复合问题（sections/子问题≥2）、data+knowledge 混合；
- 一句话问多个指标（plan.semantic.metrics ≥ 2）或多个主体（路线/对象列表 ≥ 2，即"两条路分别…"）。

### R2 shape=count 但其实要分组 → 禁止 generic_count
- generic_count 只出单值总数。若 slots 里出现 group_by、up_or_down、pile_range、damage 列表类、或问题里有"分别/各/按上下行/按类型"，说明用户要的是分布不是总数，**禁止 generic_count**（否则就是"上下行各有多少只答了一个总数"这类错题），弃权交给 distribution 模板 / Wren。

### R3 distribution 的分组维度解析不到，禁止拿第一列顶替
- 现在 515-520 行：group_by 列在该表解析不到时，用 `field_grounding.columns_of` 的第一列硬当分组维度。这会张冠李戴（"按技术等级分布"实际按别的列分）。
- 改为：group_by 解析不到就该分支弃权，不许兜底顶替。

### R4 top/rank 的指标不许用关键词猜
- 现在 589-593 行：metric 靠"问题里有没有'面积'/'avg_area'"这种关键词猜、agg 默认 count。这是又一处关键词穷举。
- 改为：metric_column / agg 必须来自 plan.semantic.metrics 明确给出；plan 没明确就不摆 rank 卡片，弃权交 Wren。

### R5 纯"全库/全部"无过滤的计数，不走 generic 抢位
- generic_count/detail 只在 slots 里至少有一个真实业务过滤（路线 / 时间 / 类型 / 桩号区间 / 阈值）时才摆成正常候选；
- 用户只说"全库有多少种/全部列出来"这种无任何业务过滤的题，交给 preset 的 table_count 或 Wren；generic 最多作为不推荐的兜底，不抢 recommended。
- 目的：让 generic 只在"带着明确条件来查"时出现，别一上来就全表扫。

### R6 generic 的理由必须是人话（承接上一份方案）
- 删掉写死的"字段目录解析（编码翻中文）、不经过大模型"（537/558/579）。
- 从它实际生成的 sql_preview/scope 反推一句：查哪张表、按哪些条件、做什么聚合，例："按病害表统计：2026年7月、全库、数行数"。

## 四、收紧后 generic 该接什么
只接满足下面全部条件的简单题：
- 单主体、单指标、无后置计算、非评价/原因；
- shape 与用户意图一致（要总数就是 count 且无分组语义；要明细就是 list/detail；要分布就是 distribution 且 group_by 列真实存在）；
- 带明确业务过滤，或确实就是简单全表计数时也只做兜底不抢推荐位。
其余一律不摆 generic，交给 Wren / 专门模板 / analysis 链路。

## 五、验收（给 codex 自测）
1. "2026年7月全库有多少处"（单主体单指标带时间）→ generic_count 可摆，且时间真正进 WHERE（=1379，承接上一份过滤丢失修复）；
2. "上下行各有多少处"（要分组）→ 不摆 generic_count，走 distribution/专门模板；
3. "哪条路养护压力大/为什么/建议怎么养"→ generic 不出现，走 analysis/Wren；
4. "两条路分别多少处、哪条多"（多主体+对比）→ generic 不出现；
5. "按技术等级分布"但该表没这列 → 不拿别的列顶替，弃权；
6. "全库病害有多少种"（无业务过滤）→ 不被 generic 抢推荐位，走 table_count/Wren；
7. generic 卡片理由是一句人话。
