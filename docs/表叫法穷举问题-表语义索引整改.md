# 表叫法穷举不了怎么办：表语义索引 + 证据驱动的选表

## 问题

用户对每张表的叫法是他的理解，不是库里的表名：

- "把定距拍的片子调出来" → `ai_distance_capture`
- "这条路上一共标了多少个点" → `basic_facilities_sections_pile_detail`（模型 `pile_point`）
- "构造物清单里有哪些桥" → `basic_facilities_bridges`
- "巡查车子跑过的轨迹" → `ai_maintain_patrol` / `gps_points`

给表写别名清单（"拍片子=定距采集""桩点=里程桩"）永远补不完：换个人、换个说法就漏。

## 解法：不枚举叫法，索引"表自己的语义"

新增 `wren_engine` 三个能力（全部从 MDL 自动生成，库结构变了重建 MDL 就跟着变）：

1. `_schema_index(kind)`：表语义索引 = 每张表的**说明** + 每个列的**列名/中文注释**。
2. `search_models(kind, 用户原话)`：按语义检索候选表，并给出**命中证据**（哪条列注释对上了）。
   - 中文用 2~3 字滑窗 + "全库只出现在少数表上的罕见单字"兜单字概念（"有哪些桥"→桥表）；
   - 不引分词库、不写别名表。
3. `suggest_fields(kind, [猜测的列名])`：把"用户/模型自己的列叫法"反查回真实列。

检索结果作为**证据**喂给三个语义环节（判断权仍在 LLM）：

| 环节 | 提示词 | 作用 |
| --- | --- | --- |
| 意图分类 | `intent.md` | 数据查询别被判成知识问答 |
| 意图/主体解析 | `query_semantic.md` | 主体（subject）别一律默认 disease |
| 选表 | `table_selector.md` | 删掉别名穷举清单，改成"看列注释判断语义" |

## 同时修掉的 6 个真实 bug（都是实测复现的）

1. **汇总崩溃**：`agent._summarize_rows_core` 里 `numeric/looks_count/asks_count` 只在 count 分支赋值，
   单行多列题（"病害工单的处理状态"）直接 `UnboundLocalError` → 改成进单行分支就统一算。
2. **MDL 条件锚死 disease**：`mdl_condition_lines` 一律写 `disease.xxx`，主体是工单/路线/巡查时
   模型照着 `FROM disease` 写。改成按主体模型锚定（列存在就用主体表，不存在才说明要 JOIN）。
3. **口径卡片写错对象**：`scope_card` 永远写"对象：全部病害"，校验器判答非所问又把问题改写成
   离谱的字段清单（"把路线台账的明细全部调出来"→ 报"没有找到路线'包括路'"）。
   现在对象名从 MDL 模型说明取，主体粗到"资产/设施"时以选表结果为准。
4. **字典题被"猜字段"拦死**：语义层把 `disease.pic_position` 当成本轮必带字段，
   而选中的表是字典表 → 校验器拦下正确 SQL。现在只对**确实属于本轮选中表**的字段做校验。
5. **不适用条件进 SQL**："边坡台账明细"里"边坡"被当成病害类型 → SQL 变"边坡病害"。
   选中表里没有病害/字典表时，`damage_type` 条件直接摘掉。
6. **`restate()` 用了没导入的 `calibrate`** → 带桩号的问题直接 `NameError: calibrate is not defined`。

顺带修：跨库路由选错（"沿线设施资产台账"被路由到 PG，编译报 `table 'wren.public.disease' not found`），
现在用库结构语义检索复核，PG 里没落点、MySQL 里有落点就回 MySQL。

## 验证

1. **表叫法题（原话→表）8 题**：`ai_distance_capture` / `basic_facilities_bridges` / `pile_point` /
   `maintenance_road_work_record` / `ai_work_order` / `ai_asset_base` / `patrol` /
   `basic_facilities_slope` 全部选对。
2. **38 题全字段可达性**（`backend/test_all_fields.py`，与上一轮同一套题对拍）：
   - 表可达 **29/38 → 33/38**
   - 字段命中 **115/145 → 130/145**
   - 修好的：路线台账 / 路段台账 / 里程桩点 / 隧道台账 / 边坡台账（表+9 个字段）/ 病害类型字典（6/6 字段）
3. **真值回归**：西乡段泛油 534、西乡段面积合计 56241.20、7 月西乡段巡检 10 次、密度 178.63 全部正确。
4. **知识问答复核**："泛油病害怎么处置"仍走知识库、给出预防养护技术清单（没被表检索抢走）。

### 本轮仍没解决的（如实记录）

- `ai_work_order` 与 `maintenance_work_order` 两张表**列和注释完全相同**（库里就是"养护_任务工单"），
  语义上无法区分，选表在两者间摇摆（两表都为空）。要真解决得给其中一张补业务描述。
- 定距采集（F-distance）、日常养护作业记录（F-workrec）两题：表选中了，但走 LLM 兜底时
  被改写成别的表 / 追问条件，仍会答偏（这两张表本身也是空的）。
- 倾斜监测点（PG）明细题仍不稳：PG 侧没有走"选表→小范围字段"这条路。
