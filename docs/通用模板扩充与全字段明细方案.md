# 通用模板扩充与全字段明细方案

目标：不再为每个字段、每种问法单独写模板。先建一个以数据库建表注释为事实源的字段目录，再用一个通用明细模板覆盖全部字段的查看，配一批与具体字段无关的通用聚合算子，最后把冷门字段和当前为空但业务热门的表预置成固定模板。空表照样注册，将来有数据即可查，空结果如实返回，不算错误。

本方案只解决"查得到、口径对"，占位值、异常值的数据清洗不在范围。

## 一、字段目录服务 schema_catalog（地基）

现在字段中文名散落在字段字典 md、Wren MDL 和 nl2sql.py 的硬编码别名里，冷门字段因此查不到。已连库验证：information_schema.COLUMNS.COLUMN_COMMENT 可用，ai_problem 共 54 列，其中 50 列有注释，冷门字段注释完整，而且编码含义直接写在注释里，例如 problem_status 注释为"病害状态: 0待转工单,10已转工单,15忽略病害"，collect 为"收藏：0否，1是"。

新建 services/schema_catalog.py，作为全系统唯一的字段中文名与编码映射事实源：

- 启动和刷新时从 information_schema.COLUMNS 读取每张白名单表的 TABLE_NAME、COLUMN_NAME、DATA_TYPE、COLUMN_COMMENT、ORDINAL_POSITION。
- 解析注释，产出 label（中文名）和 code_map（编码到中文）。解析规则：取冒号/括号后的"数字+中文"序列，如"0.手动新增 5.车辆巡检 10.人工巡检"解析为 {0:手动新增,5:车辆巡检,10:人工巡检}。
- 解析不准的注释，用一份人工覆盖配置 data/code_map_overrides.json 纠正（只写例外，不重复全量）。
- 标注字段角色：is_primary、is_soft_delete（del_flag）、is_time、is_numeric、is_code（有 code_map）、is_image（problem_url/preview_url/distance_capture_url/picture/asset_sample_image 等）、is_geo（lng/lat/经纬度）、is_fk，以及外键显示值的 JOIN 方式。
- 外键显示值统一登记：routes_id 关联 basic_facilities_routes 取 short_name；damage_type、problem_base_id 关联 ai_problem_base 取 problem_type；patrol_id 关联 ai_maintain_patrol 取 task_number/patrol_number；sections_id 关联 basic_facilities_sections 取 full_name；device_code 关联 ai_collection_equipment；asset_details_id 关联 ai_asset_base 取 asset_type。
- 提供 label 到物理列的双向查找：resolve_column(table, 中文名或物理名) 返回白名单内的列，找不到就明确返回 None，交给 Wren，不猜。
- 刷新方式与 preset 热加载一致：启动加载、文件/结构版本变化时重载、提供手动刷新；PostgreSQL 走 pg_catalog 同义视图（gps_points、inclination_points 两表字段无注释，label 用一份小的补充配置补齐）。
- Wren MDL、nl2sql 的字段别名、模板参数选项都改为从 catalog 取，不再各写一份。

## 二、通用明细模板 generic_detail（一个模板看任意列）

这是本次重点。用一个参数化模板查看任意表白名单字段的详情，字段参数传中文名或物理名均可，由 catalog 解析成物理列；用户不需要知道列名。

参数：

- table：主体表，必须在白名单（病害、资产、设备、巡检、定距、路线、路段、桩点、工单、GPS 等）。
- columns：要看的字段，中文名或物理名，缺省给该主体的常用明细列（病害默认桩号、类型、面积、置信度、采集时间、方向、图片等）。
- filters：过滤条件数组，每项 {字段, 操作符, 值}；操作符限定 =、!=、>、>=、<、<=、between、in、is null、like；编码字段的值传中文（"已收藏""待转工单""车辆巡检"），由 code_map 翻成 code。
- order_by：{字段, 方向}，字段同样走白名单。
- limit：默认取系统明细上限，不允许无上限全表导出。

SQL 形状：

```
SELECT {白名单列 AS 中文注释别名, 外键 JOIN 出的名称列, 编码列保留 code 并附中文列}
FROM {主表} {必要的字典/名称 LEFT JOIN}
WHERE del_flag = 0 {AND 过滤条件}
ORDER BY {白名单列} {ASC|DESC}
LIMIT {上限}
```

规则：

- 列名、表名只能来自 catalog 白名单，绝不拼接用户原文；值按类型强校验，编码值先过 code_map。
- 编码字段输出时给中文（如 problem_status 输出"待转工单"），需要时同时保留 code；这样外行也看得懂。
- is_image 列命中时，结果走现有图片渲染（SeaweedFS 取图），而不是只返回 URL 文本。
- is_geo 列命中时可附带地图链接或经纬度数值，不做越界值清洗（清洗另算）。
- 空表执行返回空明细，并明确说"该表当前没有数据"，不报错、不编造。
- 跨库：table 属于 gps_points、inclination_points 时 kind=postgreSQL，SELECT 形状一致。

有了它，"把西乡段收藏的病害明细调出来""看看西乡段病害的经纬度和病害位置""这台设备采了哪些病害""GPS 轨迹点明细"都能确定性命中，不再被关键词忽略或乱跳库。

## 三、通用聚合算子（与具体字段无关）

下列算子的"分组列、指标列、时间列"都是参数，统一从 catalog 白名单解析，编码列自动翻译中文。它们替代"再加一个关键词模板"的做法。

1. generic_group_distribution：任意分类列分组，输出 类别中文、数量、占比。覆盖工单状态、病害来源、收藏、关注、是否绑定任务、上下行、操作类型、历史损坏区间、路格、设备、巡检主体、资产类型等所有分类字段。
2. generic_time_series：任意时间列按年/季/月/周/日/时/星期分组计数或汇总。覆盖逐月趋势、哪天最多、集中时段、星期几多、任务开始时间分布。
3. generic_rank：任意分组列配任意数值指标（count、sum、avg、max、min，指标可为面积、置信度、长度、宽度、高度、速度等），排序取 Top N。
4. generic_column_stats：任意数值列的 count、sum、avg、max、min、非空率；经纬度列给 min/max 范围。
5. generic_null_completeness：任意列或一组列的空值数、空值率、填报完整率，可按路线分组。覆盖图片覆盖率、经纬度缺失、类型未识别比例、面积未填。
6. generic_distinct_values：任意列的取值种数和去重取值清单（编码给中文）。覆盖"有多少种资产类型""有哪些设备""多少个巡检人"。
7. generic_filter_count：任意条件组合的计数，是 generic_detail 的计数版，条件编码中文转 code。
8. generic_geo：经纬度范围、按上下行/桩号段或经纬度网格聚合，回答"分布在哪一侧""经纬度范围""空间集中在哪"。
9. cross_db_track：PostgreSQL GPS/倾斜监测点的明细与速度、卫星数、位移统计，kind 明确标 postgresql，避免再出现用 GPS 问题去查 MySQL gps_points 占位表的错误。

这些算子做成参数化代码构造器；因为通用性强、口径需要让人看清，命中后一律走《确定性能力人工确认方案》的候选确认卡，展示"查哪张表、哪些列、怎么分组过滤"，人确认后执行；表达不了的结构弃权交 Wren。

## 四、数据画像（元数据）能力：哪些表、字段没数据

"全库哪些字段没数据""每张表多少行""字段空值率、填报完整度"不是业务取数，而是关于数据库本身的元数据问题。information_schema 只存表结构和估算行数，不记录某一列是否全空，必须遍历白名单表、对每一列实际统计。这类问题无法映射成业务 plan，之前被错误套成"缺路线"澄清，出现"没找到路线'把全库没有数据的字段'"这种回答。

- 新增意图类型 meta/profiling，与 knowledge、data、analysis、image、composite 并列。识别"没数据的字段、空字段、空值率、完整度、覆盖率、各表数据量、数据画像、填没填"等说法，直接路由到画像算子，不进业务 plan、不生成业务 SQL。
- 画像算子 profile_columns(scope)：基于 schema_catalog 取白名单表和列，对每列动态生成非空计数、按表聚合执行，返回 表、字段物理名、中文名、类型、表总行数、非空数、空值数、空值率；scope 支持全库、指定表、只看全空、空值率超过阈值。
- 判空口径写死，避免误判：数值、日期、jsonb 列只判 IS NULL，数值 0 不算空；字符型判 IS NULL 或空串；PostgreSQL 的 jsonb 不能用 <>'' 比较；值为字符串 'NULL' 的算异常占位值，归数据清洗，不计为空。
- 整表 0 行单独归为"空表（全部字段无数据）"，与"有数据但个别列全空"分开呈现。
- 结果缓存：按表结构版本加表行数缓存，启动、手动、定时刷新，不必每次全库扫描；看板增加固定卡片"数据完整度画像"。
- 兜底修复：plan 映射不上时，先判断是不是元数据问题并走画像；确实不认识才明确说不支持，禁止把用户原话误当路线名或条件去套"缺路线"澄清。
- 已连库实测的基线（白名单 MySQL 16 张加 PostgreSQL 2 张，供验收）：空表 12 张，分别是 ai_asset_main（27 字段）、ai_distance_capture（32）、basic_facilities_bridges（28）、basic_facilities_tunnels（80）、basic_facilities_slope（31）、project_manage_project_main（56）、maintenance_project（18）、maintenance_road_work_record（15）、ai_work_order（26）、maintenance_work_order（26）、gps_points（9）、inclination_points（11）。有数据但存在整列全空字段的表：ai_problem 1703 行有 16 列（collect、work_order_id、problem_name、problem_describe、preview_url、disease_length、history_damage_interval、vehicle_id、inspection_user_id、inspection_obj_id、inspection_obj_type、start_num、end_num、create_by、unit_id、file_name）；basic_facilities_sections 5840 行有 38 列；ai_maintain_patrol 148 行有 6 列（device_code、vehicle_id、patrol_partner、unit_id、patroller_id、memo）；ai_asset_base 88 行有 5 列；basic_facilities_routes 3627 行有 3 列（picture、picture_cover、blueprint）；ai_problem_base 97 行有 3 列；basic_facilities_sections_pile_detail 69557 行无整列全空。

## 六、与现有体系衔接

- 固定模板进 preset_queries.json，带 match、scope、参数选项，走现有白名单绑定执行，并在预置维护里显示 SQL 供仿写。
- 通用算子和 generic_detail 是参数化代码构造器，字段参数走 catalog 白名单，不允许新增端到端关键词；它们作为候选进入人工确认卡，确认后执行。
- catalog 解析不了的字段或算子表达不了的结构，弃权交 Wren 语义层，不硬套模板。
- 数据画像（meta/profiling）与业务取数分开：不经过业务 plan 和模板匹配，直接走 profile_columns 算子，结果来自缓存的只读统计，不随单次提问重复全库扫描。
- 所有模板结果仍走结果校验；图片类走图片渲染；空表、空结果如实说明。
- 字段中文名、编码映射、外键 JOIN、图片列判断以后只维护 catalog 一处，新增表或字段后 catalog 刷新即可被通用模板覆盖，不必再改代码。

## 七、安全约束

- 表、列白名单；操作符白名单；值类型校验与编码值白名单；只读、SELECT/WITH 校验；明细强制 LIMIT；统一补 del_flag=0（无该列的表除外）；禁止把用户原文直接拼进 SQL；PostgreSQL 与 MySQL 按表归属固定 kind，不靠关键词猜库。

## 八、落地步骤

1. 实现 schema_catalog：读 information_schema/pg_catalog，解析注释和编码，建字段角色与外键/图片/经纬度登记，配 code_map_overrides，加热加载与手动刷新。
2. 实现 generic_detail 与九类通用算子，含编码翻译、外键 JOIN、图片渲染、跨库 kind、空表处理和白名单校验。
3. 新增 meta/profiling 意图与 profile_columns 画像算子，落实判空口径、结果缓存和看板"数据完整度画像"卡片，并修正 plan 失败时误套"缺路线"澄清的兜底。
4. 把通用算子接入候选收集与人工确认卡，展示表、列、口径。
5. 按第五节清单新增固定 preset，补参数选项（设备、任务、资产类型、路格等动态选项连库查）。
6. Wren MDL 与 nl2sql 字段别名改为引用 catalog，移除重复硬编码。
7. 用第九节用例回归，并对全部白名单表跑一次"通用明细取数"和一次"全字段画像"冒烟，确认空表诚实答空、有数据表字段可达、全空字段统计与基线一致。

## 九、验收用例（含实测预期）

- "把西乡段收藏的病害明细调出来"：命中 generic_detail，过滤 collect=1、路线西乡段；当前收藏为空时如实说没有收藏记录，而不是返回全部 911 条。
- "西乡段病害的经纬度和病害位置明细"：返回 lng、lat、map_position 中文列，1702 条范围内该路线有值。
- "全库病害按工单状态、来源、是否绑定任务分别怎么分布"：命中 generic_group_distribution，输出中文类别和占比（当前分别为全部待转工单、全部车辆巡检、全部已绑定）。
- "哪些病害被关注了"：返回 track_problem=1 的明细，当前 1 条。
- "数据库里有多少种资产类型，分别是什么"：命中 asset_type_dict/generic_distinct_values，返回 ai_asset_base 的类型清单。
- "系统有几台采集设备，分别什么状态"：命中 equipment_list，返回 5 台设备及中文状态。
- "看看某次巡检的 GPS 轨迹"：命中 gps_track_detail 且走 PostgreSQL；gps_points 当前为空时明确说暂无轨迹数据，不去查 MySQL。
- "西乡段面积大于 5 平方米的病害明细，列出桩号、类型、面积、图片"：generic_detail 多列加条件，图片列正常渲染。
- "桥梁台账有多少座、列一下"：空表模板返回 0 并说明暂无桥梁数据，不报错。
- "把全库没有数据的字段全部调出来"：命中 meta/profiling，返回 12 张空表清单和各有数据表的整列全空字段（中文名、空值率），不再报"没找到路线'把全库没有数据的字段'"。
- "ai_problem 哪些字段一个值都没填"：画像算子只扫该表，返回 16 个全空字段（收藏、工单、病害名称、描述、缓存图、病害长度等）。
- 对每张白名单表执行一次"默认明细取数"：有数据表返回列中文正确的明细，空表返回空并提示，592 个字段中常用字段均可通过中文名在 generic_detail 中取到。
