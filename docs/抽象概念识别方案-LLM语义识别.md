# 抽象概念识别方案：从关键词匹配改成LLM语义识别

> 问题：现在靠硬编码关键词匹配"老病害/新病害"，用户换个说法就不认了，永远补不完。
> 方案：把"是不是在问分档对比"交给LLM判断，不用维护关键词表。

---

## 一、现在的问题

### 现状

`nl2sql.py` 里有个 `_BUCKET_CONCEPTS`，硬编码了3个维度：
```python
(("老问题", "新问题", ...), "time", "采集时间"),
(("大病害", "小病害", ...), "area", "病害面积"),
(("高置信度", "低置信度", ...), "confidence", "识别置信度"),
```

两个问题：
1. **维度写死了**：只有时间/面积/置信度三个，用户问"密集/稀疏"、"多/少"就不认
2. **关键词写死了**：用户换个说法就不认，比如"老病害"匹配不上"老的病害"

### 为什么不智能？

**本质是穷举，永远补不完：**
- 加一个维度，改代码
- 加一种说法，加关键词
- 永远补不完，这就是"拆东墙补西墙"

---

## 二、改进方案：交给LLM语义识别

### 核心思路

**不靠关键词匹配，不靠写死维度。**
**LLM自己判断：** 用户在问"哪个维度分两档对比？哪两档？"

不管用户问什么维度、什么说法，只要LLM理解了，就都能答对。

### 流程对比

**现在：**
```
用户问 → 关键词匹配 → 匹配上走模板 / 匹配不上走COUNT(*)
```

**改成：**
```
用户问 → LLM理解语义 → 哦，这是按【面积】分两档对比
   ↓
告诉SQL生成器：按面积中位数分两档，大的算A，小的算B
   ↓
LLM自己写SQL：CASE WHEN area < 中位数 THEN 小 ELSE 大 END
   ↓
GROUP BY → 返回小多少大多少
```

**支持的任意维度（不写死）：**
- 时间维度：老问题/新问题 → 按collection_time中位数
- 面积维度：大病害/小病害 → 按area中位数
- 置信度维度：高置信度/低置信度 → 按confidence中位数
- 密度维度：密集/稀疏 → 按密度中位数
- 数量维度：多/少 → 按数量中位数
- 距离维度：远/近 → 按距离中位数
- 长度维度：长/短 → 按长度中位数
- 等等...

**用户问哪个维度，LLM就识别哪个维度，不用提前写死。**

---

## 三、具体要改什么

### 1. parse_semantics 加一种 shape

在 `query_semantic.md` 提示词里，加一种 shape：

```
bucket_compare：分档对比。用户在问"某指标的两档哪个多"
  - 识别：用户问 A多还是B多，A和B是同一个维度的两端
  - 要识别出三个东西：
    1. bucket_metric：按哪个指标分？（time/area/confidence/...）
    2. bucket_low_label：低的那档叫什么？（老问题/小病害/低置信度）
    3. bucket_high_label：高的那档叫什么？（新问题/大病害/高置信度）
  - 告诉SQL生成器：按这个指标的中位数分两档
```

**LLM 判断逻辑：**
- 用户问"A多还是B多？"
- A和B是同一个维度的两端（老/新、大/小、高/低、密/疏）
- 就是 bucket_compare
- 自动识别是哪个维度、两档分别叫什么名字

---

### 2. semantic_summary 加提示

在 `semantic_summary` 里，如果识别到 shape = bucket_compare，就加一条：

```
【分档对比】用户在问"老的多还是新的多"，请按【采集时间】的中位数分两档：
早于中位数的算"老问题"，晚于中位数的算"新问题"。
SQL 里要用 CASE WHEN 实现，GROUP BY 这个分档。
回答时必须说明分界线是多少。
```

---

### 3. 删掉硬编码的关键词表

把 `_BUCKET_CONCEPTS` 整个删掉，不用了。
全部交给LLM语义识别。

## 四、为什么这样就智能了？

**现在：** 加一个关键词解决一种问法，永远补不完。
**改完：** 不管怎么问，LLM理解语义就能答对。

**举例：**
- "老问题多还是新问题多？" → LLM理解：按时间分两档
- "以前就有的多还是新发现的多？" → LLM理解：按时间分两档
- "之前巡检就有的多还是这次新冒出来的多？" → LLM理解：按时间分两档

**都是同一个意图，都是按时间分两档，不管怎么问都能答对。**

这就是真智能，不是穷举。

---

## 五、改完之后

**不用维护关键词表了。**
**新的抽象概念不用改代码，改提示词就行。**

比如以后用户问"严重的多还是轻微的多？"，只要在提示词里加一句"严重/轻微也是分档对比"，LLM自己就理解了。
