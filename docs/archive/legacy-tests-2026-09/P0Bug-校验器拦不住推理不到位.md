# P0 Bug：校验器拦不住"只列数据不给结论"的问题

> 现象：用户问的是"分析/判断/结论"类问题，但系统只列了数据，没给推理和结论。
> 校验器没拦住，直接把答非所问的结果返回给用户了。

---

## 一、Bug现象

### 用户问的
```
宝安大道西乡段比其他路高这么多，是因为巡检频繁，还是真的病害多？
```

### 系统答的
```
分布：宝安大道西乡段 911 处。
（各口径：巡查任务次数 = 10、平均每次发现病害数 = 91.1000、病害密度 = 178.63）
```

### 问题在哪？

| 用户要的 | 系统给的 |
|---------|---------|
| 对比两条路的巡检次数和密度 | 只列了西乡段的数据 |
| 给结论：是巡检频繁，还是真的病害多？ | 没给结论 |
| 二选一的判断 | 只列数据 |

---

## 二、为什么校验器没拦住？

现在的校验器只有7条规则，都是检查"数据对不对"：
1. 聚合 vs 明细
2. 分组识别
3. 字段匹配
4. 主体匹配
5. 单位匹配
6. 维度完整性
7. 指标口径一致性

**但缺了第8条：推理/结论是否到位**

用户问的不是单纯查数据，而是要"分析/判断/结论"的时候，只列数据就是答非所问。

---

## 三、加第8条校验规则

### 【检查8：推理/结论是否到位】

用户问的不是单纯查数据，而是要"分析/判断/结论"的问题 → 不能只列数据，要给出推理和结论。

| 用户问的类型 | 回答应该有什么 | 反例 |
|-------------|-------------|------|
| 是A还是B？（二选一） | 对比A和B，给结论：是A/是B/两者都有 | 只列A的数据，没对比没结论 |
| 为什么会这样？（原因分析） | 列可能原因，说明哪个是主要的 | 只列数据，没说原因 |
| 好不好？（评价） | 给个判断：好/一般/较差/严重 | 只列数据，没说好不好 |
| 应该怎么做？（建议） | 给具体建议：先做什么，后做什么 | 只列数据，没说怎么做 |

**如果用户问的是需要"推理/结论"的问题，但回答只列了数据，没给结论 → 错，是"推理不到位"问题。**

---

## 四、新增issue_type

```
reasoning_insufficient：用户问的是"分析/判断/结论"类问题，但回答只列了数据，没给推理和结论
```

---

## 五、校验示例

### 输入
用户问题：西乡段病害密度比其他路高这么多，是因为巡检频繁，还是真的病害多？
生成的 SQL：只查了西乡段的数据
系统返回的结果：西乡段巡检10次，密度178.6
最终回复：分布：西乡段 911 处。（各口径：巡查任务次数=10、平均每次91.1、密度178.63）

### 输出
```json
{
  "correct": false,
  "issue_type": "reasoning_insufficient",
  "reason": "用户问的是'是巡检频繁还是真的病害多'，需要对比两条路的巡检次数和密度来下结论，但回复只列了西乡段的数据，没对比，也没给结论。"
}
```

## 六、问题优化示例

### 优化前的问题
```
西乡段病害密度比其他路高这么多，是因为巡检频繁，还是真的病害多？
```

### 优化后的问题
```
宝安大道西乡段和宝安中心--恒明珠，分别统计各自的巡检次数和病害密度，对比一下：西乡段密度高，是因为巡检次数更多，还是因为每次巡检发现的病害更多？
```

---

## 七、优先级

| 优先级 | 改动 | 效果 |
|--------|------|------|
| P0 | 校验器加第8条规则 | 拦住"只列数据不给结论"的问题 |
| P0 | 加reasoning_insufficient类型 | 能识别这种问题 |
| P1 | 问题优化加对应示例 | 自动优化成需要对比+结论的问题 |
