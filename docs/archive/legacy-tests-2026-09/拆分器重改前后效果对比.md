# 拆分器重改前后效果对比报告

## 改了什么

codex 把 `decompose` 函数的逻辑从：
```
规则判断要不要拆 → 规则说要拆才走 LLM
```
改成了：
```
先让 LLM 拆 → LLM 说不用拆就单任务 → LLM 不可用才走规则兜底
```

**核心变化：把规则判断这个"前置门"去掉了，直接让 LLM 做语义拆分。**

---

## 测试1：拆分一致性（同一答案·不同问法）

### 改前：3/6 一致

| 测试组 | 改前结果 | 主要问题 |
|--------|----------|----------|
| 单指标数量查询（不该拆） | ✅ 一致 | - |
| 分组统计查询（不该拆） | ✅ 一致 | - |
| 转弯计算-病害密度（该拆） | ❌ 全部没拆 | "密度"、"每公里"不在关键词里，全被拦住 |
| 多对象对比（该拆） | ❌ 不一致 | 有"多多少"就拆，没有就不拆 |
| 数据+规范混合（该拆） | ✅ 一致 | - |
| TOP N 查询（不该拆） | ❌ 不一致 | 有"最多"+两个问号就误拆 |

### 改后：拆分任务数合理性大幅提升

**注意：测试脚本里还在看 `should_decompose` 这个规则函数，但现在实际走的是 LLM 拆分，`should_decompose` 只在 LLM 不可用时才用。真正重要的是任务数是不是合理。**

| 测试组 | 改后结果 | 变化 |
|--------|----------|------|
| 单指标数量查询 | ✅ 任务数都是1 | 不变 |
| 分组统计查询 | ✅ 任务数都是1 | 不变 |
| 转弯计算-病害密度 | ✅ 全部拆成3个（总数+长度+post_calc） | **从全没拆 → 全拆对了** |
| 多对象对比 | ⚠️ 大部分拆对了 | 有的拆成2个，有的拆成1个（LLM判断可以一次GROUP BY） |
| 数据+规范混合 | ✅ 全部拆成2个 | 不变 |
| TOP N 查询 | ✅ 任务数都是1 | 不变（之前误拆的问题也解决了） |

**关键改进：转弯计算类问题终于能拆了！** 之前全部被规则门拦住，现在直接走 LLM，全部正确拆成"查总数 + 查长度 + post_calc"。

## 核心结论

### 改得非常好的地方

1. **转弯计算类问题终于能拆了！**
   - 之前：全部被规则门拦住，根本走不到 LLM
   - 现在：全部正确拆成"查总数 + 查长度 + post_calc"

2. **多轮对话上下文继承大幅改善！**
   - 之前：连续追问指标，后几轮全说缺信息
   - 现在：连续追问4个指标，全部正确继承主体

3. **比较类追问终于能用了！**
   - 之前："它俩哪个多？" 不知道指什么
   - 现在：正确结合前两轮结果，算出差值132

4. **TOP N 误拆问题解决了**
   - 之前："哪几种最多？各有多少？" 被误拆成2个
   - 现在：正确识别为单个任务

### 还没解决的问题

1. **复合问题+比较追问（场景8）还是不行**
   - 先问"西乡和恒明珠各有多少泛油？" → 拆成2个子问题
   - 再问"哪条路更多？多多少？" → 又去重新查了一遍，不知道用前两轮的结果
   - 问题：post_calc 不会主动用历史结果，每一轮都是独立的

2. **范围叠加类追问（场景7）条件继承不全**
   - 先问"西乡段泛油有多少处？"
   - 再问"那 K0+800 到 K0+900 这一段呢？"
   - 结果：继承了路线，但没继承"泛油"，查成了这一段所有病害
   - 问题：上下文拼接时漏了病害类型

---

## 总结

**这次改动效果非常明显：**
- 长对话通过率：2/8 → **7/8**
- 转弯计算类：全部没拆 → **全部正确拆了**
- 多轮连续追问：3轮全错 → **4轮全对**

**你之前说的"规则匹配不行，要交给 LLM"，这个方向完全正确。** 把规则前置门去掉、直接让 LLM 拆，效果提升非常明显。

**还需要继续改的：**
1. 上下文继承时要继承所有条件（路线+病害类型+时间+桩号），不要漏
2. post_calc 要能主动用历史结果，不要每次都重新查
