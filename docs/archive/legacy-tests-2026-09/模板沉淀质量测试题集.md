## 三、测试执行建议

### 3.1 测试顺序

1. **先跑 2.1 单对象简单查询**（5 题）——验证基础参数替换是否正常
2. **再跑 2.2 可选条件测试**（5 题）——验证新功能 conditions.optional 是否生效
3. **跑 2.3 多对象对比测试**（4 题）——验证多对象不沉淀规则
4. **跑 2.4 复合问题测试**（5 题）——验证复合问题模板的完整性
5. **跑 2.5 被降级模板验证**（5 题）——人工判断降级是否合理
6. **跑 2.6 问法变体测试**（5 题）——验证同义问法召回
7. **跑 2.7 边界情况测试**（5 题）——验证边界处理

### 3.2 每题需要记录的信息

- 是否弹卡
- 弹卡的模板是否正确
- 参数替换是否正确（路线/时间/类型/阈值）
- 可选条件是否被正确删除或保留
- 执行结果是否正确（连库验证）
- 总结是否完整（多指标是否都列出来）

### 3.3 重点关注

1. **可选条件删除后 SQL 是否有残留占位符**（如 `{{time_start}}` 没被删掉）
2. **多对象问题是否真的不弹自动模板卡**（防止规则失效）
3. **被降级模板中，哪些是误报可以恢复的**（特别是 #6、#7、#11）
4. **LLM 审核的 parameter_misaligned 误报率**（正常参数用法被误判的比例）
