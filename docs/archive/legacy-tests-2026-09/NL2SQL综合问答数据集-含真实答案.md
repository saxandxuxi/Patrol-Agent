## 一、简单问题（一个答案，多个问法）

### S1：宝安大道西乡段病害总数

**问法变体**：
1. 宝安大道西乡段有多少处病害？

**真实答案**：911 处

**标准 SQL**：
```sql
SELECT COUNT(*) FROM ai_problem p
JOIN basic_facilities_routes r ON p.routes_id = r.id
```

### S2：宝安大道西乡段泛油病害数量

4. 西乡段泛油病害的数量是多少

**真实答案**：534 处

**标准 SQL**：
```sql
SELECT COUNT(*) FROM ai_problem p
JOIN basic_facilities_routes r ON p.routes_id = r.id
JOIN (SELECT DISTINCT problem_code, problem_type FROM ai_problem_base WHERE del_flag=0) dd
  ON p.damage_type = dd.problem_code
WHERE p.del_flag = 0 AND r.short_name = '宝安大道西乡段' AND dd.problem_type = '泛油'
```

### S3：西乡段病害类型分布

```sql
SELECT dd.problem_type, COUNT(*) as cnt
FROM ai_problem p
JOIN basic_facilities_routes r ON p.routes_id = r.id

  ON p.damage_type = dd.problem_code
WHERE p.del_flag = 0 AND r.short_name = '宝安大道西乡段'
GROUP BY dd.problem_type ORDER BY cnt DESC
```

## 二、复合问题（一个问题包含多个子问题）

### C1：指代补全——数量最多病害 + 总数

**问题**：宝安大道西乡段 K0+000 至 K0+887 路段中，数量最多的病害是哪种？该路段病害总数是多少？

**难点**：第二个子问题的"该路段"是指代词，必须补全为"宝安大道西乡段 K0+000 至 K0+887 路段"，否则单独查会查全库。

**正确拆分**：
1. 宝安大道西乡段 K0+000 至 K0+887 路段中，数量最多的病害是哪种？
2. 宝安大道西乡段 K0+000 至 K0+887 路段中，病害总数是多少？

**真实答案**：数量最多的是泛油（534 处），该路段病害总数 911 处

---

### C2：后置计算——路线长度 + 哪条更长 + 长多少

**问题**：宝安大道西乡段和宝安中心--恒明珠的路线长度分别是多少公里？哪条更长？长多少？

**难点**："哪条更长？长多少？"是基于前一个查询结果的后置计算，不需要查数据库。笨拆分把它们当独立查询查数据库，必然失败。

**正确拆分**：
1. 【data_query】宝安大道西乡段和宝安中心--恒明珠的路线长度分别是多少公里？
2. 【post_calc】哪条更长？长多少？（基于子问题1的结果比较大小并算差值）

**真实答案**：西乡段 5.10 公里，恒明珠 19.00 公里；恒明珠更长，长 13.90 公里

**注意**：路线长度不能用 distance 字段（西乡=5.60 不准，恒明珠=0.00 未填），必须用起止桩号相减。

**问题**：西乡段6月和7月的泛油病害分别有多少？哪个月更多？多多少？

**注意**：西乡段病害全部在 7 月，6 月无数据。

**问题**：宝安大道西乡段的泛油病害中，有图片的和没有图片的分别有多少？各占百分之多少？

## 三、转弯问题（一个答案，多个问法）

### T1：路线长度——起止桩号相减

**问法变体**：
1. 宝安大道西乡段全长多少公里？
2. 西乡段这条路有多长？
3. 宝安大道西乡段的路线长度是多少公里？

**难点**：没有 length 字段，distance 字段不准（西乡=5.60，恒明珠=0.00），必须用起止桩号字符串解析相减：K5+100 - K0+000 = 5.10km。

**真实答案**：5.10 公里

**标准 SQL**：
```sql
SELECT
  (CAST(SUBSTRING_INDEX(SUBSTRING_INDEX(end_num,'+',1),'K',-1) AS DECIMAL)*1000
   + CAST(SUBSTRING_INDEX(end_num,'+',-1) AS DECIMAL)
   - CAST(SUBSTRING_INDEX(SUBSTRING_INDEX(start_num,'+',1),'K',-1) AS DECIMAL)*1000
   - CAST(SUBSTRING_INDEX(start_num,'+',-1) AS DECIMAL)) / 1000.0 AS length_km
FROM basic_facilities_routes
WHERE short_name = '宝安大道西乡段' AND del_flag = 0
```

---

### T2：病害密度——长度除以数量

**问法变体**：
1. 宝安大道西乡段平均每公里有多少处病害？
2. 西乡段病害密度是多少？
3. 西乡段每公里平均发现几处病害？

**难点**：需要先算路线长度（起止桩号相减），再用病害数除以长度。两个间接计算叠加。

**真实答案**：178.6 处/公里（911 ÷ 5.10）

---

### T3：面积大于平均——子查询

**问法变体**：
1. 宝安大道西乡段面积大于平均面积的病害有多少处？
2. 西乡段有多少处病害的面积超过平均值？

**难点**：WHERE 里不能直接用聚合函数，必须用子查询先算 AVG(area)，再 WHERE area > (子查询)。

**真实答案**：11 处（平均面积 61.74 ㎡）

**标准 SQL**：
```sql
SELECT COUNT(*) FROM ai_problem p
JOIN basic_facilities_routes r ON p.routes_id = r.id
WHERE p.del_flag = 0 AND r.short_name = '宝安大道西乡段'
  AND p.area > (SELECT AVG(area) FROM ai_problem p2
    JOIN basic_facilities_routes r2 ON p2.routes_id = r2.id
    WHERE p2.del_flag = 0 AND r2.short_name = '宝安大道西乡段')
```

---

### T4：数量最多 vs 面积最大——数量面积倒挂

**问法变体**：
1. 宝安大道西乡段数量最多的病害类型和面积最大的病害类型分别是什么？
2. 西乡段哪种病害数量最多？哪种病害总面积最大？

**难点**：数量和面积是两个不同的排序维度，结果可能不一样（倒挂）。泛油数量最多但面积很小，未识别类型数量少但面积巨大。

**真实答案**：数量最多的是泛油（534 处，面积 569.78 ㎡），面积最大的是未识别类型（377 处，面积 55671.42 ㎡）

**关键发现**：泛油数量占 58.6% 但面积只占 1.0%，未识别数量占 41.4% 但面积占 99.0%——典型的数量面积倒挂。

---

### T5：平均间距——长度除以数量

**问法变体**：
1. 宝安大道西乡段病害平均每隔多少米出现一处？
2. 西乡段病害的平均间距是多少米？

**难点**：需要先算路线长度（米），再除以病害数。

**真实答案**：5.6 米（5100 ÷ 911）

---

### T6：占比计算——部分除以总数

**问法变体**：
1. 宝安大道西乡段泛油病害占全部病害的百分之多少？
2. 西乡段泛油病害的占比是多少？

**真实答案**：58.62%（534 ÷ 911 × 100）

---

### T7：置信度过滤——JSON 字段提取

**问法变体**：
1. 宝安大道西乡段置信度低于 0.7 的病害有多少处？
2. 西乡段 AI 识别置信度不足 0.7 的病害有几处？

**难点**：置信度没有独立列，在 pic_position JSON 里（$.confidence），必须用 JSON_EXTRACT 提取并 CAST 成数字才能比较。

**真实答案**：385 处

**标准 SQL**：
```sql
SELECT COUNT(*) FROM ai_problem p
JOIN basic_facilities_routes r ON p.routes_id = r.id
WHERE p.del_flag = 0 AND r.short_name = '宝安大道西乡段'
  AND CAST(JSON_UNQUOTE(JSON_EXTRACT(p.pic_position, '$.confidence')) AS DECIMAL(10,6)) < 0.7
```

## 八、带数据库名字的题目

> 目的：测试系统能否正确识别用户提到的数据库名（简称/全称），不把它误判为路线名或其他实体，并正确路由到对应数据库。

### D1：带数据库简称（MySQL）——一个答案多个问法

**问法变体**：
1. MySQL 里宝安大道西乡段有多少处病害？
2. 在 mysql 中查询西乡段的病害总数
3. 查一下 mysql 数据库里西乡段有几处病害

**真实答案**：911 处

**难点**：系统要能识别"MySQL/mysql"是数据库名，不把它当成路线名或其他实体，正确路由到 MySQL。如果数据库名被当成路线名，会报"没有找到路线 MySQL"。

---

### D2：带完整库名（new_four_road_base_ai）

**问法变体**：
1. 从 new_four_road_base_ai 库查一下西乡段泛油有多少处？
2. new_four_road_base_ai 数据库里西乡段泛油病害数量是多少？

**真实答案**：534 处

**难点**：完整库名很长（25 个字符），包含下划线和数字，系统可能误判为路线名或其他实体。必须正确识别为数据库名并忽略。

---

### D3：带数据库名 + 数值阈值（复杂查询）

**问题**：帮我查一下 mysql 数据库里西乡段面积大于 5 的病害有哪些？列出桩号和面积。

**真实答案**：共 48 处。按面积从大到小前 3 处：

| 桩号 | 面积 | 病害类型 |
|---|---:|---|
| k0+511 | 5000.00 ㎡ | 未识别 |
| k0+874 | 5000.00 ㎡ | 未识别 |
| k0+220 | 5000.00 ㎡ | 未识别 |

**难点**：数据库名 + 数值阈值（面积>5）+ 列表查询，三个要素叠加。系统要能正确分离数据库名（忽略）和查询条件（路由到 MySQL 执行）。

### D6：数据库列表（知识问答，非数据查询）

**问题**：系统连接了哪几个数据库？分别有什么用？

**真实答案**：3 个数据源：
1. **MySQL `new_four_road_base_ai`**：主业务库，存储病害、路线、巡查任务、资产等业务数据
2. **PostgreSQL `gpsdb`**：GPS 轨迹库和倾角传感器数据
3. **SeaweedFS**：图片对象存储，存储病害图片和巡检照片

**难点**：这是知识问答（问系统架构），不是数据查询。系统要能区分，不走 NL2SQL 路径，直接回答系统配置信息。

---

### D7：跨数据库复合查询（一个问题两个库）

**问题**：MySQL 里的病害总数和 PostgreSQL 里的 GPS 点数分别是多少？

**真实答案**：MySQL 病害总数 1702 处，PostgreSQL GPS 点数 0 条。

**难点**：复合问题，包含两个独立查询，分别路由到不同数据库。系统要能：
1. 拆分成两个子问题
2. 第一个子问题路由到 MySQL，查 ai_problem 总数
3. 第二个子问题路由到 PostgreSQL，查 gps_points 总数
4. 汇总两个结果回答

这是对问题拆分器和跨库路由的综合测试。

### D8：带数据库名的分组查询——一个答案多个问法

**问法变体**：

3. mysql 数据库里西乡段每种病害分别有多少

**真实答案**：泛油 534 处，未识别类型 377 处。

**难点**：数据库名 + 分组查询（GROUP BY 病害类型），不同问法（简称/全称/口语化）都要能正确识别数据库名并忽略，然后执行分组查询。

## 九、验证要点

| 检查项 | 说明 |
|---|---|
| 路线名准确 | 必须用"宝安大道西乡段"和"宝安中心--恒明珠"，不要用"西乡段"或"恒明珠段"（可能匹配不到） |
| 病害类型关联 | 必须 JOIN ai_problem_base 字典表（DISTINCT 子查询），damage_type 是 code 不是中文名 |
| 置信度提取 | 必须用 JSON_EXTRACT(pic_position, '$.confidence') + CAST，没有独立列 |
| 有图片判断 | problem_url IS NOT NULL AND problem_url != ''，两条路全部病害都有图片 |
| 路线长度 | 不能用 distance 字段（不准/未填），必须用起止桩号相减 |
| 时间范围 | 西乡段病害全部在 2026 年 7 月，6 月无数据 |
| 桩号范围 | 西乡段病害实际只覆盖 K0+000~K0+887，台账写 K0+000~K5+100 |
| 上下行 | 西乡段全部上行（up_or_down=1），下行为 0 |
| 未识别类型 | damage_type=NULL 的病害有 377 处，LEFT JOIN 字典表时 problem_type 为 NULL |
| 数据库名识别 | "MySQL/mysql/new_four_road_base_ai"是数据库名，不能当成路线名，必须忽略并正确路由 |
| PostgreSQL 路由 | "PostgreSQL/postgres/gpsdb"必须路由到 PG 库，不能查 MySQL；PG 两张表均为空表 |
| 跨库复合查询 | 一个问题同时提到 MySQL 和 PG 时，必须拆成两个子问题分别查不同库再汇总 |
| 知识问答区分 | 问"系统连接了哪几个数据库"是知识问答，不走 NL2SQL，直接回答系统配置 |
