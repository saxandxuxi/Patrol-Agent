# 两个bug整改方案

## Bug 1：密度数值前后不一致

### 现象
同一条路，两次回答的密度数值不一样：
- 第一次：西乡段密度 = 178.63 处/公里
- 第二次：西乡段密度 = 162.68 处/公里

### 根因
两次查询走了不同路径，**路长计算口径不统一**：
- 模板快速通道：用起止桩号相减算路长（准）
- Wren/LLM路径：用 `distance` 字段（不准），或者加了别的过滤条件

### 改法
**统一口径：不管走哪条路径，路长都必须用起止桩号相减算，不能用 distance 字段。**

具体：
1. 在所有生成SQL的地方，只要算路线长度，都用这个公式：
   ```sql
   (CAST(SUBSTRING_INDEX(SUBSTRING_INDEX(end_num, '+', 1), 'K', -1) AS UNSIGNED) * 1000 
    + CAST(SUBSTRING_INDEX(end_num, '+', -1) AS UNSIGNED) 
    - CAST(SUBSTRING_INDEX(SUBSTRING_INDEX(start_num, '+', 1), 'K', -1) AS UNSIGNED) * 1000 
    - CAST(SUBSTRING_INDEX(start_num, '+', -1) AS UNSIGNED)) / 1000.0
   ```
2. 在Wren的MDL提示词里，明确写死：**"路线长度必须用起止桩号相减算，不要用 distance 字段"**
3. 加一个校验：如果生成的SQL里用了 `distance` 字段算长度，直接报错重写

### 验收标准
同一个密度问题，不管走模板还是Wren路径，算出来的数值必须一致。

## Bug 2：下钻断链（问"哪个路段"却说没有数据）

### 现象
```
R1：密度最高的是哪条路？
    → 答：西乡段，178.63 处/公里

R2：优先投这条路的哪个路段？
    → 答："数据里没有子路段明细，我无法告诉你具体桩号"
```

### 根因
对话理解器只负责"补全条件"，不负责"判断需不需要重新查"。
它默认"用户在追问，我用刚才的结果接着答就行"。
但是用户问"哪个路段"的时候，上一轮的整体粒度数据根本不够，必须重新查——按桩号分段统计。

### 改法
**对话理解器加一条规则：粒度升级类问题必须重新查，不能用旧结果。**

具体：
1. 识别"粒度升级词"：
   - 哪个路段 / 哪一段 / 最严重的位置 / 集中在哪
   - 拆成多少段 / 按公里分 / 按桩号分
   - 重点养护哪些路段

2. 识别到这些词的时候：
   - 不管上一轮查了什么粒度的结果
   - 都要重新生成一个新的查询：按桩号分段统计当前路线的分布
   - 不能说"刚才的结果里没有分段数据"

3. 在对话理解的提示词里加这条规则：
   > "当用户问'哪个路段/哪一段/最严重的位置'这类问题时，说明用户要的是**比之前更细粒度**的数据。不管上一轮查的是整体还是对比，都必须重新生成一个新查询——按桩号分段（比如每1公里一段）统计当前路线的分布。不能说'数据里没有明细'。"

### 验收标准
```
R1：西乡段病害密度多少？
    → 答：178.63 处/公里

R2：那哪个路段最严重？
    → 答：K1+000-K2+000段最严重，XX 处/公里
         （而不是说"没有子路段明细数据"）
```
