# 时间依赖性与TopN+明细复合问题修复方案

> 背景：用户问"哪个星期西乡段泛油数量是最多的？把相关的数据全部列出来"，系统只返回了一周的数据（2026年第31周，401处），没有列出所有周的数据进行对比，回答里还说"无法与其他周次进行横向对比"。这是一类"时间依赖性 + TopN + 明细"的复合问题，需要系统性修复。
> 核心思路：在语义规划阶段识别复合需求（TopN + 明细），SQL 生成阶段同时生成分组统计和明细，回答生成阶段既说明极值又列出全部分组数据。
> 生成时间：2026-10-12

---

## 一、问题诊断

### 1.1 案例分析

**用户问法：** "哪个星期西乡段泛油数量是最多的？把相关的数据全部列出来"

**系统返回：**
- 只返回了一周的数据：2026年第31周（202631），401处
- 回答里说："由于本次查询结果中仅包含这一周的数据，无法与其他周次进行横向对比来验证'最多'的相对性"
- 但用户明确要求"把相关的数据全部列出来"

**正确的回答应该是：**
1. 按周分组统计西乡段泛油数量（所有周的数据）
2. 找出数量最多的那一周（第31周，401处）
3. 列出所有周的数据（不只是 Top1）
4. 回答时既说明哪一周最多，又列出全部分组数据

### 1.2 这类问题的共性

**时间依赖性 + TopN + 明细复合问题的特征：**

| 特征 | 说明 | 例子 |
|---|---|---|
| 时间维度分组 | 按天/周/月/季度/年分组 | "哪个星期"、"哪个月"、"哪一天" |
| 极值查询 | 最多/最少/最高/最低/最早/最晚 | "数量是最多的"、"面积最大"、"时间最早" |
| 明细列出 | 把相关的数据全部列出来/列出所有/分别列出 | "把相关的数据全部列出来"、"列出所有"、"分别是多少" |
| 复合需求 | 同时包含 TopN 和明细两个子问题 | "哪个最多？把数据列出来" |

### 1.3 根因分析

#### 根因 1：语义规划（plan）只识别了 TopN，没有识别明细需求

- 用户问法里同时有"哪个星期最多"（TopN）和"把数据全部列出来"（明细）
- 但语义规划可能只识别了 TopN，把 `shape` 设为 `top` 或 `distribution`
- 没有识别出用户还需要明细（`list` 或 `detail`）

#### 根因 2：SQL 生成只生成了 TopN 的 SQL

- 当 `shape=top` 时，模板生成器可能只生成了 Top1 的 SQL
- 例如：`WHERE 周 = (SELECT MAX(数量) FROM ...)` 或者 `ORDER BY 数量 DESC LIMIT 1`
- 没有生成分组统计的 SQL（`GROUP BY 周 ORDER BY 数量 DESC`）
- 导致结果只有一行（Top1），没有所有周的数据

#### 根因 3：复合题拆分有问题

- 这类问题本质上是复合题（TopN + 明细）
- 但复合题拆分器可能没有把它拆成两个子问题
- 或者拆了，但只执行了 TopN 子问题，没有执行明细子问题

#### 根因 4：回答生成时 LLM 看到只有一行数据就说"无法对比"

- SQL 只返回了一行数据（Top1）
- 回答生成的 LLM 看到只有一行，就说"无法与其他周次进行横向对比"
- 但实际上是 SQL 生成有问题，不是数据本身只有一周

## 二、解决方案

### 2.1 核心思路

**在四个阶段同时修复：**

1. **语义规划阶段**：识别复合需求（TopN + 明细），在 plan 里标记 `need_detail=True`
2. **SQL 生成阶段**：当 `need_detail=True` 时，生成分组统计 SQL（不只是 Top1），返回所有分组数据
3. **复合题拆分阶段**：把"哪个最多？把数据列出来"拆成两个子问题，分别执行
4. **回答生成阶段**：当结果是分组数据时，既说明极值，又列出全部分组数据

### 2.2 阶段 1：语义规划识别复合需求

**文件：** `prompts/query_semantic.md`、`backend/app/services/nl2sql.py`

**改动：**

1. **在语义规划提示词中增加复合需求识别**：
   - 当用户问法同时包含"哪个/什么 最/最多/最少"和"列出/全部/分别"时，标记为复合需求
   - 在 plan 里增加 `need_detail=True` 字段
   - 例子：
     - "哪个星期最多？把数据列出来" → `shape=top`, `need_detail=True`
     - "哪个月病害最多？分别是多少" → `shape=top`, `need_detail=True`
     - "哪条路最长？列出所有" → `shape=top`, `need_detail=True`

2. **在 plan 里增加 `detail_scope` 字段**：
   - `all`：列出所有分组数据
   - `top_n`：只列出前 N 名
   - `related`：只列出与极值相关的明细
   - 例子：
     - "把相关的数据全部列出来" → `detail_scope=all`
     - "列出前 5 名" → `detail_scope=top_n`, `top_n=5`

### 2.3 阶段 2：SQL 生成分组统计（不只是 Top1）

**文件：** `backend/app/services/nl2sql.py`、`backend/app/services/templatizer.py`

**改动：**

1. **当 `need_detail=True` 时，生成分组统计 SQL**：
   - 不生成 `WHERE 周 = (SELECT MAX(...))` 或 `LIMIT 1`
   - 而是生成 `GROUP BY 周 ORDER BY 数量 DESC`（返回所有分组数据）
   - 例子：
     ```sql
     -- 改前（只返回 Top1）
     SELECT * FROM (
       SELECT YEARWEEK(collection_time, 1) AS week, COUNT(*) AS cnt
       FROM ai_problem WHERE ... GROUP BY week ORDER BY cnt DESC LIMIT 1
     ) t
     
     -- 改后（返回所有分组，按数量排序）
     SELECT YEARWEEK(collection_time, 1) AS week, COUNT(*) AS cnt
     FROM ai_problem WHERE ... GROUP BY week ORDER BY cnt DESC
     ```

2. **在模板匹配时，`need_detail=True` 的问题不匹配 Top1 模板**：
   - Top1 模板（`LIMIT 1`）只能返回一行，不满足明细需求
   - 应该匹配分组统计模板（`GROUP BY ... ORDER BY ... DESC`，无 LIMIT）
   - 或者匹配 `top_n` 模板（`LIMIT N`，N > 1）

3. **在 `_build_generic_metric_template` 中支持 `need_detail`**：
   - 当 `need_detail=True` 时，生成的 SQL 不加 `LIMIT 1`
   - 返回所有分组数据，按指标排序

### 2.4 阶段 3：复合题拆分

**文件：** `backend/app/services/agent.py`、复合题拆分器

**改动：**

1. **把"哪个最多？把数据列出来"拆成两个子问题**：
   - 子问题 1："哪个星期西乡段泛油数量是最多的？" → TopN 查询
   - 子问题 2："西乡段泛油数量按周分组的全部数据" → 分组明细查询
   - 两个子问题分别执行，结果合并回答

2. **或者，执行一个分组统计查询，同时满足两个子问题**：
   - 执行 `GROUP BY 周 ORDER BY 数量 DESC`（返回所有分组）
   - 第一行就是 Top1（最多的那一周）
   - 所有行就是明细（全部数据）
   - 这样一次查询就能同时回答两个子问题

3. **推荐方案：执行一个分组统计查询**（更高效，不需要两次查询）
   - 当 `need_detail=True` 时，执行分组统计查询（无 LIMIT）
   - 结果第一行是 Top1，所有行是明细
   - 回答时既说明 Top1，又列出所有分组

### 2.5 阶段 4：回答生成

**文件：** `backend/app/services/agent.py`、回答生成提示词

**改动：**

1. **当结果是分组数据时，回答模板标准化**：
   - 第一句：说明极值（哪一周最多，数量是多少）
   - 第二句：列出全部分组数据（按排序）
   - 例子：
     ```
     2026年第31周泛油数量最多，共401处。
     
     按周分组的全部数据如下：
     - 第31周：401处
     - 第30周：356处
     - 第29周：289处
     - ...（共 N 周）
     ```

2. **在回答生成提示词中增加分组数据的回答规范**：
   - 当结果是分组数据（多行）时，必须既说明极值，又列出所有分组
   - 不允许说"无法对比"（因为数据就在结果里）
   - 如果分组太多（超过 10 个），可以列出前 10 个，然后说"还有 N 个分组，请在结果工作台查看完整表格"

3. **增加结果工作台的引导**：
   - 当分组数据超过 10 个时，回答里提示"完整数据请在结果工作台查看表格与图表"
   - 结果工作台会展示完整的表格和图表（柱状图/折线图）

## 三、实施步骤

### 阶段 1：语义规划识别（P0）

1. 修改 `query_semantic.md`，增加复合需求识别（TopN + 明细）
2. 修改 `nl2sql.py`，在 plan 里增加 `need_detail` 和 `detail_scope` 字段
3. 增加单元测试：验证"哪个最多？把数据列出来"能识别为 `need_detail=True`

### 阶段 2：SQL 生成分组统计（P0）

1. 修改 `nl2sql.py` 的 `_build_generic_metric_template`，支持 `need_detail`
2. 修改 `templatizer.py`，`need_detail=True` 的问题不匹配 Top1 模板
3. 增加单元测试：验证 `need_detail=True` 时生成的 SQL 没有 `LIMIT 1`

### 阶段 3：回答生成标准化（P0）

1. 修改回答生成提示词，增加分组数据的回答规范
2. 修改 `agent.py`，当结果是分组数据时，回答模板标准化
3. 增加单元测试：验证分组数据的回答既说明极值又列出所有分组

### 阶段 4：复合题拆分（P1，可选）

1. 如果阶段 1-3 不能完全解决问题，再考虑复合题拆分
2. 把"哪个最多？把数据列出来"拆成两个子问题
3. 但推荐用"一次分组统计查询同时满足两个子问题"的方案（更高效）

## 四、验收标准

### 语义规划

1. ✅ "哪个星期西乡段泛油数量是最多的？把相关的数据全部列出来" → plan 里 `need_detail=True`, `detail_scope=all`
2. ✅ "哪个月病害最多？分别是多少" → plan 里 `need_detail=True`
3. ✅ "西乡段泛油有多少处"（单纯统计，没有明细需求）→ plan 里 `need_detail=False`

### SQL 生成

1. ✅ `need_detail=True` 时，生成的 SQL 没有 `LIMIT 1`，是 `GROUP BY ... ORDER BY ... DESC`
2. ✅ `need_detail=True` 时，不匹配 Top1 模板（`LIMIT 1`）
3. ✅ `need_detail=False` 时，正常生成 Top1 SQL

### 回答生成

1. ✅ "哪个星期西乡段泛油数量是最多的？把相关的数据全部列出来" → 回答既说明哪一周最多，又列出所有周的数据
2. ✅ 回答里不说"无法对比"（因为数据就在结果里）
3. ✅ 分组超过 10 个时，列出前 10 个，提示"完整数据请在结果工作台查看"

### 端到端测试

1. ✅ "哪个星期西乡段泛油数量是最多的？把相关的数据全部列出来" → 返回所有周的数据，第一周是最多的
2. ✅ "哪个月西乡段病害最多？分别是多少" → 返回所有月的数据
3. ✅ "哪条路泛油最多？列出所有路的数据" → 返回所有路的数据

## 五、扩展：其他时间依赖性问题

这类修复不仅适用于"哪个星期最多"，还适用于所有时间依赖性 + TopN + 明细的复合问题：

| 问题类型 | 例子 | 修复方式 |
|---|---|---|
| 按天 + TopN + 明细 | "哪天泛油最多？把每天的数据列出来" | 同上 |
| 按月 + TopN + 明细 | "哪个月病害最多？分别是多少" | 同上 |
| 按季度 + TopN + 明细 | "哪个季度巡检次数最多？列出所有季度" | 同上 |
| 按年 + TopN + 明细 | "哪一年病害最多？每年分别是多少" | 同上 |
| 按时段 + TopN + 明细 | "哪个时段病害最多？各时段分别是多少" | 同上 |
| 按星期几 + TopN + 明细 | "星期几病害最多？每天分别是多少" | 同上 |

**核心原则：只要用户同时问了"哪个最/最多"和"列出/全部/分别"，就应该返回全部分组数据，而不只是 Top1。**

## 六、风险与应对

| 风险 | 应对 |
|---|---|
| 语义规划识别不准，把单纯 TopN 问题误判为 `need_detail=True` | 收集 bad case，持续优化提示词；可以先用关键词规则兜底（"列出/全部/分别"等词） |
| 返回全部分组数据太多，回答太长 | 回答里只列前 10 个，其余提示"在结果工作台查看"；结果工作台展示完整表格和图表 |
| 某些 Top1 模板确实只需要一行（如"最大面积是多少"） | 这类问题没有"列出/全部/分别"等词，`need_detail=False`，正常走 Top1 |
| 复合题拆分增加复杂度 | 推荐用"一次分组统计查询同时满足两个子问题"的方案，不需要拆分 |
