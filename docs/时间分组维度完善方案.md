# 时间分组维度完善方案（纯语义理解）

## 一、现状分析

### 1.1 代码现状

通过阅读代码，发现时间分组维度的实现分散在4个地方：

| 位置 | 文件 | 现状 |
|---|---|---|
| **语义层合法值集合** | `nl2sql.py:304 _SEMANTIC_GROUP_BY` | 只有 `month`、`day`、`week`、`hour` 4个时间维度 |
| **中文标签** | `nl2sql.py:7603 _SEMANTIC_LABELS` | 只有 月份/日期/周次/时段 |
| **SQL表达式** | `nl2sql.py:7745 _TIME_BUCKET_EXPRS` | 只有 day/week/month/hour 4个 |
| **外置YAML配置** | `resources/lexicon/metrics.yaml` | dimensions 和 time_buckets 里**已经有 half_month**，但代码集合里没有，所以被过滤掉了 |

### 1.2 核心问题

#### 问题1：half_month 配置了但不生效

YAML 里已经写了 half_month 的关键词和SQL表达式：
```yaml
- key: half_month
  words: [半个月, 上半月, 下半月, 每半个月]
  expr: CONCAT(...IF(DAY(...) <= 15, '上半月', '下半月'))
```

但是 `_SEMANTIC_GROUP_BY` 集合里没有 `half_month`，语义层输出后会被 `_pick()` 函数过滤成 null。

#### 问题2：缺少大量时间分组维度

现有只有 day/week/month/hour，缺少：
- year（年）、half_year（半年）、quarter（季度）、season（季节）
- half_month（半月）、ten_day（旬）
- workday（工作日/周末）、time_of_day（凌晨/上午/下午/晚上）
- minute（分钟）、second（秒）
- 自定义粒度（每N天/每N小时/每N分钟）

#### 问题3：靠关键词匹配，换个问法就不行

YAML 里的 dimensions 用 `words` 列表做关键词匹配：
```yaml
- key: half_month
  words: [半个月, 上半月, 下半月, 每半个月]
```

用户说"按半月切分"、"半月维度看"、"哪段半个月最多"就匹配不到。

#### 问题4：TopN聚合查询被当成明细查询

"哪半个月的病害数量最多？"应该是：
1. 按半月分组，COUNT(*)
2. ORDER BY count DESC LIMIT 1

实际生成的是500条明细，然后结果总结LLM基于明细前几行瞎分析"数据样本不全"。

## 二、完整的时间分组维度体系

### 2.1 固定时间单位（14个，从粗到细）

| 标识 | 中文名 | 定义 | MySQL SQL表达式 |
|---|---|---|---|
| `year` | 年份 | 按自然年 | `YEAR(p.collection_time)` |
| `half_year` | 半年 | 上半年（1-6月）/下半年（7-12月） | `CONCAT(YEAR(p.collection_time), IF(MONTH(p.collection_time)<=6,'上半年','下半年'))` |
| `quarter` | 季度 | Q1=1-3月，Q2=4-6月，Q3=7-9月，Q4=10-12月 | `CONCAT(YEAR(p.collection_time),'Q',QUARTER(p.collection_time))` |
| `season` | 季节 | 春3-5/夏6-8/秋9-11/冬12-2 | `CASE WHEN MONTH(...) IN (3,4,5) THEN '春' WHEN MONTH(...) IN (6,7,8) THEN '夏' WHEN MONTH(...) IN (9,10,11) THEN '秋' ELSE '冬' END` |
| `month` | 月份 | 按自然月 | `DATE_FORMAT(p.collection_time, '%Y-%m')` |
| `half_month` | 半月 | 上半月1-15日/下半月16日-月底 | `CONCAT(DATE_FORMAT(p.collection_time,'%Y年%m月'), IF(DAY(...)<=15,'上半月','下半月'))` |
| `ten_day` | 旬 | 上旬1-10/中旬11-20/下旬21-月底 | `CONCAT(DATE_FORMAT(...,'%Y年%m月'), CASE WHEN DAY(...)<=10 THEN '上旬' WHEN DAY(...)<=20 THEN '中旬' ELSE '下旬' END)` |
| `week` | 周次 | ISO 8601，周一到周日 | `CONCAT(DATE_FORMAT(...,'%x'),'年第',DATE_FORMAT(...,'%v'),'周')` |
| `day` | 日期 | 按自然日 | `DATE(p.collection_time)` |
| `dow` | 星期几 | 周一/周二/.../周日 | `CASE DAYOFWEEK(...) WHEN 1 THEN '周日' ... END`（YAML已有） |
| `workday` | 工作日/周末 | 工作日周一到周五/周末周六周日 | `CASE WHEN WEEKDAY(...)<=4 THEN '工作日' ELSE '周末' END` |
| `hour` | 小时 | 0-23点 | `HOUR(p.collection_time)` |
| `time_of_day` | 时段 | 凌晨0-6/上午6-12/下午12-18/晚上18-24 | `CASE WHEN HOUR(...)<6 THEN '凌晨' WHEN HOUR(...)<12 THEN '上午' WHEN HOUR(...)<18 THEN '下午' ELSE '晚上' END` |
| `minute` | 分钟 | 按分钟 | `DATE_FORMAT(p.collection_time, '%Y-%m-%d %H:%i')` |

### 2.2 自定义时间粒度（3个）

| 标识 | 参数 | 定义 | MySQL SQL表达式 |
|---|---|---|---|
| `every_n_days` | `n`（天数） | 每N天一个桶 | `CONCAT(FLOOR(DATEDIFF(p.collection_time,'2000-01-01')/{n}),'桶')` 或直接用 FLOOR 表达式 |
| `every_n_hours` | `n`（小时数） | 每N小时一个桶 | `CONCAT(DATE(p.collection_time),' ',FLOOR(HOUR(p.collection_time)/{n})*{n},'时')` |
| `every_n_minutes` | `n`（分钟数） | 每N分钟一个桶 | `DATE_FORMAT(p.collection_time, '%Y-%m-%d %H:00')` + FLOOR(MINUTE/n) |

### 2.3 不支持的维度

- `second`（秒）：巡检业务用不到，不加入；如果LLM输出了，兜底按 `minute`
- 其他非时间分组（病害类型/路线/上下行等）：已有，不在本方案范围

## 三、纯语义理解改造（不靠关键词映射）

### 3.1 核心原则

**删除"靠 words 关键词列表匹配时间维度"的路径，时间维度完全由语义层 LLM 判断。**

- YAML 里 dimensions 的 `words` 保留用于**非时间维度**（病害类型/路线等）的规则兜底
- 时间维度（year/half_year/quarter/season/month/half_month/ten_day/week/day/dow/workday/hour/time_of_day/minute/every_n_*）不走关键词，由语义层根据问题语义输出
- 提示词里给出所有时间维度的**定义 + 判断标准 + 少量例子**（例子是示范判断逻辑，不是穷举关键词）

### 3.2 修改 `prompts/query_semantic.md`

在 group_by 部分增加（替换现有时间维度说明）：

```markdown
### group_by：时间分组维度（纯语义判断，不要靠关键词）

当用户问"哪个X最多/最少"、"按X分布"、"X维度的趋势"、"什么时候"时，
需要选择一个时间分组维度。根据问题的**语义**判断用户想看的时间粒度，
不要因为用户没说某个词就不分组。

#### 可选的时间分组维度（按粒度从粗到细）

- `year` 年份：按自然年（"哪一年"、"年度趋势"）
- `half_year` 半年：上半年1-6月/下半年7-12月（"上半年下半年对比"、"半年维度"）
- `quarter` 季度：自然季度Q1-Q4（"哪个季度"、"季度分布"）
- `season` 季节：春3-5/夏6-8/秋9-11/冬12-2（"哪个季节"、"季节性规律"）
- `month` 月份：按自然月（"哪个月"、"月度趋势"）
- `half_month` 半月：上半月1-15日/下半月16日到月底（"哪半个月"、"按半月切分"、"半月维度"）
- `ten_day` 旬：上旬1-10/中旬11-20/下旬21-月底（"哪一旬"、"上中下旬"）
- `week` 周次：ISO 8601周一到周日（"哪个星期/周"、"周度趋势"）
- `day` 日期：按自然日（"哪一天"、"日度趋势"、"几号"）
- `dow` 星期几：周一到周日（"星期几最多"、"周几分布"）
- `workday` 工作日/周末：工作日周一到周五/周末周六周日（"工作日和周末对比"）
- `hour` 小时：0-23点（"哪个小时/几点钟最多"、"小时级分布"）
- `time_of_day` 时段：凌晨0-6/上午6-12/下午12-18/晚上18-24（"一天中哪个时段"、"上午下午对比"、"高峰期"）
- `minute` 分钟：按分钟（"每分钟趋势"）
- `every_n_days` 每N天：自定义天数粒度，需带 group_by_params={"n": 数字}（"每7天"、"每隔10天"）
- `every_n_hours` 每N小时：需带 group_by_params={"n": 数字}（"每4小时"、"每8小时一班"）
- `every_n_minutes` 每N分钟：需带 group_by_params={"n": 数字}（"每30分钟"）

#### 判断标准

1. 看用户问的时间粒度：说"半月/半个月"就是 half_month，说"季度"就是 quarter，
   说"一天中什么时候/几点"就是 hour 或 time_of_day。
2. "分布/趋势"类问题如果没明说粒度：数据通常只覆盖几天到几周，默认用 `day`；
   跨月/跨年才用 month/quarter/year。
3. "工作日/周末""上午/下午/晚上"这种二分类/四分类，分别用 workday / time_of_day。
4. "每隔N天/小时/分钟"用 every_n_*，n 必须是数字。
5. 拿不准粒度时选较细的（day 而不是 month），但**绝对不能不分组**，
   也不能把"哪半个月最多"降级成拉明细。

#### 输出格式

时间分组时输出：
"group_by": "half_month"
自定义粒度时额外输出：
"group_by_params": {"n": 10}

#### 例子（示范判断逻辑，不是关键词表）

- "西乡段哪半个月的病害数量最多？" → group_by=half_month
- "按半月切分，哪段病害数量最高？" → group_by=half_month（换说法也要认）
- "一天中什么时候采集的病害最多？" → group_by=hour
- "上午和下午哪个多？" → group_by=time_of_day
- "工作日是不是比周末多？" → group_by=workday
- "每10天一个周期，数量怎么变？" → group_by=every_n_days, group_by_params={"n":10}
- "哪个季度的病害最多？" → group_by=quarter
```

### 3.3 明确 TopN 聚合查询

在 `query_semantic.md` 增加：

```markdown
### "哪X最多/最少"必须是聚合查询，不是明细查询

"哪半个月最多"、"哪种类型最多"、"哪条路最多"这类问题：
1. shape=top（或 distribution + order）
2. 必须 GROUP BY 那个维度 + COUNT/SUM/AVG
3. ORDER BY 指标 DESC LIMIT 1（或用户要的N）
4. **绝对不能 SELECT * 拉 500 条明细**——拉明细无法回答"哪个最多"

只有用户明确说"列出明细/全部数据/每一条"时才查明细。
```

### 4.4 自定义粒度处理

`every_n_days/hours/minutes` 的 n 是动态参数，不能写死在字典里，需要在调用 `_time_bucket_hint()` 时特殊处理：

```python
def _time_bucket_hint(group_by: str, dialect: str, params: dict | None = None) -> str:
    alias = "disease" if dialect == "mdl" else "p"

    # 自定义粒度：n 来自语义层的 group_by_params
    if group_by == "every_n_days":
        n = int((params or {}).get("n") or 7)
        expr = f"FLOOR(DATEDIFF({alias}.collection_time, '2000-01-01') / {n})"
        return f"按「每{n}天」分组：GROUP BY {expr}，SELECT 里也写 {expr} AS 分组"
    if group_by == "every_n_hours":
        n = int((params or {}).get("n") or 1)
        expr = f"CONCAT(DATE({alias}.collection_time),' ',FLOOR(HOUR({alias}.collection_time)/{n})*{n},'时')"
        return f"按「每{n}小时」分组：GROUP BY {expr}，SELECT 里也写 {expr} AS 分组"
    if group_by == "every_n_minutes":
        n = int((params or {}).get("n") or 1)
        expr = (f"CONCAT(DATE_FORMAT({alias}.collection_time,'%Y-%m-%d %H:'),"
                f"LPAD(FLOOR(MINUTE({alias}.collection_time)/{n})*{n},2,'0'))")
        return f"按「每{n}分钟」分组：GROUP BY {expr}，SELECT 里也写 {expr} AS 分组"

    spec = _TIME_BUCKET_EXPRS.get(str(group_by))
    if not spec:
        return ""
    expr = spec[0].format(alias=alias) if dialect == "mdl" else spec[1].format(alias=alias)
    return (
        f"按「{_SEMANTIC_LABELS.get(group_by, group_by)}」分组的写法：GROUP BY {expr}，"
        f"SELECT 里也写 {expr} AS 分组；"
        f"**不要写 {alias}.{group_by}**（表里没有这个字段）"
    )
```

### 4.6 TopN 聚合不加 LIMIT 500

检查 TopN/distribution 模板生成路径：
- 聚合查询（有 GROUP BY + COUNT/SUM/AVG）的 LIMIT 应该是 TopN 的 N（默认1或用户指定），**不是 500**
- 500 只用于明细查询（shape=detail/list）
- 在生成SQL的统一出口加判断：如果SQL含 GROUP BY 且是 top/distribution 形态，LIMIT 用 top_n 的值，不允许 500

## 九、核心原则

1. **时间维度纯语义理解**：不靠关键词穷举，LLM根据问题语义判断粒度，换说法也要认
2. **完整粒度覆盖**：从年到分钟14个固定维度 + 3个自定义粒度，秒级兜底成分钟
3. **配置与代码一致**：YAML 和 `_TIME_BUCKET_EXPRS` 表达式保持一致
4. **TopN必须聚合**：GROUP BY + 聚合 + LIMIT N，绝不拉500条明细代替统计
5. **结果基于数据**：总结LLM基于聚合结果回答，不基于明细前几行瞎分析
6. **不新增连库**：全部是SQL函数表达式，复用现有数据流
