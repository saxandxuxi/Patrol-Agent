# 通用算子多列重复、桩号被挤掉（给 codex）

## 一、现象
问"分别列出路段桩号和相关的修改人"，通用算子拼出：
```sql
SELECT m.update_by AS '修改人', m.update_by AS '修改人', ... (重复 6 次)
FROM basic_facilities_sections_pile_detail m WHERE m.del_flag=0 LIMIT 500
```
桩号没查出来，全是 update_by 重复。

## 二、复现（已跑）
- named_columns("修改人") 返回 6 条，全是 update_by：ai_asset_base / ai_asset_main / ai_distance_capture / ai_work_order / bridges / slope 各一条。
- usable 过滤（capabilities.py:872-876）只按 resolve_column(table, "update_by") 校验——pile_detail 表也有 update_by，6 条全过、没按列名去重。
- usable[:6] 被 6 个 update_by 占满；columns_of 已命中的桩号列（pile_map_position / pile_map_position_name）追加不进去，被挤掉。

## 三、根因
1. named_columns 跨表返回同名列不去重：同一个词"修改人"在 6 张表都有 update_by，返回 6 条。
2. usable 过滤只认列名、不认 named_columns 自带的 model（哪张表），别的表的 update_by 也被当成本表列收下。
3. usable[:6] 名额被重复列占满，真正的桩号列被挤掉。

## 四、修复
1. named_columns 结果按**列名去重**：同一列名只留一条（model 信息保留用于下一步校验）。
2. usable 过滤时，named_columns 的 model 要和落点表 table 对得上；对不上的不收（或至少按列名去重后再收）。
3. columns_of 命中的列（桩号等）优先级高于 named_columns 的重复列，先放进去再 [:6]；或去重后再截断。

## 五、验收
1. "分别列出路段桩号和相关的修改人" → SELECT 里应同时有 桩号列（pile_map_position_name）和 update_by，不重复；
2. "X 和 Y 分别列出"这类多列问题，每列只出现一次；
3. 单列表（"修改人"）仍正常返回 update_by。

---

## 六、实施记录（2026-09-23，已改完）

三处都改了，另外顺手补了两条会让这个 bug 反复出现的坑：

1. **`named_columns` 按列名去重**（`nl2sql.named_columns`）：同一列名只留一条，`model` 字段保留
   给调用方核表。改前"修改人"返回 6 条 update_by，改后 1 条。
2. **`usable` 用 model 定次序**（`capabilities._generic_candidates`）：命中就是本表的排前面，
   "只是别的表也有同名列"的排后面——**但不能丢**（按 §四.2 的另一种读法"对不上的不收"会把
   update_by 整个丢掉，验收 1 反而过不了；实测过）。
3. **点名列先并进集合再截断**：字段触达挑出的桩号列不会再被点名列占满名额挤掉。
4. 顺带（同一个坑的另一面）：`_FIELD_FAMILIES["pile_number"]` 补上桩号列族
   （`pile_map_position(_name)` / `stake_*_num` / `start_num` / `end_num`）——桩点表的通用明细
   SELECT 的是 `pile_map_position*`，而归一化结果闸认的是"桩号列族"，不补就会被误判成"没带桩号列"。
5. 顺带：`shape=distribution` 但没有分组维度时，如果用户点名的列**在落点表上**，
   给一条"这一列有哪些取值"的候选——"修改人"两个字单独问也能出卡（以前 0 候选）。

实测（每问都是新进程）：

```
分别列出路段桩号和相关的修改人
  → SELECT m.update_by AS '修改人', m.pile_map_position AS '桩号坐标点', m.pile_map_position_name AS '桩号名称', …
     落点 basic_facilities_sections_pile_detail，update_by 只出现一次 ✓（验收 1、2）
列出修改人 / 修改人
  → 分别给 generic_detail:ai_problem（SELECT update_by）与 generic_distinct:ai_asset_main ✓（验收 3）
```
